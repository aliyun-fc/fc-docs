# E2B Compatibility and Migration

## How can an existing E2B application connect to FC Agent Sandbox?

Keep the E2B SDK invocation pattern unchanged first, and replace only the API key, API URL, and domain.

```bash
export E2B_API_KEY="<your-api-key>"
export E2B_API_URL="https://api.<region>.e2b.fc.aliyuncs.com"
export E2B_DOMAIN="<region>.e2b.fc.aliyuncs.com"
```

After the change, verify four things first: sandbox creation, command execution, file reads and writes, and resource release. Do not start by migrating complex templates, network logic, or storage logic.

## Why do official E2B examples not configure an endpoint?

Official E2B examples target E2B services by default. FC Agent Sandbox provides an E2B-compatible endpoint on the Function Compute side, so `E2B_API_URL` and `E2B_DOMAIN` must be configured explicitly.

`E2B_API_URL`, `E2B_DOMAIN`, the template, and the sandbox must all belong to the same region. If the regions do not match, common results include creation failures, connection failures, or templates not being found.

## Does the E2B CLI still need `E2B_ACCESS_TOKEN`?

Do not keep using `E2B_ACCESS_TOKEN` in new integration flows. It is a deprecated legacy E2B authentication variable. New E2B CLI versions should use `E2B_API_KEY`.

```bash
export E2B_API_KEY="<your-api-key>"
```

If the SDK works but the CLI does not, check the CLI version first, and then verify `E2B_API_KEY`, `E2B_API_URL`, and `E2B_DOMAIN`.

## Is FC Agent Sandbox exactly the same as E2B?

No. FC Agent Sandbox provides an E2B SDK-friendly developer experience so existing E2B applications can connect with relatively little refactoring.

In addition to E2B-compatible APIs, FC Agent Sandbox provides Function Compute extensions for VPC configuration, dynamic OSS mounts, monitoring and logging, and team quotas. These capabilities are not native E2B SDK interfaces. Before using them, confirm the currently available configuration entry points and applicable scope.

Migration still needs to be evaluated against currently available capabilities. For Volume, access token management, logs, Network Config Update, high-frequency metrics, or cloud-enhanced capabilities, first check [Getting Started / E2B Compatibility](../01.Getting%20Started/07.E2B%20Compatibility.md), or contact the product or sales team to confirm the current supported scope, enablement method, and usage boundaries. For Snapshots, see [Snapshots](../04.Features/01.Sandbox/12.Snapshots.md).

## Can API keys be managed through the E2B SDK?

No. FC Agent Sandbox API keys are created and managed in the Function Compute console, not through the E2B SDK. For instructions, see [Create an API Key](../01.Getting%20Started/03.Create%20an%20API%20Key.md).

In production, isolate API keys by application, environment, or workspace. Do not write full API keys into code, templates, logs, command output, downloaded files, or frontend pages.

## Why do Python and TypeScript examples use different parameter names?

This is a language-style difference across SDKs. Common Python parameters include `api_key` and `api_url`, while common TypeScript parameters include `apiKey` and `apiUrl`.

When troubleshooting, follow the type definitions and examples for the current language SDK. Do not copy field names directly from another language.

## What if sandbox creation succeeds after migration, but `run_code` or port access fails?

First confirm that you are using the `e2b-code-interpreter` or `@e2b/code-interpreter` SDK. The generic `e2b` SDK provides basic file, command, and process capabilities, but it cannot call `run_code` or `runCode`, even with the `code-interpreter-v1` template.

After confirming the SDK, validate code execution, command execution, and file reads and writes with the built-in `code-interpreter-v1` template. If the built-in template works, focus the custom template check on Code Interpreter dependencies, startup commands, listening ports, and readiness conditions.

## Can E2B Volume, Storage, and Snapshot be migrated directly?

Do not assume so by default. Volume is not currently part of the E2B compatibility path for FC Agent Sandbox.

Snapshots support create, list, delete, and restore, but naming, delete paths, and restore constraints are not identical to official E2B. Read [Snapshots](../04.Features/01.Sandbox/12.Snapshots.md) before migrating.

For persistent or shared files, use external storage such as NAS or OSS. FC Agent Sandbox provides a Function Compute extension for dynamic OSS mounts. Before adjusting a migration design for other storage mounts or FUSE solutions, confirm that the required capability is formally available.
