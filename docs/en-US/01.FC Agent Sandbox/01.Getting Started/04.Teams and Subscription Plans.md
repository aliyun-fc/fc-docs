# Teams and Subscription Plans

A subscription plan (Plan) belongs to a Team and determines the capabilities available to sandboxes under that Team. This topic describes subscription plans and Team management operations. For Team creation, resource group configuration, and how to get the Team ID, see [Create a Team](02.Create%20a%20Team.md).

## Subscription plans

The subscription plan determines the runtime capabilities available to sandboxes under a Team. When you create a Team in the console, Pro is selected by default. After creation, you can only upgrade to a higher tier. Downgrade is not supported in the console. If you need a lower tier, create a new Team or contact product support.

For capability differences, typical scenarios, and billing details of each subscription plan, see [Feature differences in the multi-version subscription plan for cloud sandboxes](https://www.alibabacloud.com/help/en/functioncompute/feature-differences-in-the-multi-version-subscription-plan-for-cloud-sandboxes). For billing rules, see [Pay-as-you-go](../03.Pricing/02.Pay-as-you-go.md).

If a request exceeds the capabilities allowed by the current subscription plan, such as an unsupported timeout or hibernation operation, the request fails. Adjust the request parameters, or upgrade the Team's subscription plan.

## Manage Teams

1. Open any FC Agent Sandbox page.
2. In the Team selector, click **Manage Team**.
3. In the management drawer, view the Team ID, name, version (subscription plan), description, resource group, owner, and creation time. You can also search by Team name or owner UID.

Supported operations:

| Operation | Description |
|-----------|-------------|
| Upgrade | Upgrade the subscription plan to a higher tier. The upgrade path is Eco → Std → Pro. Downgrade is not supported. |
| Delete | Before deletion, the console shows the number of related API keys, sandboxes, and templates. You cannot delete a Team that still has API keys. Clean up the keys on the API Keys page first. |

The console does not currently support editing the Team name or description, or changing the Team's resource group. Confirm the name and resource group when you create the Team.

## Recommendations

- Before upgrading a subscription plan, confirm the capabilities and billing rules of the target plan.
- To change a Team name or resource group, create a new Team and migrate your business resources.
- Before deleting a Team, confirm that the Team no longer has API keys, templates, sandboxes, or volumes that you need to keep.
- If you need to limit the total CPU or memory available to a Team, record the Team ID and configure quotas as described in [Team Quota Management](../04.Features/07.FC%20Extensions/06.Quota%20Management.md).

## FAQ

### Why is the subscription plan not shown when I create a Team?

Multi-version subscription plans are enabled by region. In regions where the feature is not available, the plan selector is hidden and the system creates the Team with Pro.

### Can I move an existing Team to another resource group?

The console does not currently support changing a Team's resource group. Select the correct resource group when you create the Team. To change ownership, create a new Team under the target resource group and switch the corresponding API keys and traffic.

### What should I do if deleting a Team fails because API keys still exist?

You cannot delete a Team that still has API keys. Delete the related keys on the API Keys page first, and then delete the Team. Before deletion, confirm that the Team no longer has business resources that you need to keep.

### Are FC Agent Sandbox Teams managed through the E2B SDK?

No. FC Agent Sandbox Teams are created and managed in the Function Compute console. They are not managed through the E2B SDK Team API. Day-to-day access still uses the E2B SDK to create and operate sandboxes. Identity comes from the FC Agent Sandbox API key and the Team bound to that key.
