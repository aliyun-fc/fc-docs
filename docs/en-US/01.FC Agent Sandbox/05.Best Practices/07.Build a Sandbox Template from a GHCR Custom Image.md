# Build a Sandbox Template from a GHCR Custom Image

FC Agent Sandbox can build a Sandbox template directly by pulling an image from a container registry. When your business needs to preinstall a specific language runtime, system dependencies, a private SDK, or a data science toolchain, packaging everything into a container image and building the template from that image is more controllable and reproducible than installing dependencies one by one at runtime.

This document uses a private image on [GitHub Container Registry (GHCR)](https://ghcr.io) as an example, and shows how to call the `CreateTemplate` OpenAPI operation in the China (Hong Kong) region (`cn-hongkong`) to build a second-generation (micro) runtime template from `ghcr.io/<owner>/<image>:<tag>`, create a Sandbox, and verify the run. GHCR is a registry that requires authentication, so you must provide pull credentials when creating the template. GHCR is hosted outside the Chinese mainland, so the build region must be able to access `ghcr.io`; this document uses the China (Hong Kong) region.

## Use cases

- A team packages a unified Python/Node.js runtime and common dependencies into an image, and multiple Agents share the same base template.
- Analysis tasks need heavy dependencies such as `pandas`, `numpy`, and charting libraries preinstalled once at build time instead of at every run.
- A private SDK or internal tool is published only to a private GHCR repository and cannot be pulled publicly.
- You need to align image versions with template versions so builds are traceable and can be rolled back.

## Prerequisites

- FC Agent Sandbox is enabled, a Team has been created, and you have the Team ID. For details, see [Create a Team](../01.Getting%20Started/02.Create%20a%20Team.md).
- The Alibaba Cloud account or RAM user calling the OpenAPI operations has the template API permissions (`fcsandbox:CreateTemplate`, `fcsandbox:GetTemplate`, `fcsandbox:DeleteTemplate`). For details, see the permission configuration in [Build and Manage Templates via OpenAPI](../04.Features/02.Templates/08.Build%20and%20Manage%20Templates%20via%20OpenAPI.md).
- You have the `E2B_API_KEY` for the target region (used to create Sandboxes). For details, see [E2B SDK Connection Parameters](../07.Developer%20Reference/02.E2B%20SDK%20Connection%20Parameters.md).
- The second-generation runtime is currently available only to whitelisted accounts and regions. Without access, the template build fails with `MicroSandbox runtime is not enabled for this account`. To use it, contact technical support to request access.
- An image is ready on GHCR. The second-generation runtime only supports Ubuntu/Debian-based images, and the image must retain system components such as `systemd`, `openssh-server`, `sudo`, `chrony`, `fuse3`, and `iptables`. For the complete requirements, see [Image requirements](../04.Features/02.Templates/08.Build%20and%20Manage%20Templates%20via%20OpenAPI.md#image-requirements). A minimal Dockerfile that meets the requirements:

```dockerfile
FROM debian:12
RUN apt-get update && DEBIAN_FRONTEND=noninteractive apt-get install -y --no-install-recommends \
    systemd systemd-sysv openssh-server sudo chrony fuse3 iptables \
    python3 curl ca-certificates \
    && rm -rf /var/lib/apt/lists/*
CMD ["/sbin/init"]
```

- GitHub credentials for pulling the image have been created (see "Registry credentials" below).
- Install the FC Agent Sandbox OpenAPI SDK and the E2B SDK:

```bash
pip install alibabacloud_fcsandbox20260509 e2b==2.31.0
```

## Registry credentials

Pulling an image from a private GHCR repository requires a username and password. The credential here is a GitHub [Personal Access Token (classic)](https://github.com/settings/tokens), not your account login password:

- **Username**: your GitHub username (the owner that the image belongs to).
- **Password**: the value of the Personal Access Token (classic) you created (in the form `ghp_xxxxxxxx`).

> **Token scope requirements**: The second-generation runtime runs directly from the source image. The build only pulls the image and never pushes back, so the token only needs the **`read:packages`** scope. Missing this scope causes the image pull to fail during the build (auth 401 / 403; see the [GitHub documentation](https://docs.github.com/en/packages/working-with-a-github-packages-registry/working-with-the-container-registry)).

Creation path: GitHub → **Settings** → **Developer settings** → **Personal access tokens** → **Tokens (classic)** → **Generate new token (classic)**, and select `read:packages` under **Select scopes**.

The credentials are passed through `runtime_config.sandbox_config.registry_config.auth_config` in the `CreateTemplate` request body:

| Field | Meaning | Value |
| --- | --- | --- |
| `user_name` | Registry username | GitHub username |
| `password` | Registry password | Personal Access Token (classic) |

> Credentials are sensitive. Inject them via environment variables or a secrets manager. Do not hardcode them in code or commit them to a repository.

## Recommended workflow

Split "custom image → template → Sandbox" into four steps:

1. Call `CreateTemplate` to create the template: set `sandbox_config.image` to the GHCR image address, `generation` to `2` (second-generation micro runtime), and `registry_config.auth_config` to the registry credentials, and obtain the `template_id`.
2. Poll `GetTemplate` until the build reaches a terminal state (`ready` / `error`).
3. Create a Sandbox with the `template_id`, wait for the data plane to be ready, then run a command as a smoke test.
4. Destroy the Sandbox after verification to avoid holding resources. When the template is no longer needed, call `DeleteTemplate` to delete it.

Building the template is a one-time action: the `template_id` built from an image can be reused by many subsequent `Sandbox.create` calls. In production, separate build and run into two stages instead of rebuilding on every run.

## Example code

The following example builds a second-generation runtime template from the private GHCR image `ghcr.io/<owner>/<image>:<tag>`, creates a Sandbox, runs a command to print a verification marker, and finally destroys the Sandbox. The Alibaba Cloud credentials, GitHub credentials, and `E2B_API_KEY` are all read from environment variables.

```python
import os
import time

from alibabacloud_fcsandbox20260509 import models
from alibabacloud_fcsandbox20260509.client import Client as FCSandboxClient
from alibabacloud_tea_openapi import models as open_api_models
from e2b import Sandbox

REGION = "cn-hongkong"
POP_ENDPOINT = f"fcsandbox.{REGION}.aliyuncs.com"
API_URL = f"https://api.{REGION}.e2b.fc.aliyuncs.com"
DOMAIN = f"{REGION}.e2b.fc.aliyuncs.com"
SOURCE_IMAGE = "ghcr.io/<owner>/<image>:<tag>"
SANDBOX_MARKER = "sandbox-ok"
READY_TIMEOUT_SECONDS = 90
READY_INTERVAL_SECONDS = 3


def required_env(name: str) -> str:
    value = os.environ.get(name, "").strip()
    if not value:
        raise RuntimeError(f"missing environment variable: {name}")
    return value


def main() -> int:
    team_id = required_env("FCSANDBOX_TEAM_ID")
    pop_client = FCSandboxClient(
        open_api_models.Config(
            access_key_id=required_env("ALIBABA_CLOUD_ACCESS_KEY_ID"),
            access_key_secret=required_env("ALIBABA_CLOUD_ACCESS_KEY_SECRET"),
            region_id=REGION,
            endpoint=POP_ENDPOINT,
        )
    )

    # 1. Create the template: second-generation micro runtime + private GHCR image + pull credentials.
    #    The first build starts immediately after creation.
    response = pop_client.create_template(
        models.CreateTemplateRequest(
            body=models.CreateTemplateInput(
                name=f"ghcr-demo-{int(time.time())}",
                team_id=team_id,
                runtime_config=models.CreateTemplateRuntimeConfig(
                    cpu=2,
                    memory_size=2048,
                    disk_size=10240,
                    sandbox_config=models.CreateTemplateSandboxConfig(
                        image=SOURCE_IMAGE,
                        generation=2,
                        registry_config=models.CreateTemplateRegistryConfig(
                            auth_config=models.CreateTemplateRegistryAuthConfig(
                                user_name=required_env("GHCR_USERNAME"),
                                password=required_env("GHCR_PASSWORD"),
                            ),
                        ),
                    ),
                ),
            )
        )
    )
    template_id = response.body.template_id
    print(f"template_id={template_id}")

    # 2. Poll GetTemplate until the build reaches a terminal state.
    deadline = time.time() + 900
    while True:
        got = pop_client.get_template(template_id, models.GetTemplateRequest(team_id=team_id))
        state = got.body.status.state
        print(f"state={state}")
        if state == "ready":
            break
        if state == "error":
            reason = got.body.status.reason.message if got.body.status.reason else ""
            raise RuntimeError(f"build failed: {reason}")
        if time.time() > deadline:
            raise RuntimeError("build timed out")
        time.sleep(10)

    # 3. Create a Sandbox with the template_id.
    sandbox = Sandbox.create(
        template=template_id,
        timeout=900,
        api_key=required_env("E2B_API_KEY"),
        api_url=API_URL,
        domain=DOMAIN,
    )
    print(f"sandbox_id={sandbox.sandbox_id}")

    try:
        # Wait for the data plane to be ready, then run the smoke test.
        last_error = None
        result = None
        deadline = time.monotonic() + READY_TIMEOUT_SECONDS
        while time.monotonic() < deadline:
            try:
                result = sandbox.commands.run(f"echo {SANDBOX_MARKER}", timeout=60)
                break
            except Exception as err:
                last_error = err
                time.sleep(READY_INTERVAL_SECONDS)
        if result is None:
            raise RuntimeError(f"timed out waiting for the data plane: {last_error}") from last_error
        if result.exit_code != 0 or SANDBOX_MARKER not in result.stdout:
            raise RuntimeError(f"verification failed: exit={result.exit_code}, stdout={result.stdout}")
        print(f"stdout={result.stdout.strip()}")
    finally:
        # 4. Destroy the Sandbox.
        sandbox.kill()

    # The template can be reused long-term. Delete it when it is no longer needed:
    # pop_client.delete_template(template_id, models.DeleteTemplateRequest(team_id=team_id))
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

Run it with credentials in environment variables:

```bash
export ALIBABA_CLOUD_ACCESS_KEY_ID="<your-access-key-id>"
export ALIBABA_CLOUD_ACCESS_KEY_SECRET="<your-access-key-secret>"
export FCSANDBOX_TEAM_ID="<your-team-id>"
export GHCR_USERNAME="<github-username>"
export GHCR_PASSWORD="ghp_xxxxxxxxxxxxxxxxxxxx"   # Personal Access Token (classic)
export E2B_API_KEY="<your-e2b-api-key>"
python3 build_from_ghcr.py
```

A normal run prints the `template_id`, build states, and `sandbox_id` in sequence, followed by the verification marker `sandbox-ok`, and finally destroys the Sandbox.

## Recommendations for production

- **Credential management**: Inject the GitHub token, Alibaba Cloud credentials, and `E2B_API_KEY` via environment variables or a secrets manager. Do not hardcode them in code or commit them to Git. Follow the principle of least privilege: select only `read:packages` for the token, and rotate it regularly.
- **Separate build from run**: Building a template is a one-time action. Persist and reuse the resulting `template_id`; do not rebuild before every `Sandbox.create`.
- **Image versioning**: Use explicit tags (avoid relying on `latest`) so templates and image versions stay aligned, traceable, and rollback-friendly.
- **Resource sizing**: Evaluate `cpu`, `memory_size`, and `disk_size` against the workload in the image. Note that for the second-generation runtime, the configured disk size includes the image itself; the actual writable space is the disk size minus the image size.
- **Clean up promptly**: Call `sandbox.kill()` when the task ends (in a `finally` block) so Sandboxes are not held on exception paths. When a template is no longer needed, call `DeleteTemplate` to delete it.
