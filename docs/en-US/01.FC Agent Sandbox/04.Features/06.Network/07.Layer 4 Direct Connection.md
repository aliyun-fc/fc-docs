# Layer 4 Direct Connection

Layer 4 direct connection allows clients in a virtual private cloud (VPC) to access TCP services running in a sandbox through a private `IP:Port`. It is suitable for VNC, SSH, databases, caches, and custom binary protocols that require long-lived TCP connections.

To use Layer 4 direct connection, configure an ingress VPC when you create the sandbox, and then allocate an endpoint for a service port in the sandbox. After the endpoint is allocated, the client connects by using the returned `host` and `port`.

For HTTP/HTTPS services, web UIs, and standard APIs, you can continue to use the Layer 7 access URL provided by `sandbox.getHost(port)`. The following table compares the two access methods:

| Access method | Address | Protocol | Use cases |
| --- | --- | --- | --- |
| Layer 4 direct connection | Private `IP:Port` | TCP | VNC, SSH, databases, caches, and custom TCP services |
| Layer 7 access URL | HTTPS domain name | HTTP, HTTPS, WebSocket | Web UIs, service previews, and HTTP APIs |

## Limits

| Limit | Description |
| --- | --- |
| Availability | The feature is currently available by invitation at the account and region level. Submit an Alibaba Cloud support ticket to request access before use. |
| Network scope | The endpoint provides only a private VPC address. The client must be in the ingress VPC or in a network connected to the ingress VPC. |
| Protocol | Only TCP is supported. |
| Sandbox state | You can allocate an endpoint when the sandbox is in the `running` state. |
| Internal port | The valid range is `1` to `65535`. Port `49983` is reserved by the system. |
| External port | The platform allocates the port dynamically. It might differ from the internal port. |
| Layer 4 port mapping rules per sandbox | The default maximum is 4 rules, which refers to the number of mapping rules created by `AllocPortForward`. The actual limit depends on the account configuration. Contact us if you need to adjust the limit. |
| Endpoint lifecycle | The endpoint follows the sandbox lifecycle and is automatically reclaimed when the sandbox is deleted or expires. |
| Port mapping release | You cannot currently delete an individual port mapping. |
| Access authentication | Layer 4 traffic does not pass through Layer 7 access token validation. The service must implement its own authentication and access control. |

## Prerequisites

Complete the following preparations before you use Layer 4 direct connection:

- Layer 4 direct connection is enabled for your account and target region.
- A VPC, vSwitches, and a security group are created in the target region. The resources belong to the same account and region.
- The vSwitches have sufficient available IP addresses. Configure two or more vSwitches when possible to improve availability.
- The client is in the ingress VPC, or is connected to the ingress VPC through Cloud Enterprise Network (CEN), VPN, Express Connect, or another private network connection.
- You have obtained an FC Agent Sandbox API Key and API URL for the target region. For information about obtaining an API Key, see [Create an API Key](../../01.Getting%20Started/03.Create%20an%20API%20Key.md).
- The TCP service in the sandbox listens on `0.0.0.0:<internalPort>`.

## How It Works

Layer 4 direct connection uses the following creation and access flow:

1. When you create a sandbox, specify the ingress VPC, vSwitches, and security group in metadata.
2. After the sandbox enters the `running` state, allocate an endpoint for the internal service port.
3. The platform returns the endpoint `host` and `port`, and forwards TCP traffic received at that address to the sandbox `internalPort`.
4. The client connects to the endpoint from a network that can reach the ingress VPC.

The ingress VPC carries inbound traffic from clients to the sandbox. The egress VPC is used when the sandbox accesses VPC resources. The two configurations are independent:

- Use `fc.sandbox.network.portforwardvpc` for the ingress VPC.
- Use `fc.sandbox.network.vpc` for the egress VPC. For configuration details, see [VPC Network Configuration](../07.FC%20Extensions/02.VPC%20Network%20Configuration.md).

If inbound and outbound traffic use the same VPC, you must still configure both metadata fields.

## Use the HTTP API

Send the following requests to the FC Agent Sandbox API URL for the target region:

```text
https://api.<region>.e2b.fc.aliyuncs.com
```

### 1. Create a Sandbox and Configure the Ingress VPC

Use the following metadata field for the ingress VPC:

```text
fc.sandbox.network.portforwardvpc
```

The field value must be a serialized JSON string. The object in the string has the following structure:

```json
{
  "vpcId": "vpc-xxxxxxxx",
  "vSwitchIds": ["vsw-xxxxxxxx"],
  "securityGroupId": "sg-xxxxxxxx"
}
```

Field reference:

| Field | Required | Description |
| --- | --- | --- |
| `vpcId` | Yes | The ingress VPC in which the Layer 4 endpoint resides. |
| `vSwitchIds` | Yes | The list of vSwitch IDs used by the endpoint. |
| `securityGroupId` | Yes | The security group that controls inbound access to the endpoint. |

Create a sandbox:

```http
POST /sandboxes
X-API-KEY: <your-api-key>
Content-Type: application/json
```

```json
{
  "templateID": "base",
  "timeout": 3600,
  "metadata": {
    "fc.sandbox.network.portforwardvpc": "{\"vpcId\":\"vpc-xxxxxxxx\",\"vSwitchIds\":[\"vsw-xxxxxxxx\"],\"securityGroupId\":\"sg-xxxxxxxx\"}"
  }
}
```

Successful creation indicates that the ingress network configuration has taken effect. You must allocate each service port separately after the sandbox enters the `running` state.

### 2. Start a TCP Service in the Sandbox

The service must listen on all network interfaces and on the internal port that you plan to use. For example, if a VNC service uses port `5900`, it must listen on:

```text
0.0.0.0:5900
```

If the service listens only on `127.0.0.1`, the Layer 4 endpoint cannot access it.

### 3. Allocate an Endpoint

Allocate a Layer 4 endpoint for port `5900` in a running sandbox:

```http
POST /sandboxes/{sandboxID}/fc-l4-ip
X-API-KEY: <your-api-key>
Content-Type: application/json
```

```json
{
  "internalPort": 5900,
  "protocol": "tcp"
}
```

Request parameters:

| Parameter | Required | Description |
| --- | --- | --- |
| `internalPort` | Yes | The port on which the service listens in the sandbox. The valid range is `1` to `65535`, excluding `49983`. |
| `protocol` | No | Only `tcp` is supported. If this parameter is omitted or is an empty string, it defaults to `tcp`. |

Response example:

```json
{
  "host": "172.16.0.10",
  "port": 30000,
  "internalPort": 5900,
  "protocol": "tcp"
}
```

The response contains the following fields:

- `host`: the private IP address in the ingress VPC.
- `port`: the external port allocated by the platform.
- `internalPort`: the service port in the sandbox.
- `protocol`: the transport protocol used by the endpoint.

Each allocation returns the currently valid endpoint. The client must use the `host` and `port` from the response. Do not substitute `internalPort` for the returned `port`.

### 4. Configure the Security Group and Connect to the Service

Add an inbound rule to the ingress security group that allows the client IP address or CIDR block to access the `port` returned in the endpoint response. Allow only the source ranges and ports required by your workload.

The following example tests TCP connectivity to the endpoint:

```bash
nc -vz 172.16.0.10 30000
```

The application client connects by using the same `host` and `port`. For example, after a VNC client connects to `172.16.0.10:30000`, traffic is forwarded to port `5900` in the sandbox.

## Security Recommendations

- Configure application-layer authentication for SSH, VNC, databases, custom management interfaces, and similar services.
- Use security groups to restrict access to trusted client IP addresses or business CIDR blocks.
- Grant database accounts, SSH keys, and application tokens the minimum required permissions and set appropriate expiration times.
- Store credentials in a secure credential management service instead of code, templates, metadata, or logs.
- Use application or audit logs to record connection activity and authentication results.

Layer 4 traffic does not pass through `trafficAccessToken` or `envdAccessToken` validation. The `secure: true` and `network.allowPublicTraffic` settings apply only to their corresponding Layer 7 paths and do not replace authentication implemented by the Layer 4 service.

## Lifecycle

- **Pause**: After the sandbox enters the paused state, new endpoint allocation requests return a state conflict.
- **Resume**: Wait for the sandbox to return to the `running` state, call the endpoint API again to obtain the current address, and re-establish the TCP connection.
- **Kill or expiration**: The endpoint is automatically reclaimed with the sandbox lifecycle.
- **Repeated allocation**: You can allocate the same internal port repeatedly. Treat the latest response as the current endpoint.

## FAQ

| Symptom | Possible cause | Fix |
| --- | --- | --- |
| Sandbox creation returns `invalid port forward vpc config` | The VPC, vSwitch, or security group configuration is incomplete, or the resources do not belong to the same account or region | Check the three resource IDs, region, and account. |
| Endpoint allocation returns `l4 direct is not enabled for this account` | Layer 4 direct connection is not enabled for the current account or region | Submit an Alibaba Cloud support ticket to request access. |
| The API returns `l4 endpoint is not ready` | The ingress VPC is not configured, or the endpoint network resources are still being created | Confirm that the sandbox creation request contains the ingress VPC configuration. If resources are being created, wait and retry a limited number of times. |
| The API returns `port limit exceeded` | The sandbox has reached the maximum number of Layer 4 port mapping rules | Reuse an existing mapping rule. Contact us if you need to adjust the limit. |
| The API returns `internalPort 49983 is reserved for envd` | The request uses a system-reserved port | Configure the service to use another port. |
| The API returns `conflict` | The sandbox is not in the `running` state | Wait for sandbox creation or resume to complete, and then retry. |
| The endpoint is unreachable from the client | The client cannot reach the ingress VPC, the security group does not allow the external port, or the service does not listen on all network interfaces | Check network connectivity, the security group inbound rule, and the service listen address. |
| The endpoint is reachable but authentication fails | The service account, key, or access policy rejects the request | Check the authentication configuration of the service. |
