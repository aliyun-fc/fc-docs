# Migrate from AgentBay to FC Agent Sandbox Desktop
> A guide to migrating from Wuying AgentBay (`linux_latest`) to the FC Agent Sandbox e2b-desktop SDK.

## 1. Capability mapping

> Method names and signatures follow the e2b-desktop SDK release. Some capabilities are covered by shell commands inside the sandbox and are marked as "shell-aligned".

| Wuying AgentBay `session.computer.*` | `e2b-desktop` equivalent | Notes |
|-------------------------------|--------------------|------|
| **Mouse** |  |  |
| `click_mouse(x, y)` | `left_click(x, y)` | Pass coordinates directly; or use `move_mouse` + `left_click()` in two steps |
| `click_mouse(x, y, button="right")` | `right_click(x, y)` | Same as above |
| `move_mouse(x, y)` | `move_mouse(x, y)` | Same name |
| `drag_mouse(x1, y1, x2, y2)` | `drag((x1, y1), (x2, y2))` | Different signature; takes tuples |
| `double_click()` | `double_click()` | Same name |
| `scroll(x, y, direction, amount)` | `move_mouse(x, y)` + `scroll(direction, amount)` | No coordinate parameter; move first, then scroll |
| `get_cursor_position()` | `commands.run("xdotool getmouselocation")` | Shell-aligned |
| **Keyboard** |  |  |
| `input_text(text)` | `write(text)` | Different method name |
| `press_keys(keys)` | `press(key)` / `press(["ctrl", "c"])` | Single key or key combination list |
| `release_keys` | `commands.run("xdotool keyup <key>")` | Shell-aligned |
| **Screenshot** |  |  |
| `screenshot()` | `screenshot()` | Same name; PNG bytes |
| `beta_take_screenshot(format)` | `commands.run("scrot -q 80 /tmp/s.jpg")` + `files.read(path, format="bytes")` | Shell-aligned (scrot supports jpg/png; jpg must be read explicitly as bytes) |
| **Screen info** |  |  |
| `get_screen_size()` | `commands.run("xdpyinfo -display :0 | grep dimensions")` | Shell-aligned |
| `get_current_window_id()` | `get_current_window_id()` | Same name |
| **Window management** |  |  |
| `list_root_windows` | `commands.run('xdotool search --onlyvisible --name ""')` | Shell-aligned |
| `activate_window` | `commands.run("xdotool windowactivate --sync <id>")` | Shell-aligned |
| `maximize_window` | `commands.run("xprop -id <id> -f _NET_WM_STATE 32a -set _NET_WM_STATE _NET_WM_STATE_MAXIMIZED_VERT,_NET_WM_STATE_MAXIMIZED_HORZ")` | Shell-aligned |
| `minimize_window` | `commands.run("xdotool windowminimize <id>")` | Shell-aligned |
| `resize_window` | `commands.run("xdotool windowsize --sync <id> <w> <h>")` | Shell-aligned (terminal apps snap to character cells) |
| `close_window` | `commands.run("xdotool windowclose <id>")` | Shell-aligned |
| `focus_mode` | `commands.run("xfconf-query -c xfwm4 -p /general/click_to_focus -s ...")` | Shell-aligned |
| **App management** |  |  |
| `start_app(app, work_directory)` | `commands.run("cd <workdir> && setsid nohup <app> >/tmp/app.log 2>&1 </dev/null &")` | Shell-aligned; detaches GUI processes from the short-lived command channel |
| `stop_app` | `commands.run("pkill <app>")` | Shell-aligned |
| `get_installed_apps` | `commands.run("ls /usr/share/applications/")` | Shell-aligned |
| `list_visible_apps` | `commands.run('xdotool search --onlyvisible --name ""')` | Shell-aligned |
| **Agent (differences)** |  |  |
| `execute_task` | None | C-1: not supported |
| `get_task_status` | None | C-2: not supported |
| `terminate_task` | None | C-3: not supported |
| **Desktop observation** |  |  |
| `get_link_url` / VNC | `stream.start()` + `get_url()` | Built-in auth; see §5 |

- C-1 to C-3 (natural-language Agent) have no delivery plan and are outside the FC Agent Sandbox product scope. Everything else can be aligned through the SDK or shell commands.
- When Computer Use is not needed: use Browser Use (CDP) for web-only operations, and commands/code for pure batch processing.
- The SDK capability mapping was previously verified 35/35 with `e2b-desktop==2.4.1` and the `desktop:v0.0.44` template; see §4 for the currently recommended image version.
- The template ships with `xdotool` / `scrot` / `xdpyinfo` / `xprop` / `xwininfo` / `xfconf-query` preinstalled, but **not** `wmctrl` (use the equivalent xdotool/xprop commands above for window management; if you need wmctrl semantics, run `apt-get install -y wmctrl`, the sandbox can reach Debian repositories).
- The §6.2 frontend was verified in a real Chrome (RFB connection, screen rendering, and live desktop refresh all passed).

## 2. Scope limits

Linux desktop (Computer Use) migration uses the **e2b-desktop SDK**:
- Mouse / keyboard / screenshot are existing SDK methods (two-step style); the VNC live stream is built in with auth.
- You must use its `Sandbox` subclass to create sandboxes. Sandbox lifecycle semantics are the same as e2b (still used as `create/connect/list/kill`).
- Superset capabilities such as window and app management are outside this SDK; see the capability mapping in §1.

## 3. Built-in template mapping

| AgentBay | FC E2B | Notes |
|--------|------|------|
| `linux_latest` (Computer Use) | Desktop template (image `fc-e2b-registry.cn-beijing.cr.aliyuncs.com/runtime/desktop:v0.0.48`) | `v0.0.48` is the current recommended default version; build it with `Template.build()`, see §4 |

## 4. Prerequisites: Desktop template

The Desktop template is not available out of the box. We recommend creating it directly from the FC-published Desktop image. Build your own image only when you need additional software, a customized desktop environment, or organization-specific configuration.

### 4.1 Recommended: use the FC Desktop `v0.0.48` image

FC Desktop `v0.0.48` includes the desktop environment, Chrome, Xvfb, x11vnc, noVNC/websockify, and compatibility entry points required by `e2b-desktop`.

#### 4.1.1 Set environment variables

```bash
export E2B_API_KEY="your-api-key"
export E2B_API_URL=https://api.cn-beijing.e2b.fc.aliyuncs.com
export E2B_DOMAIN=cn-beijing.e2b.fc.aliyuncs.com
export E2B_DESKTOP_IMAGE=fc-e2b-registry.cn-beijing.cr.aliyuncs.com/runtime/desktop:v0.0.48
export E2B_DESKTOP_TEMPLATE=custom-desktop-v0048-20260901
```

- The image registry, `E2B_API_URL`, `E2B_DOMAIN`, and target resources must be in the same region. For another region, update all region-specific addresses together.
- Include the application, image version, or date in `E2B_DESKTOP_TEMPLATE`. Use a new Template name whenever the image or configuration changes. An existing name may be reused directly and therefore cannot validate the new change.
- Do not use `desktop-v*` as the Template name prefix because it is reserved by the system. For example, use `custom-desktop-v0048-20260901`.
- Inject the API key only through environment variables or a secret manager. Do not put it in scripts, Dockerfiles, image layers, or logs.

#### 4.1.2 Build and verify the Template

```bash
pip install e2b==2.31.0 e2b-desktop==2.4.1 python-dotenv
```

```python
# build.py
import os
from urllib.parse import urlparse

from dotenv import load_dotenv
from e2b import Template, default_build_logger
from e2b_desktop import Sandbox

load_dotenv()

image = os.environ["E2B_DESKTOP_IMAGE"]
template_name = os.environ["E2B_DESKTOP_TEMPLATE"]

build = Template.build(
    Template().from_image(image),
    name=template_name,
    cpu_count=4,
    memory_mb=8192,
    skip_cache=False,
    on_build_logs=default_build_logger(),
)
print(f"template_id: {build.template_id}")

# A successful build is not sufficient; create a Sandbox and verify the desktop stream.
desktop = Sandbox.create(template=build.template_id, timeout=900)
stream_started = False
try:
    desktop.stream.start(require_auth=True)
    stream_started = True
    auth_key = desktop.stream.get_auth_key()
    stream_url = desktop.stream.get_url(auth_key=auth_key)
    parsed_stream_url = urlparse(stream_url)
    if parsed_stream_url.scheme != "https" or parsed_stream_url.path != "/vnc.html":
        raise RuntimeError(f"unexpected desktop stream URL: {stream_url}")

    desktop.move_mouse(1, 1)
    desktop.press("shift")
    image = desktop.screenshot()
    if len(image) < 1024 or not image.startswith(b"\x89PNG\r\n\x1a\n"):
        raise RuntimeError("desktop screenshot is not a valid PNG")

    print(f"sandbox_id: {desktop.sandbox_id}")
    print("desktop SDK smoke test passed; browser RFB verification is still required")
finally:
    if stream_started:
        desktop.stream.stop()
    desktop.kill()
```

```bash
python build.py
```

The recommended size is 4 vCPU and 8192 MB memory. With the FC Desktop image, no startup or readiness command is required; the Desktop SDK starts the desktop environment and live stream automatically.

The script verifies Sandbox creation, the live-stream URL, mouse and keyboard operations, and a PNG screenshot. A URL check does not prove that a browser has established an RFB connection. Before production use, connect to `stream_url` with the §6 noVNC client and verify rendering, live desktop refresh, and browser mouse/keyboard input. A `stream_url` can contain temporary access credentials; pass it only through a controlled backend and do not write it to logs or tickets.

### 4.2 Advanced: build an image from Ubuntu 24.04

If the default image does not meet your software, font, desktop extension, or organization configuration requirements, create a source image from the official Docker Hub Ubuntu 24.04 image. You own the maintenance of this image, including software versions, security patches, image size, and desktop startup stability.

Organize the build context by responsibility:

```text
desktop-image/
├── Dockerfile
├── scripts/
│   └── start-desktop
└── assets/
    ├── applications/
    └── icons/
```

The following Dockerfile is a skeleton that defines the baseline dependencies and compatibility contract. You must also provide `scripts/start-desktop` to start a GNOME session through D-Bus after Xvfb is ready. Do not depend on a complete `systemd`, USB devices, or host desktop capabilities.

```dockerfile
ARG UBUNTU_IMAGE=docker.io/library/ubuntu:24.04
FROM ${UBUNTU_IMAGE}

ARG TARGETARCH
RUN test "${TARGETARCH}" = "amd64"

ENV DEBIAN_FRONTEND=noninteractive \
    DISPLAY=:0 \
    LANG=C.UTF-8 \
    LC_ALL=C.UTF-8

RUN apt-get update && apt-get install -y --no-install-recommends \
      bash ca-certificates curl git python3 sudo dbus-x11 systemd \
      xvfb x11-utils x11-apps xauth x11vnc xdotool scrot \
      gnome-session gnome-shell gnome-terminal nautilus \
      hicolor-icon-theme librsvg2-common gtk-update-icon-cache \
      fonts-liberation fonts-noto-core fonts-noto-cjk fonts-noto-color-emoji \
      novnc websockify \
    && rm -rf /var/lib/apt/lists/* \
    && if id ubuntu >/dev/null 2>&1; then \
         mv /home/ubuntu /home/user \
         && usermod --login user --home /home/user ubuntu \
         && groupmod --new-name user ubuntu; \
       else \
         useradd --create-home --user-group --shell /bin/bash --uid 1000 user; \
       fi \
    && mkdir -p /home/user/.config /home/user/Desktop /tmp/.X11-unix \
                /run/user/1000 /var/log/desktop /opt \
    && ln -s /usr/share/novnc /opt/noVNC \
    && sed -i 's/org\.gnome\.SettingsDaemon\.UsbProtection;//' \
         /usr/share/gnome-session/sessions/gnome.session \
    && printf 'user ALL=(ALL) NOPASSWD:ALL\n' > /etc/sudoers.d/user \
    && chmod 0440 /etc/sudoers.d/user \
    && chmod 1777 /tmp/.X11-unix \
    && chmod 0700 /run/user/1000 \
    && chown -R user:user /home/user /run/user/1000 /var/log/desktop

COPY --chmod=0755 scripts/start-desktop /usr/local/bin/start-desktop

# e2b-desktop 2.4.1 currently uses this command to start the desktop session.
# The script itself can start GNOME.
RUN ln -s /usr/local/bin/start-desktop /usr/local/bin/startxfce4

# The Template builder needs root to update /etc/passwd and /etc/group and
# inject runtime files. Keep the user account for SDK commands in the Sandbox,
# but keep root as the default user of the source image.
USER root
WORKDIR /home/user
EXPOSE 5900 6080
```

Use the following content for `scripts/start-desktop`. The Desktop SDK starts Xvfb first, verifies that the display is ready, and then invokes this script through the compatible `startxfce4` command:

```bash
#!/usr/bin/env bash
set -euo pipefail

export DISPLAY="${DISPLAY:-:0}"
export XDG_CURRENT_DESKTOP=GNOME
export XDG_SESSION_DESKTOP=gnome
export XDG_SESSION_TYPE=x11
export DESKTOP_SESSION=gnome
export GDK_BACKEND=x11
export LIBGL_ALWAYS_SOFTWARE=1
export XDG_RUNTIME_DIR="${XDG_RUNTIME_DIR:-/run/user/$(id -u)}"
export LANG="${LANG:-C.UTF-8}"
export LC_ALL="${LC_ALL:-C.UTF-8}"

# A Sandbox does not run systemd as PID 1. Start the system bus required by
# GNOME when it is not already available.
if [[ ! -S /run/dbus/system_bus_socket ]]; then
  sudo mkdir -p /run/dbus /run/systemd/seats /run/systemd/sessions \
    /run/systemd/users /run/systemd/inhibit
  sudo setsid dbus-daemon --system --nofork --nopidfile \
    > /var/log/desktop/system-dbus.log 2>&1 &
  for _ in {1..50}; do
    [[ -S /run/dbus/system_bus_socket ]] && break
    sleep 0.1
  done
  if [[ ! -S /run/dbus/system_bus_socket ]]; then
    echo "system D-Bus did not become ready" >&2
    exit 1
  fi
fi

login1_is_ready() {
  busctl --system --no-legend list 2>/dev/null |
    awk '$1 == "org.freedesktop.login1" && $2 != "-" { found=1 } END { exit !found }'
}

if ! login1_is_ready; then
  sudo setsid /lib/systemd/systemd-logind \
    > /var/log/desktop/logind.log 2>&1 &
  for _ in {1..50}; do
    login1_is_ready && break
    sleep 0.1
  done
  if ! login1_is_ready; then
    echo "systemd-logind did not become ready" >&2
    exit 1
  fi
fi

# GNOME can temporarily enter the Activities overview while it initializes on
# a headless Xvfb display. Exit that initial state during the bounded startup
# window so a new Sandbox opens directly on the normal desktop.
dismiss_initial_overview() {
  for _ in {1..50}; do
    pgrep -x gnome-shell >/dev/null 2>&1 && break
    sleep 0.2
  done

  for _ in {1..20}; do
    DISPLAY="$DISPLAY" xdotool key Escape >/dev/null 2>&1 || true
    sleep 0.5
  done
}
dismiss_initial_overview &

if [[ -n "${DBUS_SESSION_BUS_ADDRESS:-}" ]]; then
  exec gnome-session --session=gnome
fi
exec dbus-run-session -- gnome-session --session=gnome
```

On a headless Xvfb display, GNOME can enter the Activities (Launchpad-like) overview only after the Shell starts. The startup-only logic above sends Escape only during a bounded initialization window, so a newly created Sandbox opens on the normal desktop without user input. It is generic GNOME session initialization, not AgentBay or business-application configuration.

The following screenshot is from a newly created Sandbox based on this Ubuntu + GNOME `start-desktop` example. The verification script simulates no keyboard input; it starts `gnome-terminal` using the same D-Bus environment as the GNOME session. The window displays `GNOME Terminal ready` and an interactive shell, confirming that both the desktop and Terminal are visible rather than the Activities overview:

![A new Sandbox displays the full GNOME desktop and a Terminal window](../../../../../assets/en-US/agentbay-gnome-default-desktop.png)

The FC runtime also provides Custom Bootstrap for gatewayd to supervise extension processes such as desktop plug-ins and browser helper services. The following path is an example that you must replace. Enable it only after the image copies the matching script; omit both the `COPY` and `ENV` when no extension process is needed:

```dockerfile
# Replace scripts/start-desktop-extensions with your extension startup script.
COPY --chmod=0755 scripts/start-desktop-extensions /usr/local/bin/start-desktop-extensions
ENV FC_E2B_CUSTOM_BOOTSTRAP=/usr/local/bin/start-desktop-extensions \
    FC_E2B_CUSTOM_BOOTSTRAP_MODE=sync \
    MAX_STARTUP_WAIT=60s
```

- `FC_E2B_CUSTOM_BOOTSTRAP` is a script path or shell command. gatewayd runs it through `/bin/bash -lc`, restarts it after abnormal exits, and cleans it up when the Sandbox stops.
- `FC_E2B_CUSTOM_BOOTSTRAP_MODE` accepts `async` (the default, without readiness waiting) or `sync` (dynamic user ports return a retryable 503 until the extension is ready).
- In `sync` mode, the script must print the complete line `FC_E2B_CUSTOM_BOOTSTRAP_READY` to stdout after its services become ready, and then remain in the foreground waiting for its critical child processes. `MAX_STARTUP_WAIT` uses Go duration syntax, such as `60s`.

Use Custom Bootstrap for extension processes, not as a replacement for the GNOME session script above. `e2b-desktop==2.4.1` creates Xvfb before invoking `startxfce4`. Starting GNOME earlier from Custom Bootstrap can race with the Desktop SDK display startup. `Template.set_start_cmd()` is unsuitable for starting GNOME early for the same reason.

#### Register SVG application icons at build time

The generic Ubuntu + GNOME base image contains only the desktop runtime; it **must not include AgentBay or other application-specific configuration**. Put each application's binary, `.desktop` entry, and SVG icon in an application image derived from that base, and write them during `docker build`. Do not install icons or alter desktop configuration through `commands.run()` after a Sandbox is created.

Add the following to the application image Dockerfile. `hicolor/scalable/apps` is the standard GNOME icon-theme location for SVGs. `Icon` contains the filename stem, without `.svg`:

```dockerfile
COPY assets/icons/my-desktop-app.svg \
  /usr/share/icons/hicolor/scalable/apps/my-desktop-app.svg
COPY assets/applications/com.example.MyDesktopApp.desktop \
  /usr/share/applications/com.example.MyDesktopApp.desktop
RUN gtk-update-icon-cache -f /usr/share/icons/hicolor
```

Example `assets/applications/com.example.MyDesktopApp.desktop`:

```ini
[Desktop Entry]
Type=Application
Name=My Desktop App
Exec=/usr/local/bin/my-desktop-app
Icon=my-desktop-app
Terminal=false
StartupWMClass=my-desktop-app
Categories=Utility;
```

- Declare square SVG `width`, `height`, and `viewBox`, for example `width="256" height="256" viewBox="0 0 256 256"`. `librsvg2-common` supplies the GdkPixbuf SVG loader used by GTK; without it, an icon can be registered but still fall back to a low-resolution placeholder.
- `StartupWMClass` must match the application's actual window WM_CLASS. In a test image, obtain the actual value with `xprop -id <window-id> WM_CLASS`; do not assume that it is the binary name or application ID, since an interpreted application may report a runtime name such as Python or Java. A GTK application should also configure a stable `application_id`, and set `set_default_icon_name()` and the window `set_icon_name()` to the same icon name as the desktop entry.
- Rebuild, push, and create a new Template after changing icons or `.desktop` entries. A running Sandbox never inherits temporary configuration outside its image.

The image must also meet these compatibility requirements:

- It must provide a `linux/amd64` variant, `/bin/bash` at that exact path, and writable standard `/etc/passwd` and `/etc/group` files. The source image must use `root` as its default user while retaining the UID 1000 `user` account for SDK commands inside the Sandbox.
- `startxfce4` is the compatibility command currently used by `e2b-desktop==2.4.1`. For GNOME, it can delegate to your GNOME startup script; this does not require installing Xfce.
- `e2b-desktop==2.4.1` starts the proxy from `/opt/noVNC`. Ubuntu installs the `novnc` package under `/usr/share/novnc`, so the example provides the compatible layout through a symbolic link. noVNC uses port 6080, and x11vnc connects to the Xvfb desktop on port 5900.
- Install Chrome or another GUI application separately in the source image and pin its version. Do not download production dependencies after a Sandbox starts.
- A Custom Bootstrap script runs as `user`. The example configures passwordless `sudo` to start GNOME; narrow the sudoers rules to the commands your production image actually needs. Do not accept and concatenate untrusted commands from Sandbox creation parameters.
- Do not set `ENTRYPOINT ["/.fce2b/entrypoint"]` or copy `/.fce2b` into the source image. For a regular application image, the `Template.build()` builder mode injects these runtime files and sets the entry point. Declaring an entry point that does not exist yet causes `envd inject failed`. See [Build Custom Image Templates](../02.Templates/03.Build%20Custom%20Image%20Templates.md) for the complete image, ACR EE network, and builder requirements.

Pin the target architecture during the build. For production, replace `ubuntu:24.04` with a verified digest so that changes to the base image cannot make the build irreproducible:

```bash
docker buildx build \
  --platform linux/amd64 \
  --tag desktop-ubuntu24.04:20260831 \
  --load \
  .
```

Before pushing, start Xvfb, the desktop session, x11vnc, and noVNC locally. Confirm that a browser can open `http://127.0.0.1:<port>/vnc.html`, then verify screenshots, mouse and keyboard input, and Chrome startup. Push the image with a new immutable tag to an image registry under the same account and in the same region as FC Agent Sandbox that has been confirmed reachable by Template Builder.

Replace `E2B_DESKTOP_IMAGE` with that image address, set a new `E2B_DESKTOP_TEMPLATE` name, and reuse the §4.1.2 script to convert the Template and run the SDK smoke test. Do not infer or assemble a VPC Registry hostname from a public hostname; use the address provided by the platform and confirm it with a real Template build. Then establish a real RFB connection with the §6 browser noVNC client. Do not promote a custom image to production until rendering, live refresh, screenshots, and browser mouse/keyboard input all pass.

## 5. Migration examples

### 5.1 Common interaction loop (screenshot + action)

```python
# === Before migration: AgentBay ===
session = agent_bay.create(CreateSessionParams(image_id="linux_latest")).session
session.computer.move_mouse(640, 400)
session.computer.click_mouse(640, 400)
session.computer.input_text("echo hello")
session.computer.press_keys(["enter"])
png = session.computer.screenshot()

# === After migration: e2b-desktop SDK ===
import os

from e2b_desktop import Sandbox

desktop = Sandbox.create(
    template=os.environ["E2B_DESKTOP_TEMPLATE"],
    timeout=600,
)
try:
    # Launch Chrome and wait for rendering
    desktop.launch("google-chrome", "https://example.com")
    desktop.wait(10000)

    # Mouse: the E2B SDK is two-step (move + click); dragging uses tuples
    desktop.move_mouse(640, 400)
    desktop.left_click()
    desktop.double_click()
    desktop.drag((100, 100), (300, 300))
    desktop.scroll("down", 5)

    # Launch a preinstalled GUI program. setsid + nohup prevents command cleanup.
    desktop.commands.run(
        "setsid nohup xmessage -center 'desktop ready' "
        ">/tmp/xmessage.log 2>&1 </dev/null &"
    )
    desktop.wait(3000)

    # Screenshot (PNG bytes, feed to a vision model)
    image = desktop.screenshot()
    with open("desktop.png", "wb") as f:
        f.write(image)
finally:
    desktop.kill()
```

### 6.2 Frontend: HTML + CDN noVNC

```html
<!DOCTYPE html>
<html>
<head>
  <meta charset="utf-8">
  <title>FC Desktop</title>
  <style>
    #vnc-screen { width: 100vw; height: 100vh; }
  </style>
</head>
<body>
  <div id="vnc-screen"></div>

  <script type="module">
    // ESM import of the official noVNC build (pinned version)
    import RFB from 'https://cdn.jsdelivr.net/gh/novnc/noVNC@v1.6.0/core/rfb.js';

    async function initVNC() {
      // Get stream_url from the backend API
      const resp = await fetch('/api/sandbox/vnc-url');
      const { streamUrl, authKey } = await resp.json();

      const rfb = new RFB(
        document.getElementById('vnc-screen'),
        streamUrl,           // https://{sandbox-host}/vnc.html?autoconnect=true&resize=scale
                             // One URL, two roles: opening it in a browser serves the noVNC page;
                             // RFB upgrades it to wss://{sandbox-host}/vnc.html as the WebSocket
                             // endpoint (proxied by websockify to x11vnc)
        { credentials: { password: authKey } }
      );

      rfb.scaleViewport = true;
      rfb.resizeSession = false;
    }

    initVNC();
  </script>
</body>
</html>
```

- The browser connects directly to `wss://{sandbox-host}/vnc.html` with no custom request headers (verified: GET 200, RFB handshake succeeds). VNC auth is controlled by `stream.start(require_auth=True)` + `get_url(auth_key=...)`; when enabled, return `auth_key` to the frontend together with the URL and pass it in as `credentials.password`.
- If the data plane requires a traffic access token, the FC backend supports passing it as a query parameter (appended to `stream_url` by the backend, see §6.1). The browser WebSocket needs no custom headers and no relay service; noVNC is transparent to extra query parameters (verified with the `password=` parameter).
- No custom Web SDK is needed: noVNC (CDN ESM) is the complete data-plane client, with all connection parameters carried in the URL.

### Code

#### demo.py (backend Python: sandbox lifecycle + HTTP service)

```python
"""Linux Desktop + noVNC WebSDK integration demo (backend).

Three files ship together: demo.py (this file), index.html (frontend), and .env (credentials); see README.md for instructions.

Dependencies: pip install e2b==2.31.0 e2b-desktop==2.4.1 python-dotenv
Run: python demo.py   (open the printed http://127.0.0.1:<port>/ in a browser to see the live desktop)
"""
from __future__ import annotations

import json
import os
import signal
from http.server import BaseHTTPRequestHandler, ThreadingHTTPServer
from pathlib import Path

from dotenv import load_dotenv
from e2b import Template, default_build_logger
from e2b_desktop import Sandbox

BASE_DIR = Path(__file__).resolve().parent
load_dotenv(BASE_DIR / ".env")

TEMPLATE = os.environ["E2B_DESKTOP_TEMPLATE"]
IMAGE = os.environ.get("E2B_DESKTOP_IMAGE", "")
HOST = "127.0.0.1"


def ensure_template() -> str:
    if Template.exists(TEMPLATE):
        print(f"[demo] reuse template: {TEMPLATE}", flush=True)
        return TEMPLATE
    if not IMAGE:
        raise SystemExit(
            f"[demo] template {TEMPLATE!r} does not exist; set E2B_DESKTOP_IMAGE in .env to build it automatically"
        )
    print(f"[demo] build template {TEMPLATE!r} from image: {IMAGE}", flush=True)
    build = Template.build(
        Template().from_image(IMAGE),
        name=TEMPLATE,
        cpu_count=4,
        memory_mb=8192,
        on_build_logs=default_build_logger(),
    )
    return build.template_id


class Handler(BaseHTTPRequestHandler):
    stream_url: str = ""
    auth_key: str = ""

    def do_GET(self) -> None:
        if self.path == "/api/sandbox/vnc-url":
            body = json.dumps({
                "streamUrl": Handler.stream_url,
                "authKey": Handler.auth_key,
            }).encode("utf-8")
            self.send_response(200)
            self.send_header("Content-Type", "application/json")
            self.send_header("Content-Length", str(len(body)))
            self.end_headers()
            self.wfile.write(body)
            return
        if self.path in ("/", "/index.html"):
            body = (BASE_DIR / "index.html").read_bytes()
            self.send_response(200)
            self.send_header("Content-Type", "text/html; charset=utf-8")
            self.send_header("Content-Length", str(len(body)))
            self.end_headers()
            self.wfile.write(body)
            return
        if self.path == "/favicon.ico":
            self.send_response(204)
            self.end_headers()
            return
        self.send_error(404)

    def log_message(self, *args) -> None:
        pass  # no access log, so no URL (including query parameters) is written to disk


def _stop(_signum, _frame) -> None:
    raise KeyboardInterrupt


def main() -> None:
    signal.signal(signal.SIGTERM, _stop)

    template = ensure_template()
    print("[demo] creating desktop sandbox (Xvfb + xfce4 + x11vnc + noVNC)...", flush=True)
    desktop = Sandbox.create(template=template, timeout=600, secure=True)
    server: ThreadingHTTPServer | None = None
    try:
        desktop.stream.start(require_auth=True)
        stream_url = desktop.stream.get_url()
        auth_key = desktop.stream.get_auth_key()
        # If the data plane requires a traffic access token, append it as a query parameter here:
        # token = getattr(desktop, "traffic_access_token", None)
        # if token:
        #     stream_url += f"&token={token}"

        Handler.stream_url = stream_url
        Handler.auth_key = auth_key
        server = ThreadingHTTPServer((HOST, 0), Handler)
        print(f"[demo] open in browser: http://127.0.0.1:{server.server_port}/", flush=True)
        print("[demo] Ctrl-C to exit (stops the stream and destroys the sandbox)", flush=True)
        server.serve_forever()
    except KeyboardInterrupt:
        print("\n[demo] exiting...", flush=True)
    finally:
        if server is not None:
            server.server_close()
        try:
            desktop.stream.stop()
        except Exception:
            pass
        desktop.kill()
        print("[demo] VNC stream stopped and sandbox destroyed", flush=True)


if __name__ == "__main__":
    main()
```

    import RFB from 'https://cdn.jsdelivr.net/gh/novnc/noVNC@v1.6.0/core/rfb.js';

    async function initVNC() {
      // The API key and sandbox lifecycle stay in the backend. The browser receives the
      // ephemeral streamUrl and authKey for the current session to establish VNC.

        // opening it in a browser serves the noVNC page; RFB upgrades it to
        // wss://.../vnc.html as the WebSocket endpoint
        streamUrl,
        { credentials: { password: authKey } }
      );

      rfb.scaleViewport = true;
      rfb.resizeSession = false;
    }

    initVNC();
