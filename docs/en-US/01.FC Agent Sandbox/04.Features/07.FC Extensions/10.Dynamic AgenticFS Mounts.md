# Dynamic AgenticFS Mounts

Dynamic AgenticFS mounts let you mount an existing AgenticFS AgenticSpace Access Point or one of its subdirectories into a local directory when you create a sandbox. After the mount is ready, the sandbox can read and write the mounted directory as a local file system.

This method submits the AgenticFS mount configuration directly through sandbox metadata and does not require an FC Agent Sandbox Volume. To reuse a saved mount configuration, first [create an AgenticFS Volume](./08.Create%20an%20AgenticFS%20Volume.md), and then use `volume_mounts` to [mount the AgenticFS Volume](../12.Volumes/02.Mount%20an%20AgenticFS%20Volume.md). To append a mount to a running sandbox, see [Append Sandbox Storage Mounts](./09.Append%20Sandbox%20Storage%20Mounts.md).

Pass the following metadata when you create the sandbox:

- `fc.sandbox.storage.agenticfs`: The AgenticFS mount configuration as a JSON string.
- `fc.sandbox.network.vpc`: The complete VPC configuration used to access the AgenticFS Access Point, as a JSON string.
- `fc.sandbox.auth.role`: The ARN of the RAM role used to access AgenticFS.

## Prerequisites

For AgenticFS product concepts, see [What is AgenticFS](https://www.alibabacloud.com/help/en/nas/product-overview/agenticfs-overview). Create and manage related resources in the [NAS console](https://nasnext.console.aliyun.com/).

Before you begin, prepare the following resources:

- An AgenticFS file system, an AgenticSpace, and a RAM-enabled Access Point. Make sure that the Access Point is in the `active` state.
- The Access Point address, such as `ap-<access-point-id>.<file-system-id>-<suffix>.<region>.nas.aliyuncs.com:/`.
- A VPC, vSwitch, and security group that can reach the Access Point.
- A function execution RAM role that has AgenticFS mount and read/write permissions and whose trust policy allows Function Compute to assume it.
- An FC Agent Sandbox API key, API URL, domain, and an available template.

### Second-generation runtime image requirements

If you use a custom template with the [second-generation runtime (MicroVM)](../02.Templates/08.Build%20and%20Manage%20Templates%20via%20OpenAPI.md), install the AgenticFS client in the source image before building the template. For client installation, image build, and verification instructions, see the second-generation runtime image requirements in [Mount an AgenticFS Volume](../12.Volumes/02.Mount%20an%20AgenticFS%20Volume.md).

## Configure permissions

Attach the following policy to the function execution RAM role:

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "nas:ClientMount",
        "nas:ClientWrite",
        "nas:ClientRootAccess"
      ],
      "Resource": "*"
    }
  ]
}
```

The trust policy of the role must also allow Function Compute to assume the role. For more information, see [Policies and sample policies](https://www.alibabacloud.com/help/en/functioncompute/policies-and-sample-policies).

## Mount configuration

The value of `fc.sandbox.storage.agenticfs` must be a JSON string with the following structure:

```json
{
  "userID": 1000,
  "groupID": 1000,
  "mountPoints": [
    {
      "serverAddr": "ap-<access-point-id>.<file-system-id>-<suffix>.<region>.nas.aliyuncs.com:/project-a",
      "mountDir": "/mnt/agenticfs"
    }
  ]
}
```

The following table describes the fields:

| Field | Required | Description |
| --- | --- | --- |
| `userID` | No | The user ID used for the mount. Valid values range from `-1` to `65534`. All mount points in the configuration use this value. |
| `groupID` | No | The group ID used for the mount. Valid values range from `-1` to `65534`. All mount points in the configuration use this value. |
| `mountPoints` | Yes | The AgenticFS mount point list. It must contain at least one mount point. |
| `mountPoints[].serverAddr` | Yes | The AgenticFS Access Point address. You can specify a remote subdirectory after `:/`. |
| `mountPoints[].mountDir` | Yes | The mount directory in the sandbox. It must be a normalized absolute Unix path, such as `/mnt/agenticfs`. |

Field names are case-sensitive. Use `userID`, `groupID`, `serverAddr`, and `mountDir` exactly as shown. The platform enables TLS for AgenticFS mounts. Do not pass `enableTLS` in the configuration. The configuration is decoded as strict JSON, and undeclared fields cause sandbox creation to fail.

## Local mount directory

`mountDir` is the mount point in the local file system of the sandbox, not a remote AgenticFS directory.

- We recommend using a subdirectory of `/home`, `/mnt`, `/tmp`, or `/data`, such as `/mnt/agenticfs` or `/data/files`, to avoid covering existing directories in the template.
- Do not use `/`. The path cannot contain leading or trailing whitespace, `.`, `..`, or duplicate path separators.
- Mount directories in the same sandbox must be unique, including mount directories used by other storage types.

## Create a sandbox with an AgenticFS mount

For the basic sandbox creation procedure, see [Create a sandbox](../01.Sandbox/02.Create%20a%20Sandbox.md). The following Python example dynamically mounts AgenticFS when creating a sandbox and verifies file write, read, and delete operations. Save the code as `10_sandbox_agenticfs.py`:

```python
import json
import os

from e2b import Sandbox


def require_env(name: str) -> str:
    value = os.environ.get(name, "").strip()
    if not value:
        raise RuntimeError(f"Missing environment variable: {name}")
    return value


mount_dir = "/mnt/agenticfs"
marker_path = f"{mount_dir}/hello-agenticfs.txt"
agenticfs_config = {
    "userID": int(require_env("AGENTICFS_USER_ID")),
    "groupID": int(require_env("AGENTICFS_GROUP_ID")),
    "mountPoints": [
        {
            "serverAddr": require_env("AGENTICFS_SERVER_ADDR"),
            "mountDir": mount_dir,
        }
    ],
}
vpc_config = {
    "vpcId": require_env("FCSANDBOX_VPC_ID"),
    "securityGroupId": require_env("FCSANDBOX_SECURITY_GROUP_ID"),
    "vSwitchIds": [require_env("FCSANDBOX_VSWITCH_ID")],
}

sandbox = None
marker_written = False
try:
    sandbox = Sandbox.create(
        template=require_env("E2B_TEMPLATE"),
        timeout=300,
        api_key=require_env("E2B_API_KEY"),
        api_url=require_env("E2B_API_URL"),
        domain=require_env("E2B_DOMAIN"),
        metadata={
            "fc.sandbox.storage.agenticfs": json.dumps(agenticfs_config),
            "fc.sandbox.network.vpc": json.dumps(vpc_config),
            "fc.sandbox.auth.role": require_env("FCSANDBOX_ROLE_ARN"),
        },
    )

    sandbox.files.write(marker_path, "hello agenticfs\n")
    marker_written = True
    content = sandbox.files.read(marker_path)
    if content != "hello agenticfs\n":
        raise RuntimeError(f"File content mismatch: {content!r}")
finally:
    try:
        if sandbox is not None and marker_written:
            sandbox.files.remove(marker_path)
    finally:
        if sandbox is not None:
            sandbox.kill()

print("AgenticFS dynamic mount read/write validation succeeded")
```

Set the following environment variables before running the example:

```bash
export E2B_API_KEY="<your-e2b-api-key>"
export E2B_API_URL="https://api.<region>.e2b.fc.aliyuncs.com"
export E2B_DOMAIN="<region>.e2b.fc.aliyuncs.com"
export E2B_TEMPLATE="<template-id>"

export AGENTICFS_SERVER_ADDR="ap-<access-point-id>.<file-system-id>-<suffix>.<region>.nas.aliyuncs.com:/"
export AGENTICFS_USER_ID="1000"
export AGENTICFS_GROUP_ID="1000"

export FCSANDBOX_VPC_ID="vpc-xxxxxxxx"
export FCSANDBOX_SECURITY_GROUP_ID="sg-xxxxxxxx"
export FCSANDBOX_VSWITCH_ID="vsw-xxxxxxxx"
export FCSANDBOX_ROLE_ARN="acs:ram::<account-id>:role/<execution-role>"

python 10_sandbox_agenticfs.py
```

## Mount a subdirectory of an Access Point

Specify a remote directory after `:/` in `serverAddr` to mount only a subdirectory of the Access Point. For example:

```text
ap-<access-point-id>.<file-system-id>-<suffix>.<region>.nas.aliyuncs.com:/project-a
```

If the remote subdirectory does not exist, the system creates it when the sandbox is mounted for the first time. The remote path must be a normalized absolute path. It cannot contain whitespace, control characters, duplicate separators, `.`, or `..`, and cannot end with `/`.

## Limits

- The values of `fc.sandbox.storage.agenticfs` and `fc.sandbox.network.vpc` must be JSON strings. Do not pass Python dictionaries directly.
- The metadata key must be the all-lowercase `fc.sandbox.storage.agenticfs`. `fc.sandbox.storage.agenticFs` and `fc.sandbox.storage.agentic_fs` are not recognized as AgenticFS mount configurations.
- `serverAddr` must be an AgenticFS Access Point address, not a general-purpose NAS mount address or a URL with a protocol prefix. Its maximum length is 128 characters.
- `mountDir` can be up to 128 characters. It must be a normalized absolute Unix path and cannot be `/`.
- When creating the sandbox, provide a complete VPC configuration through `fc.sandbox.network.vpc` and an execution role through `fc.sandbox.auth.role`. The VPC configuration in the template cannot replace this metadata.
- Multiple AgenticFS mount points in the same sandbox use the same `userID` and `groupID` values.

## Troubleshooting

### Sandbox creation reports an incomplete VPC configuration

Make sure that `fc.sandbox.network.vpc` contains `vpcId`, `securityGroupId`, and a non-empty `vSwitchIds` list. Also check network connectivity between the VPC and the Access Point.

### Sandbox creation reports that a function role is required

Make sure that `fc.sandbox.auth.role` is not empty, the role has AgenticFS mount and read/write permissions, and its trust policy allows Function Compute to assume it.

### Metadata returns an unknown-field error

AgenticFS metadata uses strict JSON decoding. Check the field name casing and remove undeclared fields such as `enableTLS` and `readOnly`.

### The mount fails during sandbox creation

Make sure that the Access Point is in the `active` state. Check the Access Point address, remote subdirectory, VPC connectivity, execution role permissions, and the AgenticFS client in the custom image. Retain the request ID for troubleshooting.
