# Create a JuiceFS Volume

A JuiceFS Volume stores the mount configuration of an existing JuiceFS Enterprise file system. After the Volume is created, mount it by Volume name when creating a sandbox.

`CreateVolume` only creates and stores Volume metadata. It does not create, delete, or copy a JuiceFS file system or its data.

## Prerequisites

Prepare the following resources and information:

- A Team has been created in the FC Agent Sandbox console, and its Team ID is available.
- A file system has been created in the [JuiceFS Enterprise console](https://juicefs.com/console). The file system name, access token, and service address are available. For more information, see [JuiceFS Enterprise quick start](https://juicefs.com/docs/cloud/getting_started/).
- The Alibaba Cloud identity that calls the POP SDK has the `fcsandbox:CreateVolume` permission. Querying Volumes requires `fcsandbox:ListVolumes` and `fcsandbox:GetVolume`. Deleting Volumes requires `fcsandbox:DeleteVolume`.

For information about creating a Team and obtaining its Team ID, see [Create a Team](../../01.Getting%20Started/02.Create%20a%20Team.md).

## Configure permissions

Grant the following permissions to the Resource Access Management (RAM) identity that calls the Volume API. Replace the placeholders with actual values.

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "fcsandbox:CreateVolume",
        "fcsandbox:ListVolumes",
        "fcsandbox:GetVolume",
        "fcsandbox:DeleteVolume"
      ],
      "Resource": "*"
    }
  ]
}
```

In production, permissions can be scoped to Volume resources in a specific Team:

```text
acs:fcsandbox:<region>:<account-id>:teams/<team-id>/volumes/*
```

## Install the SDK

The FC Agent Sandbox OpenAPI supports Java, Python, Go, and TypeScript SDKs. For supported languages, installation instructions, and versions, see [Alibaba Cloud SDK and API reference](https://www.alibabacloud.com/help/en/functioncompute/alibaba-cloud-sdk-api-description). This guide uses Python.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install --upgrade alibabacloud_sandbox20260820
```

Set the following environment variables before running the example:

```bash
export ALIBABA_CLOUD_ACCESS_KEY_ID="<your-access-key-id>"
export ALIBABA_CLOUD_ACCESS_KEY_SECRET="<your-access-key-secret>"
# Also set this variable when using an STS temporary credential:
# export ALIBABA_CLOUD_SECURITY_TOKEN="<your-security-token>"

export FCSANDBOX_REGION_ID="<region>"
export FCSANDBOX_ENDPOINT="sandbox.<region>.aliyuncs.com"
export FCSANDBOX_TEAM_ID="<team-id>"
export FCSANDBOX_VOLUME_NAME="juicefs-workspace"

export JUICEFS_VOLUME_NAME="<juicefs-file-system-name>"
export JUICEFS_BASE_URL="https://<juicefs-service-address>"
export JUICEFS_TOKEN="<juicefs-token>"
export JUICEFS_REMOTE_DIR="/"
```

Do not include `https://` in `FCSANDBOX_ENDPOINT`. If the SDK includes a built-in endpoint for the target region, this variable can be omitted. The SDK resolves the endpoint from `FCSANDBOX_REGION_ID`.

## Create a JuiceFS Volume

For request parameters, response parameters, and error codes, see [CreateVolume - Create a Volume](https://api.aliyun.com/api/Sandbox/2026-08-20/CreateVolume) in OpenAPI Explorer.

The following table describes the fields in `juiceFSVolumeConfig`.

| Field | Required | Description |
| --- | --- | --- |
| `volumeName` | Yes | The JuiceFS file system name. This is not the FC Agent Sandbox Volume name. |
| `baseURL` | Yes | The service address used by the JuiceFS Enterprise client. |
| `remoteDir` | No | The remote directory to mount in the JuiceFS file system. The example explicitly sets this field to `/`. |
| `token` | Yes | The access token of the JuiceFS file system. Volume query responses do not return this field. |
| `args` | No | Additional mount arguments passed to the JuiceFS client as an array of strings. The platform generates the client options `--token` and `--subdir` from `token` and `remoteDir`. Do not pass these two options again in this field. |

`baseURL` and `envs.BASE_URL` in a direct metadata mount both specify the JuiceFS service address, but they belong to different request structures. Use `juiceFSVolumeConfig.baseURL` when creating a JuiceFS Volume. For a direct metadata mount, use `envs.BASE_URL` in `fc.sandbox.storage.juicefs`.

`--subdir` is the JuiceFS client option for mounting a remote subdirectory. It corresponds to `remoteDir`, not the local mount directory in the sandbox. Set `remoteDir`; the platform performs the conversion during the mount.

The following example uses the `JuiceFSVolumeConfig` model in the new Python SDK to create a JuiceFS Volume and prints the result. Save the code as `11_create_juicefs_volume.py`:

```python
import os

from alibabacloud_sandbox20260820 import models
from alibabacloud_sandbox20260820.client import Client as SandboxClient
from alibabacloud_tea_openapi import models as open_api_models


def require_env(name: str) -> str:
    value = os.environ.get(name, "").strip()
    if not value:
        raise RuntimeError(f"missing environment variable: {name}")
    return value


config = open_api_models.Config(
    access_key_id=require_env("ALIBABA_CLOUD_ACCESS_KEY_ID"),
    access_key_secret=require_env("ALIBABA_CLOUD_ACCESS_KEY_SECRET"),
    security_token=os.environ.get("ALIBABA_CLOUD_SECURITY_TOKEN"),
    region_id=require_env("FCSANDBOX_REGION_ID"),
)
if os.environ.get("FCSANDBOX_ENDPOINT"):
    config.endpoint = os.environ["FCSANDBOX_ENDPOINT"]

pop_client = SandboxClient(config)
response = pop_client.create_volume(
    models.CreateVolumeRequest(
        body=models.CreateVolumeInput(
            team_id=require_env("FCSANDBOX_TEAM_ID"),
            volume_name=require_env("FCSANDBOX_VOLUME_NAME"),
            juice_fsvolume_config=models.JuiceFSVolumeConfig(
                volume_name=require_env("JUICEFS_VOLUME_NAME"),
                base_url=require_env("JUICEFS_BASE_URL"),
                remote_dir=require_env("JUICEFS_REMOTE_DIR"),
                token=require_env("JUICEFS_TOKEN"),
                args=[],
            ),
        )
    )
)

if response.body is None or response.body.volume is None:
    raise RuntimeError("CreateVolume did not return a Volume")

volume = response.body.volume
print(f"request_id={response.body.request_id}")
print(f"volume_id={volume.volume_id}")
print(f"volume_name={volume.volume_name}")
print(f"storage_class={volume.storage_class}")
print(f"status={volume.status}")
```

Run the example:

```bash
python 11_create_juicefs_volume.py
```

`CreateVolume` only creates and stores Volume metadata. It does not test connectivity to the JuiceFS service or perform a mount. See [Mount a JuiceFS Volume](../12.Volumes/04.Mount%20a%20JuiceFS%20Volume.md) to mount the Volume to a sandbox and verify it by reading and writing files.

## Mount a remote subdirectory

`remoteDir` limits the directory tree that the Volume can access in the JuiceFS file system. For example, after `JUICEFS_REMOTE_DIR` is set to `/datasets/project-a`, the mount directory in the sandbox maps to this remote subdirectory instead of the file system root.

If the remote subdirectory does not exist, it is created when the Volume is mounted:

```bash
export JUICEFS_REMOTE_DIR="/datasets/project-a"
python 11_create_juicefs_volume.py
```

Use an absolute remote path that starts with `/`. The token must have the permissions required to create and access the target directory.

## Manage Volumes

Use [ListVolumes](https://api.aliyun.com/api/Sandbox/2026-08-20/ListVolumes) to list Volumes, [GetVolume](https://api.aliyun.com/api/Sandbox/2026-08-20/GetVolume) to view details, and [DeleteVolume](https://api.aliyun.com/api/Sandbox/2026-08-20/DeleteVolume) to delete a Volume that is no longer needed.

Deleting a Volume only removes its mount configuration from FC Agent Sandbox. It does not delete the JuiceFS file system or its data.

## Limits

- Only JuiceFS Enterprise is supported.
- `remoteDir` is limited to 128 bytes, and `token` is limited to 256 bytes.
- A JuiceFS Volume uses an existing customer-managed file system. StorageProfile is not supported, and FC Agent Sandbox does not create or delete external storage resources.
- Volume names must be unique within a Team.
- Do not print request bodies, JuiceFS tokens, or other credentials in logs.
