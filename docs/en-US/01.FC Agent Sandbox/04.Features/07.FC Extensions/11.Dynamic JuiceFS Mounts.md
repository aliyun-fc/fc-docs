# Dynamic JuiceFS Mounts

When creating a Sandbox, use the `fc.sandbox.storage.juicefs` metadata field to mount an existing JuiceFS file system to a specified directory. The Sandbox can then access JuiceFS through file paths, and the data is not deleted when the Sandbox is released.

Currently, JuiceFS mounts can be configured only through metadata when a Sandbox is created.

## Prerequisites

- Create a file system in the [JuiceFS Enterprise console](https://juicefs.com/console) and obtain its file system name, access token, and service endpoint. For more information, see [JuiceFS Enterprise quick start](https://juicefs.com/docs/cloud/getting_started/).
- A VPC, vSwitch, and security group that can reach the JuiceFS service are ready.
- An FC Agent Sandbox API key, API URL, domain, and a second-generation runtime (MicroVM) custom template are ready.

### Image requirements for the second-generation runtime

Dynamic JuiceFS mounts require the [second-generation runtime (MicroVM)](../02.Templates/08.Build%20and%20Manage%20Templates%20via%20OpenAPI.md). Before building a custom template, you must install the JuiceFS Enterprise client and FUSE in the source image. The second-generation runtime uses the source image directly and does not inject the JuiceFS client during the template build.

Only JuiceFS Enterprise is supported. JuiceFS provides Enterprise Mount images in the [`juicedata/mount`](https://hub.docker.com/r/juicedata/mount/tags) repository on Docker Hub. Enterprise image tags start with `ee-`. In the image, `/usr/bin/juicefs` is a client launcher, and the fixed-version client executable is located at `/usr/local/juicefs/mount/jfsmount`.

The following example uses `juicedata/mount:ee-5.3.7-58af72b`, where `5.3.7` is the client version and `58af72b` is the build commit. Check version information against the [JuiceFS command reference](https://juicefs.com/docs/cloud/reference/command_reference/). For more information about images and containers, see [Use JuiceFS in Docker](https://juicefs.com/docs/cloud/use_juicefs_in_docker/).

First, pull the image and verify the Enterprise client:

```bash
docker pull --platform linux/amd64 \
  juicedata/mount:ee-5.3.7-58af72b

docker run --rm --platform linux/amd64 \
  --entrypoint /usr/bin/juicefs \
  juicedata/mount:ee-5.3.7-58af72b \
  version
```

The output must show client version `5.3.7` and build commit `58af72b`. Do not use floating tags such as `latest` or `ee-nightly`, because rebuilding the template could then change the client version. If your build environment cannot access Docker Hub, synchronize the image to an accessible private image registry and replace the `juicedata/mount` image address in the following Dockerfile.

The following Dockerfile uses Ubuntu 22.04 by default. To extend an existing Sandbox base image, pass its image address through the `BASE_IMAGE` build argument:

```dockerfile
ARG BASE_IMAGE=ubuntu:22.04

FROM juicedata/mount:ee-5.3.7-58af72b AS juicefs-ee

FROM ${BASE_IMAGE}

ARG DEBIAN_FRONTEND=noninteractive

RUN set -eux; \
    apt-get update; \
    apt-get install -y --no-install-recommends \
        ca-certificates \
        fuse \
        librados2; \
    rm -rf /var/lib/apt/lists/*

COPY --from=juicefs-ee /usr/local/juicefs/mount/jfsmount /usr/bin/juicefs

RUN set -eux; \
    chmod 0755 /usr/bin/juicefs; \
    command -v juicefs; \
    command -v fusermount; \
    mkdir -p /mnt/juicefs

WORKDIR /root

# Do not set a custom USER, ENTRYPOINT, or CMD. The sandbox control plane manages startup.
```

Do not store the JuiceFS token or mount configuration in the Dockerfile or image layers.

Build and push a `linux/amd64` image. Replace the placeholders with actual values:

```bash
docker buildx build \
  --platform linux/amd64 \
  --build-arg BASE_IMAGE="<your-sandbox-base-image>" \
  --push \
  -t "<registry>/<namespace>/microsandbox-juicefs-ee:<version>" \
  .
```

After the build is complete, verify the client, the RADOS runtime library, and FUSE 2 in the image:

```bash
docker run --rm --platform linux/amd64 \
  --entrypoint /bin/sh \
  <registry>/<namespace>/microsandbox-juicefs-ee:<version> \
  -euxc '
    command -v juicefs
    command -v fusermount
    ldconfig -p | grep "librados\.so\.2"
    juicefs version
  '
```

This check verifies only the image contents. It does not verify VPC connectivity, the token, or an actual mount. Rebuild the MicroVM template with this image before running the following example.

## Mount configuration

The value of `fc.sandbox.storage.juicefs` is a JSON string with the following structure:

```json
{
  "mountPoints": [
    {
      "volumeName": "<juicefs-file-system-name>",
      "remoteDir": "/",
      "mountDir": "/mnt/juicefs",
      "token": "<juicefs-token>",
      "args": []
    }
  ],
  "envs": {
    "BASE_URL": "https://<juicefs-service-address>"
  }
}
```

The following table describes the fields:

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `mountPoints` | Array of objects | Yes | A list of JuiceFS mount points. Up to five mount points are supported. |
| `volumeName` | String | Yes | The JuiceFS file system name. This is not an FC Agent Sandbox Volume name or ID. |
| `remoteDir` | String | No | A remote directory in the JuiceFS file system, such as `/datasets/project-a`. If the directory does not exist, it is created during the mount. Explicitly set this field to avoid relying on an unspecified API default. |
| `mountDir` | String | Yes | The local mount directory in the Sandbox. It must be an absolute path, such as `/mnt/juicefs`. |
| `token` | String | Yes | The access token of the JuiceFS file system. |
| `args` | Array of strings | No | Additional mount options passed to the JuiceFS client. This field can be an empty array. The platform manages `--token` and `--subdir` based on `token` and `remoteDir`. You cannot override these two options in this field. |
| `envs` | Object | Yes | Environment variables passed only to the JuiceFS mount process. They are not added to Sandbox user processes. |
| `envs.BASE_URL` | String | Yes | The service endpoint accessed by the JuiceFS Enterprise client. Field names are case-sensitive. |
| `envs.GOGC` | String | No | An optional Go garbage collection tuning parameter for the JuiceFS mount process. For example, `"50"` can reduce the memory target but may increase garbage collection frequency and CPU overhead. This parameter is usually unnecessary. |

`--conf-dir` is not prohibited by the platform. To specify it, add a normalized absolute subdirectory of `/tmp` to `args`, such as `["--conf-dir", "/tmp/juicefs-config"]`. If omitted, the platform generates an isolated configuration directory for the mount.

If `JUICEFS_REMOTE_DIR` is not set, the Python example in this topic explicitly uses `/`. This is a default in the sample code, not a statement about the server-side API default.

## Install the SDK

This topic uses the E2B Python SDK:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install "e2b>=2.31.0"
```

Set the following environment variables before running the example:

```bash
export E2B_API_KEY="<your-e2b-api-key>"
export E2B_API_URL="https://api.<region>.e2b.fc.aliyuncs.com"
export E2B_DOMAIN="<region>.e2b.fc.aliyuncs.com"
export E2B_TEMPLATE="<microvm-template-id>"

export FCSANDBOX_VPC_ID="vpc-xxxxxxxx"
export FCSANDBOX_SECURITY_GROUP_ID="sg-xxxxxxxx"
export FCSANDBOX_VSWITCH_ID="vsw-xxxxxxxx"

export JUICEFS_BASE_URL="http://<juicefs-service-address>:<port>"
export JUICEFS_VOLUME_NAME="<juicefs-volume-name>"

export JUICEFS_MOUNT_DIR="/mnt/juicefs"
```

`JUICEFS_ARGS_JSON` is optional. If it is unset or set to an empty string, the example treats it as an empty array, `[]`.

## Create a Sandbox with a JuiceFS mount

The following example uses metadata to create a Sandbox with a JuiceFS mount and verifies file read/write. Save the code as `11_sandbox_juicefs.py`:

```python
import json
import os

from e2b import Sandbox


def require_env(name: str) -> str:
    value = os.environ.get(name, "").strip()
    if not value:
        raise RuntimeError(f"missing environment variable: {name}")
    return value


def optional_env(name: str, default: str) -> str:
    return os.environ.get(name, "").strip() or default


def juicefs_args() -> list[str]:
    value = json.loads(os.environ.get("JUICEFS_ARGS_JSON", "").strip() or "[]")
    if not isinstance(value, list) or not all(isinstance(item, str) for item in value):
        raise RuntimeError("JUICEFS_ARGS_JSON must be an array of strings")

    managed_options = ("--token", "--subdir")
    for item in value:
        if any(item == option or item.startswith(f"{option}=") for option in managed_options):
            raise RuntimeError(f"JUICEFS_ARGS_JSON cannot override a managed option: {item}")
    return value


mount_dir = optional_env("JUICEFS_MOUNT_DIR", "/mnt/juicefs")
marker_path = f"{mount_dir}/hello-juicefs.txt"

vpc_config = {
    "vpcId": require_env("FCSANDBOX_VPC_ID"),
    "securityGroupId": require_env("FCSANDBOX_SECURITY_GROUP_ID"),
    "vSwitchIds": [require_env("FCSANDBOX_VSWITCH_ID")],
}

juicefs_config = {
    "mountPoints": [
        {
            "volumeName": require_env("JUICEFS_VOLUME_NAME"),
            "remoteDir": optional_env("JUICEFS_REMOTE_DIR", "/"),
            "mountDir": mount_dir,
            "token": require_env("JUICEFS_TOKEN"),
            "args": juicefs_args(),
        }
    ],
    "envs": {
        "BASE_URL": require_env("JUICEFS_BASE_URL"),
    },
}

sandbox = None
marker_written = False

try:
    sandbox = Sandbox.create(
        template=require_env("E2B_TEMPLATE"),
        timeout=300,
        api_key=require_env("E2B_API_KEY"),
        api_url=require_env("E2B_API_URL"),
        domain=require_env("E2B_DOMAIN"),
        metadata={
            "fc.sandbox.network.vpc": json.dumps(vpc_config),
            "fc.sandbox.storage.juicefs": json.dumps(juicefs_config),
        },
    )

    sandbox.files.write(marker_path, "hello juicefs\n")
    marker_written = True
    content = sandbox.files.read(marker_path)
    if content != "hello juicefs\n":
        raise RuntimeError(f"file content mismatch: {content!r}")
finally:
    try:
        if sandbox is not None and marker_written:
            sandbox.files.remove(marker_path)
    finally:
        if sandbox is not None:
            sandbox.kill()

print("JuiceFS mount read/write verification succeeded")
```

Run the example:

```bash
python 11_sandbox_juicefs.py
```

## Mount a remote subdirectory

`remoteDir` limits the directory scope that the mount point can access in JuiceFS. For example, if you set `JUICEFS_REMOTE_DIR` to `/datasets/project-a`, `JUICEFS_MOUNT_DIR` in the Sandbox maps to that remote subdirectory instead of the file system root.

If the remote subdirectory does not exist, it is automatically created in the JuiceFS file system during the mount. Run the following commands to mount the subdirectory:

```bash
export JUICEFS_REMOTE_DIR="/datasets/project-a"
python 11_sandbox_juicefs.py
```

Use an absolute remote path that starts with `/`, and ensure that the token has the permissions required to create and access the target directory.

## Behavior

- The values of the `fc.sandbox.storage.juicefs` and `fc.sandbox.network.vpc` metadata fields must be JSON strings. Do not pass Python dictionaries directly.
- `mountDir` is the local mount directory inside the Sandbox. `remoteDir` is the remote directory in the JuiceFS file system. They belong to different path spaces.
- The metadata path uses `envs.BASE_URL` for the JuiceFS service address. Field names are case-sensitive. Do not use `baseURL`.
- `args` contains additional JuiceFS client mount options and can be an empty array. Do not override the platform-managed `--token` or `--subdir` options in `args`. Omit `--conf-dir` or specify it subject to the constraints in Mount configuration.
- A Sandbox restores the JuiceFS mount after it is paused and resumed. JuiceFS data is independent of the Sandbox lifecycle.

## Limits

- When creating the Sandbox, `fc.sandbox.network.vpc` must include `vpcId`, `securityGroupId`, and a non-empty `vSwitchIds`. VPC configuration in the template does not replace this metadata.
- The JuiceFS service address must be reachable from the VPC.
- The mount directory must be a normalized absolute Unix path. It cannot be `/`, and it cannot contain leading or trailing whitespace or `..`.
- We recommend using a subdirectory of `/home`, `/mnt`, `/tmp`, or `/data`, such as `/mnt/juicefs`, to avoid covering existing directories in the template.
- Mount directories in the same Sandbox cannot be duplicated.
- Do not print complete metadata, the JuiceFS token, or other credentials in logs.

## FAQ

### Sandbox creation reports incomplete VPC configuration

Confirm that `fc.sandbox.network.vpc` includes `vpcId`, `securityGroupId`, and a non-empty `vSwitchIds`. Each metadata value must be a JSON string produced by `json.dumps`.

### Sandbox creation times out or the mount fails

Check whether the MicroVM image contains the JuiceFS Enterprise client, the RADOS runtime library, and FUSE. Also check `BASE_URL`, VPC routes, the security group, the token, the file system name, and the remote directory. Keep the request ID for troubleshooting.

### Can `JUICEFS_ARGS_JSON` be empty?

Yes. This example converts an unset variable or empty string to `[]` and always sends an array in metadata. Do not send JSON `null`, and do not use this field to override `--token` or `--subdir`.

To explicitly specify a configuration directory, set `JUICEFS_ARGS_JSON` to `["--conf-dir", "/tmp/juicefs-config"]`. The path must be a normalized absolute subdirectory of `/tmp`. If you omit the option, the platform generates an isolated configuration directory.

### Which field specifies the JuiceFS service address?

Use `envs.BASE_URL` in `fc.sandbox.storage.juicefs`. This is the field for the direct metadata mount path. Do not use `baseURL` in this configuration.
