# Snapshots

> **Usage limits**
>
> Snapshot is currently available only to allowlisted accounts. Complete allowlist enablement before calling Snapshot APIs. Only the generation-2 runtime (`micro-sandbox`) is supported.

A Snapshot captures the filesystem and memory state of a running sandbox at a point in time. After creation, a Snapshot is independent of the source sandbox and source template: deleting the source sandbox or source template does not delete the Snapshot, and deleting the Snapshot does not delete the source sandbox or source template.

Typical use: install dependencies and prepare a workspace in a sandbox, create a Snapshot, and then launch sandboxes in the same state in seconds without rebuilding a template. Common scenarios include checkpointing long-running Agent tasks, warming environments for fast starts, and cloning sandboxes for parallel exploration.

Snapshots are retained for **7 days** from creation by default, and then expire automatically. After expiration they no longer appear in list results and cannot be used to create sandboxes. Snapshot retention is independent of the source sandbox lifetime: after the source sandbox is killed or reclaimed by timeout, an unexpired Snapshot remains usable.

Call Snapshot APIs through the E2B-compatible SDK. For authentication and connection parameters, see [Usage Constraints](../../01.Getting%20Started/06.Usage%20Constraints.md). Snapshot APIs (including list filtering by `name`) require Python `e2b>=2.33.0` and TypeScript `e2b>=2.34.0`.

## API overview

| Operation | JavaScript / TypeScript | Python |
| --- | --- | --- |
| Create | `sandbox.createSnapshot({ name? })` / `Sandbox.createSnapshot(sandboxId, { name? })` | `sandbox.create_snapshot(name=...)` / `Sandbox.create_snapshot(sandbox_id, name=...)` |
| List | `Sandbox.listSnapshots({ sandboxId?, name?, limit?, nextToken? })` | `Sandbox.list_snapshots(sandbox_id=..., name=..., limit=..., next_token=...)` |
| Create a sandbox from a Snapshot | `Sandbox.create(snapshotId \| "<TeamName>/<short-name>")` | `Sandbox.create(template=snapshot_id \| "<TeamName>/<short-name>")` |
| Delete | `Sandbox.deleteSnapshot(snapshotId \| qualifiedName)` | `Sandbox.delete_snapshot(snapshot_id \| qualified_name)` |

Instance and static methods have the same semantics. Instance list methods imply the current sandbox, so you do not need to pass `sandboxId` / `sandbox_id` again.

### Response fields

| Field | JavaScript | Python | Description |
| --- | --- | --- | --- |
| Snapshot ID | `snapshotId` | `snapshot_id` | UUID. Prefer this when creating, deleting, or restoring sandboxes from a Snapshot |
| Names | `names` | `names` | Named: `["<current Team name>/<short-name>:<tag>"]`; unnamed: `[]` |

Names and IDs are separate. The qualified name appears only in `names` and name-based resolution. It does not replace the Snapshot ID.

## Limits

- You can create a Snapshot only from a **running** sandbox. If the source sandbox is paused, already creating a Snapshot, or occupied by another operation, Snapshot creation fails.
- Only the generation-2 runtime (`micro-sandbox`) is supported.
- Named Snapshots require the current Team to have a name. Unnamed Teams can create only unnamed Snapshots.
- While creation is in progress, the source sandbox `state` is `snapshotting`, and you cannot delete that sandbox. After completion you can continue using the sandbox or create another Snapshot.
- Creation can take several minutes. Set the SDK **request timeout** to at least 300 seconds (`requestTimeoutMs: 300_000` in TypeScript; `request_timeout=300` in Python). `timeoutMs` / `timeout` control sandbox lifetime, not the Snapshot request timeout. The default request timeout is typically 60 seconds and may fail before Snapshot creation finishes.
- The source template must still exist when you create a Snapshot. After creation succeeds, you can still restore sandboxes from that Snapshot even if you later delete the source template.

## Create a Snapshot

`name` is optional. If omitted, the Snapshot is unnamed and can be addressed only by Snapshot ID afterward.

Within the same Team, only one available Snapshot can use a given `(short-name, tag)` at a time, regardless of the source template. Name conflicts fail the create call and do not overwrite an existing Snapshot. Different tags can coexist. After deletion, the name is released immediately.

```typescript
import { Sandbox } from "e2b";

const sandbox = await Sandbox.create("code-interpreter-v1", {
  apiKey: process.env.E2B_API_KEY,
  apiUrl: process.env.E2B_API_URL,
  domain: process.env.E2B_DOMAIN,
  timeoutMs: 300_000,
});

await sandbox.files.write("/app/state.json", '{"step": 1}');

const snapshot = await sandbox.createSnapshot({
  name: "deps-ready",
  requestTimeoutMs: 300_000,
});
// snapshot.snapshotId
// snapshot.names === ["demo-team/deps-ready:default"]

const another = await Sandbox.createSnapshot(sandbox.sandboxId, {
  apiKey: process.env.E2B_API_KEY,
  domain: process.env.E2B_DOMAIN,
  requestTimeoutMs: 300_000,
  name: "deps-ready:v1",
});
```

Python example:

```python
import os

from e2b import Sandbox

sandbox = Sandbox.create(
    template="code-interpreter-v1",
    api_key=os.environ["E2B_API_KEY"],
    api_url=os.environ["E2B_API_URL"],
    domain=os.environ["E2B_DOMAIN"],
    timeout=300,
)

sandbox.files.write("/app/state.json", '{"step": 1}')

snapshot = sandbox.create_snapshot(
    name="deps-ready",
    request_timeout=300,
)
# snapshot.snapshot_id
# snapshot.names == ["demo-team/deps-ready:default"]

another = Sandbox.create_snapshot(
    sandbox.sandbox_id,
    name="deps-ready:v1",
    api_key=os.environ["E2B_API_KEY"],
    api_url=os.environ["E2B_API_URL"],
    domain=os.environ["E2B_DOMAIN"],
    request_timeout=300,
)
```

You can create multiple Snapshots from the same sandbox.

### Naming rules

The qualified name is `<current Team name>/<short-name>:<tag>`.

- **Short name and tag**: `^[_a-zA-Z][-_a-zA-Z0-9]*$`, up to 64 characters. Must start with a letter or underscore.
- **Team name prefix**: same as the Team display name, up to 32 characters. May start with a digit and may include spaces, dots, underscores, and hyphens (for example a default Team numeric name or `My Team`).
- Segments must not contain `/` or `:`. Team names and template names also disallow `/`, so a string with exactly one `/` can only be a Snapshot qualified name and will not collide with a template name.

| `name` | Result |
| --- | --- |
| Omitted / empty | Unnamed. `names = []`; addressable only by Snapshot ID |
| `deps-ready` | `<current Team name>/deps-ready:default` |
| `deps-ready:v1` | `<current Team name>/deps-ready:v1` |
| `demo-team/deps-ready` | `demo-team/deps-ready:default`. The prefix must equal the current Team name (case-insensitive) |
| `demo-team/deps-ready:v1` | `demo-team/deps-ready:v1` |

When creating, restoring, or deleting by name, omitting the tag is equivalent to `default`.

## List Snapshots

Returns Snapshots for the current Team that are not deleted and not expired, newest first.

Immediately after a successful create, calling the list API may temporarily omit the new row because of index lag. Create and delete by Snapshot ID or qualified name are unaffected; use the `snapshotId` / `names` returned by create.

```typescript
const paginator = Sandbox.listSnapshots({
  apiKey: process.env.E2B_API_KEY,
  domain: process.env.E2B_DOMAIN,
});
const snapshots = [];
while (paginator.hasNext) {
  snapshots.push(...(await paginator.nextItems()));
}

Sandbox.listSnapshots({
  apiKey: process.env.E2B_API_KEY,
  domain: process.env.E2B_DOMAIN,
  sandboxId: sandbox.sandboxId,
});
Sandbox.listSnapshots({
  apiKey: process.env.E2B_API_KEY,
  domain: process.env.E2B_DOMAIN,
  name: "deps-ready",
});
```

Python example:

```python
paginator = Sandbox.list_snapshots(
    api_key=os.environ["E2B_API_KEY"],
    api_url=os.environ["E2B_API_URL"],
    domain=os.environ["E2B_DOMAIN"],
)
snapshots = []
while paginator.has_next:
    snapshots.extend(paginator.next_items())

Sandbox.list_snapshots(
    sandbox_id=sandbox.sandbox_id,
    api_key=os.environ["E2B_API_KEY"],
    api_url=os.environ["E2B_API_URL"],
    domain=os.environ["E2B_DOMAIN"],
)
Sandbox.list_snapshots(
    name="deps-ready",
    api_key=os.environ["E2B_API_KEY"],
    api_url=os.environ["E2B_API_URL"],
    domain=os.environ["E2B_DOMAIN"],
)
```

| Parameter | Description |
| --- | --- |
| `sandboxId` / `sandbox_id` | Filter by source sandbox |
| `name` | If parsable as a short name or qualified name, match by segments. Omitting the tag matches all tags for that name; `:v1` or a trailing `:` pins a tag. Otherwise perform a case-insensitive contains match on the qualified name. Requires Python `e2b>=2.33.0` and TypeScript `e2b>=2.34.0` |
| `limit` | Page size. Default 100, maximum 100 |
| `nextToken` / `next_token` | Pagination cursor |

Unnamed Snapshots have empty `names` and are not matched by a `name` filter. For TypeScript static calls, configure `E2B_API_URL` through the environment variable. Do not pass an unsupported `apiUrl` field to `listSnapshots`, `createSnapshot`, or `deleteSnapshot`.

## Create a sandbox from a Snapshot

The template argument of `Sandbox.create` can be a Snapshot ID or the qualified name of a named Snapshot. For the full create options, see [Create a Sandbox](02.Create%20a%20Sandbox.md).

```typescript
await Sandbox.create(snapshot.snapshotId, {
  apiKey: process.env.E2B_API_KEY,
  apiUrl: process.env.E2B_API_URL,
  domain: process.env.E2B_DOMAIN,
  timeoutMs: 300_000,
});

await Sandbox.create("demo-team/deps-ready", {
  apiKey: process.env.E2B_API_KEY,
  apiUrl: process.env.E2B_API_URL,
  domain: process.env.E2B_DOMAIN,
  timeoutMs: 300_000,
});
```

Python example:

```python
Sandbox.create(
    template=snapshot.snapshot_id,
    api_key=os.environ["E2B_API_KEY"],
    api_url=os.environ["E2B_API_URL"],
    domain=os.environ["E2B_DOMAIN"],
    timeout=300,
)

Sandbox.create(
    template="demo-team/deps-ready",
    api_key=os.environ["E2B_API_KEY"],
    api_url=os.environ["E2B_API_URL"],
    domain=os.environ["E2B_DOMAIN"],
    timeout=300,
)
```

Resolution rules:

1. `<Team name>/<short-name>` or `<Team name>/<short-name>:<tag>`: treated only as a Snapshot qualified name. If not found, the call fails and does not fall back to a template.
2. Contains `/` but the form is invalid: fails.
3. Contains no `/`: looks up a Snapshot only when the value is a UUID. Ordinary template names create from a template. If a Snapshot ID lookup misses, the value is then treated as a template name.

Allowed overrides: timeout, idle timeout, `secure`, `allowInternetAccess`, user metadata, `autoPause`, `autoResume`, network, and custom sandbox ID.

Not allowed (the create call fails if provided): environment variables, volume / filesystem mounts, function configuration, build / image, and `fc.`-prefixed system metadata.

A sandbox created from a Snapshot occupies that Snapshot. Deleting the Snapshot fails while it is occupied.

Expired or deleted Snapshots cannot create sandboxes. After you create a Snapshot, deleting the source template still allows restore from that Snapshot.

## Delete a Snapshot

Pass a single string: the Snapshot ID, or a qualified name from `names`. Deletion returns `true` on success and `false` if the Snapshot does not exist.

| Argument | Behavior |
| --- | --- |
| Snapshot ID (UUID) | Delete by ID |
| Qualified name (`demo-team/deps-ready` or `demo-team/deps-ready:default`) | Delete by qualified name |
| Short name (`deps-ready`, no `/`) | **Does not delete by Snapshot name**. Looks up by ID first; on miss, deletes a template by that name |
| Invalid qualified name (multiple `/`, empty segments, and so on) | Fails and does not fall back to template deletion |

```typescript
await Sandbox.deleteSnapshot(snapshot.snapshotId, {
  apiKey: process.env.E2B_API_KEY,
  domain: process.env.E2B_DOMAIN,
});
await Sandbox.deleteSnapshot(snapshot.names[0], {
  apiKey: process.env.E2B_API_KEY,
  domain: process.env.E2B_DOMAIN,
});
```

Python example:

```python
Sandbox.delete_snapshot(
    snapshot.snapshot_id,
    api_key=os.environ["E2B_API_KEY"],
    api_url=os.environ["E2B_API_URL"],
    domain=os.environ["E2B_DOMAIN"],
)
Sandbox.delete_snapshot(
    snapshot.names[0],
    api_key=os.environ["E2B_API_KEY"],
    api_url=os.environ["E2B_API_URL"],
    domain=os.environ["E2B_DOMAIN"],
)
```

- Deletion fails if the Snapshot is still occupied by a restored sandbox.
- Deleting a Snapshot does not delete the source template or source sandbox; deleting the source sandbox or source template does not delete the Snapshot.

When deleting by qualified name, use `names[0]` from create or list, or build the name with the current Team name. Do not pass only the short name.

## Source sandbox states

| `state` | Description |
| --- | --- |
| `snapshotting` | Snapshot creation in progress. Included in the default list. The sandbox cannot be deleted |
| `snapshot_failed` | Snapshot creation failed. Not included in the default list; filter by this state. The sandbox can be deleted |

After a failed create, the source sandbox can still be used or deleted.

## Common errors

| Condition | Result |
| --- | --- |
| Source sandbox does not exist or does not belong to the caller | Create fails |
| Runtime is not micro-sandbox | Create fails |
| Invalid name, or qualified-name prefix is not the current Team name | Create fails |
| Team has no name but `name` was provided | Create fails |
| Same short name and tag already exist | Create fails without overwrite |
| Source sandbox is paused, already creating a Snapshot, or occupied | Create fails |
| Restore overrides environment variables, mounts, or image | Create fails |
| Snapshot is occupied by a restored sandbox | Delete fails |
| Restore or delete by qualified name, but Snapshot is missing | Fails without falling back to a template |
| Create times out | Create fails, but the server may already have created the Snapshot. Increase `requestTimeoutMs` / `request_timeout` first. For named Snapshots, list by `name` or qualified name before retrying to avoid duplicates. For unnamed Snapshots, `name` filtering does not work; list by source `sandboxId` first. If the target Snapshot already exists, use its ID and do not retry unconditionally |

## Recommendations

- Prefer saving the Snapshot ID returned by create. For named Snapshots, also save `names[0]` for restore and delete by name.
- Use Snapshots when you need to relaunch the same workspace state within up to 7 days. For short pauses between tasks, prefer [Pause and Resume](06.Pause%20and%20Resume.md).
- Delete unused Snapshots promptly to avoid ongoing storage charges.
- After restoring from a Snapshot, still call `sandbox.kill()` when the task finishes to release sandbox resources.
