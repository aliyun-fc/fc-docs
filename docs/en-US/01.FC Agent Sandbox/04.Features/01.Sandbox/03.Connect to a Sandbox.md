# Connect to a Sandbox

Connecting to a Sandbox lets you reuse the same Sandbox across different processes, services, or functions. A typical pattern is that request A creates the Sandbox and returns `sandboxId`, then request B continues the task by reconnecting with `sandboxId`.

## Save the Sandbox ID

```typescript
import { Sandbox } from "e2b";

const sandbox = await Sandbox.create("code-interpreter-v1", {
  apiKey: process.env.E2B_API_KEY,
  apiUrl: process.env.E2B_API_URL,
  domain: process.env.E2B_DOMAIN,
});

console.log(sandbox.sandboxId);
```

Python example:

```python
import os

from e2b import Sandbox

sandbox = Sandbox.create(
    template="code-interpreter-v1",
    api_key=os.environ["E2B_API_KEY"],
    api_url=os.environ["E2B_API_URL"],
    domain=os.environ["E2B_DOMAIN"],
)

print(sandbox.sandbox_id)
```

## Connect to an existing sandbox

```typescript
const sandbox = await Sandbox.connect(process.env.SANDBOX_ID, {
  apiKey: process.env.E2B_API_KEY,
  apiUrl: process.env.E2B_API_URL,
  domain: process.env.E2B_DOMAIN,
});

const result = await sandbox.commands.run("pwd");
console.log(result.stdout.trim());
```

Python example:

```python
sandbox = Sandbox.connect(
    os.environ["SANDBOX_ID"],
    api_key=os.environ["E2B_API_KEY"],
    api_url=os.environ["E2B_API_URL"],
    domain=os.environ["E2B_DOMAIN"],
)

result = sandbox.commands.run("pwd")
print(result.stdout.strip())
```

If the target Sandbox is paused, `Sandbox.connect()` automatically resumes it before returning a usable Sandbox object. Pause and resume is currently available only to allowlisted accounts.

## Recommendations

- `sandboxId` is the key identifier for reconnecting to a Sandbox and should be stored by your business system.
- Reconnecting restores control-plane access and runtime access only; it does not automatically recover task state for your application.
- If you cannot confirm that the Sandbox is still usable, reconnect and call `sandbox.getInfo()` or run a lightweight command as a health check.

### `POST /sandboxes/{sandboxID}/connect`



[Official contract](https://docs.e2b.dev/api-reference/sandboxes/connect-to-sandbox)

**Endpoint:** `POST /sandboxes/{sandboxID}/connect`

Servers: `https://api.e2b.app`.

Security (upstream OpenAPI): `[{"ApiKeyAuth": []}]`. Scheme details are provided in the linked official contract.

#### Request parameters

| Name | Location | Type | Required | Constraints | Description |
|---|---|---|---|---|---|
| sandboxID | path | string | yes | — | — |

#### Request body

Required: **yes**.

##### application/json

| Field | Type / schema | Required | Constraints | Description |
|---|---|---|---|---|
| `timeout` | integer | yes | minimum=0; format="int32" | Timeout in seconds from the current time after which the sandbox should expire |
| `memory` | boolean | no | — | Defaults to true. When false and the sandbox is paused, resume from disk state only: the sandbox cold-boots fresh and any memory in the snapshot is ignored, never modified or deleted. Disk state has crash-recovery semantics — writes not flushed before the pause may be lost. A no-op for snapshots that contain no memory. Rejected with an error in environments where this capability is not enabled, never silently downgraded to a memory restore. |

#### Responses

| Status | Description | Content type | Schema |
|---|---|---|---|
| 200 | The sandbox was already running | application/json | Sandbox |
| 201 | The sandbox was resumed successfully | application/json | Sandbox |
| 400 | Bad request | application/json | Error |
| 401 | Authentication error | application/json | Error |
| 404 | Not found | application/json | Error |
| 409 | Conflict | application/json | Error |
| 500 | Server error | application/json | Error |
| 503 | Service unavailable | application/json | Error |
| 504 | Backend timeout | application/json | Error |

##### SandboxNetworkConfig

| Field | Type / schema | Required | Constraints | Description |
|---|---|---|---|---|
| `allowPublicTraffic` | boolean | no | default=true | Specify if the sandbox URLs should be accessible only with authentication. |
| `allowOut` | array of string | no | — | List of allowed destinations for egress traffic. Each entry can be a CIDR block (e.g. "8.8.8.8/32"), a bare IP address (e.g. "8.8.8.8"), or a domain name (e.g. "example.com", "*.example.com"). Allowed entries always take precedence over denied entries. |
| `denyOut` | array of string | no | — | List of denied CIDR blocks or IP addresses for egress traffic. Domain names are not supported for deny rules. |
| `egressProxy` | SandboxEgressProxyConfig | no | nullable=true | SOCKS5 proxy for sandbox egress. Outbound TCP is tunneled through the proxy after allow/deny filtering; the sandbox is unaware. Domain-matched flows use remote DNS (ATYP=domain). |
| `maskRequestHost` | string | no | — | Specify host mask which will be used for all sandbox requests |
| `rules` | object | no | — | Per-domain transform rules applied to matching outbound HTTPS requests. Keys may be exact DNS names (for example, "api.example.com") or a leading wildcard (for example, "*.example.com"), and are normalized to lowercase on write. Wildcards match subdomains at any depth but not the apex domain; a bare "*" is invalid. Exact rules take precedence, followed by the longest matching wildcard suffix, and matching rule sets are not merged. Broad wildcards such as "*.com" are allowed and may expose transformed credentials to every matching destination the sandbox contacts. Rules do not grant network access; configure allowOut separately to permit the destination.  |
