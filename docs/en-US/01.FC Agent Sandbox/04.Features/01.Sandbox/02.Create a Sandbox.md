# Create a Sandbox

Creating a Sandbox is the first step in using FC Agent Sandbox. After the Sandbox is ready, you can run commands, read and write files, execute code, or start temporary HTTP services.

## Create a Default Sandbox

```typescript
import { Sandbox } from "e2b";

const sandbox = await Sandbox.create("code-interpreter-v1", {
  apiKey: process.env.E2B_API_KEY,
  apiUrl: process.env.E2B_API_URL,
  domain: process.env.E2B_DOMAIN,
});

try {
  const result = await sandbox.commands.run("echo hello");
  console.log(result.stdout.trim());
} finally {
  await sandbox.kill();
}
```

Python example:

```python
import os

from e2b import Sandbox

sandbox = Sandbox.create(
    template="code-interpreter-v1",
    api_key=os.environ["E2B_API_KEY"],
    api_url=os.environ["E2B_API_URL"],
    domain=os.environ["E2B_DOMAIN"],
)

try:
    result = sandbox.commands.run("echo hello")
    print(result.stdout.strip())
finally:
    sandbox.kill()
```

## Specify a Template

When you need preinstalled dependencies or a fixed runtime environment, create the Sandbox from a template:

```typescript
const sandbox = await Sandbox.create("code-interpreter-v1", {
  apiKey: process.env.E2B_API_KEY,
  apiUrl: process.env.E2B_API_URL,
  domain: process.env.E2B_DOMAIN,
  timeoutMs: 10 * 60 * 1000,
});
```

In the Python SDK, pass the template name or template ID through the `template` parameter:

```python
sandbox = Sandbox.create(
    template="code-interpreter-v1",
    api_key=os.environ["E2B_API_KEY"],
    api_url=os.environ["E2B_API_URL"],
    domain=os.environ["E2B_DOMAIN"],
    timeout=10 * 60,
)
```

Common `Sandbox.create()` parameters include:

- `template` / first argument: Template name or template ID.
- `timeoutMs`: Sandbox timeout in milliseconds.
- `envs`: Environment variables injected into the Sandbox runtime.
- `metadata`: Custom metadata written to the Sandbox control plane.

## Recommendations

After creating the Sandbox, your application code should call `sandbox.kill()` in a `try/finally` block. If a task needs to preserve its current state for a short time, use [Pause and Resume](06.Pause%20and%20Resume.md). If you need to freeze runtime state and repeatedly launch new sandboxes from that state, use [Snapshots](12.Snapshots.md). Do not use pause or snapshots as a substitute for releasing resources when the task finishes.

## Create from a Snapshot

The template argument of `Sandbox.create` can also be a Snapshot ID or the qualified name of a named Snapshot (for example `demo-team/deps-ready`). For resolution rules, allowed overrides, and occupancy constraints, see [Snapshots](12.Snapshots.md).

## FC creation values

FC uses 300 seconds when `timeout` is omitted or zero, raises positive values below 60 seconds to 60, and rejects negative values with 400. The upstream HTTP default of 15 seconds below does not apply to FC. Python SDK creation defaults to 300 seconds; TypeScript uses milliseconds in `timeoutMs`. See [Timeouts](07.Timeouts.md).

FC defaults omitted `secure` to true. Explicit `secure:false` with `network.allowPublicTraffic:false`, or a non-null `egressProxy`, returns 400. The response may differ from upstream for tokens and domain fields; see the FC compatibility guidance.

### `POST /sandboxes`



[Official contract](https://docs.e2b.dev/api-reference/sandboxes/create-sandbox)

**Endpoint:** `POST /sandboxes`

Servers: `https://api.e2b.app`.

Security (upstream OpenAPI): `[{"ApiKeyAuth": []}]`. Scheme details are provided in the linked official contract.

#### Request body

Required: **yes**.

##### application/json

| Field | Type / schema | Required | Constraints | Description |
|---|---|---|---|---|
| `templateID` | string | yes | — | Identifier of the required template |
| `timeout` | integer | no | default=15; minimum=0; format="int32" | Time to live for the sandbox in seconds. |
| `autoPause` | boolean | no | default=false | Automatically pauses the sandbox after the timeout |
| `autoPauseMemory` | boolean | no | default=true | Controls the snapshot kind taken when the sandbox auto-pauses on timeout (only relevant when autoPause is true). When false, the auto-pause drops the in-memory state and persists only the filesystem (a filesystem-only snapshot); resuming it cold-boots (reboots) the sandbox from disk. Such a snapshot cannot be auto-resumed by traffic and must be resumed explicitly, so it cannot be combined with autoResume. Defaults to true (full memory snapshot). |
| `autoResume` | SandboxAutoResumeConfig | no | — | Auto-resume configuration for paused sandboxes. |
| `secure` | boolean | no | — | Secure all system communication with sandbox |
| `allow_internet_access` | boolean | no | — | Allow sandbox to access the internet. When set to false, it behaves the same as specifying denyOut to 0.0.0.0/0 in the network config. |
| `network` | SandboxNetworkConfig | no | — | — |
| `metadata` | SandboxMetadata | no | — | — |
| `envVars` | EnvVars | no | — | — |
| `mcp` | Mcp | no | nullable=true | MCP configuration for the sandbox |
| `iam` | SandboxIam | no | — | Sandbox workload identity configuration. A non-empty, valid tokens map enables workload identity for the sandbox. |
| `volumeMounts` | array of SandboxVolumeMount | no | — | — |

##### SandboxNetworkConfig

| Field | Type / schema | Required | Constraints | Description |
|---|---|---|---|---|
| `allowPublicTraffic` | boolean | no | default=true | Specify if the sandbox URLs should be accessible only with authentication. |
| `allowOut` | array of string | no | — | List of allowed destinations for egress traffic. Each entry can be a CIDR block (e.g. "8.8.8.8/32"), a bare IP address (e.g. "8.8.8.8"), or a domain name (e.g. "example.com", "*.example.com"). Allowed entries always take precedence over denied entries. |

| `egressProxy` | SandboxEgressProxyConfig | no | nullable=true | SOCKS5 proxy for sandbox egress. Outbound TCP is tunneled through the proxy after allow/deny filtering; the sandbox is unaware. Domain-matched flows use remote DNS (ATYP=domain). |
| `maskRequestHost` | string | no | — | Specify host mask which will be used for all sandbox requests |
| `rules` | object | no | — | Per-domain transform rules applied to matching outbound HTTPS requests. Keys may be exact DNS names (for example, "api.example.com") or a leading wildcard (for example, "*.example.com"), and are normalized to lowercase on write. Wildcards match subdomains at any depth but not the apex domain; a bare "*" is invalid. Exact rules take precedence, followed by the longest matching wildcard suffix, and matching rule sets are not merged. Broad wildcards such as "*.com" are allowed and may expose transformed credentials to every matching destination the sandbox contacts. Rules do not grant network access; configure allowOut separately to permit the destination.  |
