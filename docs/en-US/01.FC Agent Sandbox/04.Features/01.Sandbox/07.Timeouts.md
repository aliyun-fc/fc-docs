# Timeouts

You can set a timeout when creating a Sandbox, and you can adjust the timeout after the Sandbox has been created. A reasonable timeout helps prevent idle Sandboxes from occupying resources for too long.

## Configure at creation time

Python example:

```python
import os

sandbox = Sandbox.create(
    template="code-interpreter-v1",
    timeout=300,
    api_key=os.environ["E2B_API_KEY"],
    api_url=os.environ["E2B_API_URL"],
    domain=os.environ["E2B_DOMAIN"],
)
```

TypeScript example:

```typescript
const sandbox = await Sandbox.create("code-interpreter-v1", {
  timeoutMs: 300_000,
  apiKey: process.env.E2B_API_KEY,
  apiUrl: process.env.E2B_API_URL,
  domain: process.env.E2B_DOMAIN,
});
```

## Adjust After Creation

After creation, you can continue to adjust the timeout of the current Sandbox:

```python
sandbox.set_timeout(600)
```

You can also adjust the timeout of a specific Sandbox through the static method:

```python
Sandbox.set_timeout(sandbox_id, 600)
```

## Notes

- The Python SDK and TypeScript SDK use different timeout units. The Python examples typically use seconds, while the TypeScript examples use milliseconds.
- If the timeout is too short, tasks may end prematurely. If it is too long, resource usage and cost risk increase.
- Even with a timeout configured, you should still call `sandbox.kill()` explicitly when the task is complete.

## Lifetime differences

The E2B raw create API declares a 15-second default. The current Python SDK defaults to 300 seconds. FC creation also defaults to 300 seconds when timeout is omitted or zero. FC raises positive values below 60 seconds to 60 seconds. A zero or negative value for FC `set_timeout` is rejected with 400, unlike zero on create.

The FC gateway ceiling is 604800 seconds (7 days); subscription plans can impose lower limits. Connecting to a running sandbox only extends its existing deadline. Connecting to a paused sandbox resumes it and resets the lifetime window, subject to FC access restrictions. Setting the timeout measures the new interval from the current request, rather than adding it to the old deadline.

Command execution timeout, client request timeout and sandbox lifetime are separate settings.

### `POST /sandboxes/{sandboxID}/refreshes`



[Official contract](https://docs.e2b.dev/api-reference/sandboxes/refresh-sandbox)

**Endpoint:** `POST /sandboxes/{sandboxID}/refreshes`

Servers: `https://api.e2b.app`.

Security (upstream OpenAPI): `[{"ApiKeyAuth": []}]`. Scheme details are provided in the linked official contract.

#### Request parameters

| Name | Location | Type | Required | Constraints | Description |
|---|---|---|---|---|---|
| sandboxID | path | string | yes | — | — |

#### Request body

Required: **no**.

##### application/json

| Field | Type / schema | Required | Constraints | Description |
|---|---|---|---|---|
| `duration` | integer | no | minimum=0; maximum=3600 | Duration for which the sandbox should be kept alive in seconds |

#### Responses

| Status | Description | Content type | Schema |
|---|---|---|---|
| 204 | Successfully refreshed the sandbox | none declared | — |
| 401 | Authentication error | application/json | Error |
| 404 | Not found | application/json | Error |
| 500 | Server error | application/json | Error |

#### Data structures

##### SandboxRefreshRequest

| Field | Type / schema | Required | Constraints | Description |
|---|---|---|---|---|
| `duration` | integer | no | minimum=0; maximum=3600 | Duration for which the sandbox should be kept alive in seconds |

##### Error

| Field | Type / schema | Required | Constraints | Description |
|---|---|---|---|---|
| `code` | integer | yes | format="int32" | Error code |
| `error_code` | string | no | — | Machine-readable semantic error code. Not a closed set; initial values: sandbox_capacity_unavailable, sandbox_placement_timeout, sandbox_no_compatible_node, sandbox_create_failed, internal_server_error. |
| `message` | string | yes | — | Error |
