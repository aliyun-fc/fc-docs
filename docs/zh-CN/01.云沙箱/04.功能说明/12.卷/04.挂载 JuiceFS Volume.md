# 挂载 JuiceFS Volume

创建 Sandbox 时，可以通过 `volume_mounts` 将已有 JuiceFS Volume 挂载到指定目录。挂载后，Sandbox 可以通过文件路径访问 JuiceFS，数据不随 Sandbox 释放而删除。

如需直接在创建 Sandbox 时提交完整的 JuiceFS 配置，请参见[动态挂载 JuiceFS](../07.FC%20扩展/12.动态挂载%20JuiceFS.md)。

如需向运行中的 Sandbox 追加挂载，请参见[追加挂载沙箱存储](../07.FC%20扩展/09.追加挂载沙箱存储.md)。

## 前提条件

- 已为目标 Team [创建 JuiceFS Volume](../07.FC%20扩展/13.创建%20JuiceFS%20Volume.md)，并获取 Volume 名称。
- 已准备绑定同一 Team 的云沙箱 API Key。Volume 和 API Key 不能跨 Team 使用。
- 已准备与 JuiceFS 服务网络连通的 VPC、vSwitch 和安全组。
- 已准备云沙箱 API URL、Domain 和第二代运行时（MicroVM）自定义模板。

### 第二代运行时镜像要求

JuiceFS Volume 挂载必须使用[第二代运行时（MicroVM）](../02.模板/03.通过%20OpenAPI%20构建和管理模板.md)。构建自定义模板前，必须在源镜像中预装 JuiceFS 企业版客户端、RADOS 运行库和 FUSE 2。第二代运行时直接使用源镜像，不会在模板构建时注入 JuiceFS 客户端。

镜像构建、推送和验证方法参见[动态挂载 JuiceFS](../07.FC%20扩展/12.动态挂载%20JuiceFS.md)。镜像中不要包含 JuiceFS Token 或挂载配置。

## 安装 SDK

本文使用 Python E2B SDK 演示。`volume_mounts` 需要 E2B Python SDK 2.31.0 或以上版本。

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install "e2b>=2.31.0"
```

运行示例前设置以下环境变量：

```bash
export E2B_API_KEY="<your-e2b-api-key>"
export E2B_API_URL="https://api.<region>.e2b.fc.aliyuncs.com"
export E2B_DOMAIN="<region>.e2b.fc.aliyuncs.com"
export E2B_TEMPLATE="<microvm-template-id>"

export JUICEFS_SANDBOX_VOLUME_NAME="juicefs-workspace"
export FCSANDBOX_VPC_ID="vpc-xxxxxxxx"
export FCSANDBOX_SECURITY_GROUP_ID="sg-xxxxxxxx"
export FCSANDBOX_VSWITCH_ID="vsw-xxxxxxxx"
```

## 挂载并验证

以下示例将 JuiceFS Volume 挂载到 `/mnt/juicefs`，并验证文件写入、读取和删除。将代码保存为 `04_mount_juicefs_volume.py`：

```python
import json
import os

from e2b import Sandbox


def require_env(name: str) -> str:
    value = os.environ.get(name, "").strip()
    if not value:
        raise RuntimeError(f"缺少环境变量: {name}")
    return value


vpc_config = {
    "vpcId": require_env("FCSANDBOX_VPC_ID"),
    "securityGroupId": require_env("FCSANDBOX_SECURITY_GROUP_ID"),
    "vSwitchIds": [require_env("FCSANDBOX_VSWITCH_ID")],
}

mount_dir = "/mnt/juicefs"
marker_path = f"{mount_dir}/hello-juicefs.txt"
sandbox = None
marker_written = False

try:
    sandbox = Sandbox.create(
        template=require_env("E2B_TEMPLATE"),
        timeout=300,
        api_key=require_env("E2B_API_KEY"),
        api_url=require_env("E2B_API_URL"),
        domain=require_env("E2B_DOMAIN"),
        volume_mounts={
            mount_dir: require_env("JUICEFS_SANDBOX_VOLUME_NAME"),
        },
        metadata={
            "fc.sandbox.network.vpc": json.dumps(vpc_config),
        },
    )

    info = sandbox.get_info()
    print(f"volume_mounts={info.volume_mounts}")

    sandbox.files.write(marker_path, "hello juicefs\n")
    marker_written = True
    content = sandbox.files.read(marker_path)
    if content != "hello juicefs\n":
        raise RuntimeError(f"文件内容不一致: {content!r}")
finally:
    try:
        if sandbox is not None and marker_written:
            sandbox.files.remove(marker_path)
    finally:
        if sandbox is not None:
            sandbox.kill()

print("JuiceFS Volume 挂载读写验证成功")
```

运行示例：

```bash
python 04_mount_juicefs_volume.py
```

## 行为说明

- `volume_mounts` 使用 `{挂载目录: Volume 名称}` 格式，不使用 Volume ID，也不使用 JuiceFS 文件系统名称。
- Gateway 根据 Volume 名称读取创建 Volume 时保存的 `volumeName`、`baseURL`、`remoteDir`、`token` 和 `args`，再转换为 JuiceFS 挂载配置。
- 本文在创建 Sandbox 时通过 `fc.sandbox.network.vpc` 提供完整 VPC 配置。也可以在创建 JuiceFS Volume 时通过 `mountConfig.vpcConfig` 保存 VPC 配置；如果两处都提供，以创建 Sandbox 请求中的配置为准。
- Sandbox 暂停后再恢复时会恢复 Volume 挂载，JuiceFS 数据不依赖 Sandbox 生命周期。

## 使用限制

- 创建 Sandbox 时必须能够获得完整的 `vpcId`、`securityGroupId` 和非空 `vSwitchIds`。模板中的 VPC 配置不能替代该挂载配置。
- JuiceFS 服务地址必须能从该 VPC 访问。
- 挂载目录必须是规范化的绝对 Unix 路径，不能为 `/`，不能包含前后空格或 `..`。
- 建议使用 `/home`、`/mnt`、`/tmp` 或 `/data` 的子目录，例如 `/mnt/juicefs`，避免覆盖模板内已有目录。
- 同一个 Sandbox 中的挂载目录不能重复。
- 一个 Sandbox 最多挂载 5 个 JuiceFS 挂载点。追加挂载时，已有与新增 JuiceFS 挂载点累计不能超过 5 个。
- 同一次创建 Sandbox 或追加挂载请求中的多个 JuiceFS Volume 必须使用相同的 `baseURL`。
- 如果同时使用 named Volume 和 metadata 直接挂载 JuiceFS，二者的服务地址必须一致。

## 常见问题

### Volume 创建成功，但 Sandbox 创建超时或挂载失败

检查 MicroVM 镜像中是否包含 JuiceFS 企业版客户端、RADOS 运行库和 FUSE 2，并检查 VPC 路由、安全组、JuiceFS 服务地址、Token、文件系统名称和远端目录。`CreateVolume` 不执行网络探测或真实挂载。

### `volume_mounts` 中应该填写哪个名称

填写创建云沙箱 Volume 时指定的名称，即本文示例中的 `JUICEFS_SANDBOX_VOLUME_NAME`，不要填写 JuiceFS 文件系统名称或 Volume ID。
