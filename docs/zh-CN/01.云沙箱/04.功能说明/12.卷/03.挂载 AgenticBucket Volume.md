# 挂载 AgenticBucket Volume

创建 Sandbox 时，可以通过 `volume_mounts` 将已有 AgenticBucket Volume 挂载到指定目录。挂载后，Sandbox 可以通过文件路径访问 BucketSpace，数据不随 Sandbox 释放而删除。

## 前提条件

- 已为目标 Team [创建 AgenticBucket Volume](../07.FC%20扩展/10.创建%20AgenticBucket%20Volume.md)，并获取 Volume 名称。
- 已准备绑定同一 Team 的云沙箱 API Key。Volume 和 API Key 不能跨 Team 使用。
- 已准备函数执行 RAM Role。该 Role 具备目标 AgenticBucket 和 BucketSpace 的读写权限，且信任策略允许函数计算服务扮演。
- 使用自定义模板时，模板内需要包含可执行的 ossfs2。当前验证版本为 2.0.9。
- 已准备云沙箱 API URL、Domain 和可用模板。

无需关闭 AgenticBucket 的 `BlockPublicAccess`。Sandbox 通过执行 Role 获取短期凭证，不需要在 metadata 或用户代码中配置长期 AK/SK。

## 配置权限

请将以下权限策略授予函数执行 RAM Role，并按实际读写范围收敛 Resource：

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "oss:ListObjects",
        "oss:GetObject",
        "oss:PutObject",
        "oss:DeleteObject",
        "oss:AbortMultipartUpload",
        "oss:ListParts"
      ],
      "Resource": "*"
    }
  ]
}
```

## 安装 SDK

本文使用 Python E2B SDK 演示。`volume_mounts` 需要 E2B Python SDK 2.31.0 或以上版本。

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install "e2b>=2.31.0"
```

运行示例前设置以下环境变量：

```bash
export E2B_API_KEY="<your-e2b-api-key>"
export E2B_API_URL="https://api.<region>.e2b.fc.aliyuncs.com"
export E2B_DOMAIN="<region>.e2b.fc.aliyuncs.com"
export E2B_TEMPLATE="<template-id>"

export AGENTIC_BUCKET_VOLUME_NAME="<volume-name>"
export FCSANDBOX_ROLE_ARN="acs:ram::<account-id>:role/<execution-role>"
```

## 挂载并验证

以下示例将 AgenticBucket Volume 挂载到 `/mnt/agentic-bucket`，并验证文件读写。该示例要求 Volume 不是只读 Volume。将代码保存为 `03_mount_agentic_bucket_volume.py`：

```python
import os

from e2b import Sandbox


def require_env(name: str) -> str:
    value = os.environ.get(name, "").strip()
    if not value:
        raise RuntimeError(f"缺少环境变量: {name}")
    return value


mount_dir = "/mnt/agentic-bucket"
marker_path = f"{mount_dir}/hello-agentic-bucket.txt"
sandbox = None

try:
    sandbox = Sandbox.create(
        template=require_env("E2B_TEMPLATE"),
        timeout=300,
        api_key=require_env("E2B_API_KEY"),
        api_url=require_env("E2B_API_URL"),
        domain=require_env("E2B_DOMAIN"),
        volume_mounts={
            mount_dir: require_env("AGENTIC_BUCKET_VOLUME_NAME"),
        },
        metadata={
            "fc.sandbox.auth.role": require_env("FCSANDBOX_ROLE_ARN"),
        },
    )

    sandbox.files.write(marker_path, "hello agentic bucket\n")
    content = sandbox.files.read(marker_path)
    if content != "hello agentic bucket\n":
        raise RuntimeError(f"文件内容不一致: {content!r}")
finally:
    if sandbox is not None:
        sandbox.kill()

print("AgenticBucket Volume 挂载读写验证成功")
```

运行示例：

```bash
python 03_mount_agentic_bucket_volume.py
```

## 行为说明

- `volume_mounts` 使用 `{挂载目录: Volume 名称}` 格式，不使用 Volume ID。
- 创建 Sandbox 时，通过 `fc.sandbox.auth.role` 传入执行 Role；不需要在 Sandbox 中配置长期 AK/SK。
- Sandbox 暂停后再恢复时会恢复 Volume 挂载，BucketSpace 数据不依赖 Sandbox 生命周期。

## 使用限制

- 同地域访问建议使用 AgenticBucket 所在地域的 OSS 内网 Endpoint，不需要额外配置 VPC。
- 单次创建 Sandbox 请求中的普通 OSS 与 AgenticBucket 挂载点合计不能超过 5 个。
- 挂载目录必须是规范化的绝对 Unix 路径，不能为 `/`，不能包含前后空格或 `..`。
- 同一个 Sandbox 中的挂载目录不能重复。建议使用 `/mnt/agentic-bucket` 或其子目录，避免覆盖模板内已有目录。
- 只读 Volume 只能读取挂载路径内的文件。

## 常见问题

### 创建 Sandbox 提示 `requires executionRoleArn` 错误

检查 `fc.sandbox.auth.role` 是否为空，以及执行 Role 的信任策略是否允许函数计算服务扮演。

### Sandbox 创建时挂载失败

检查 Volume 与 API Key 是否属于同一 Team，AgenticBucket、BucketSpace 与 Endpoint 是否匹配，以及执行 Role 是否具备所需权限。保留 request ID 便于排查。

### Volume 已挂载但无法写入

检查 Volume 是否为只读、执行 Role 是否具备写入权限，以及 AgenticBucket 的访问控制是否拒绝当前访问。
