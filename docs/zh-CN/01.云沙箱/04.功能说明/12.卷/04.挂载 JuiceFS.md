# 挂载 JuiceFS

创建 Sandbox 时，可以通过 `fc.sandbox.storage.juicefs` metadata 将已有 JuiceFS 文件系统挂载到指定目录。挂载后，Sandbox 可以通过文件路径访问 JuiceFS，数据不随 Sandbox 释放而删除。

该方式直接传入 JuiceFS 挂载配置，不需要预先创建 FC Agent Sandbox Volume，也不使用 E2B SDK 的 `volume_mounts` 参数。

## 前提条件

- 已准备 JuiceFS 文件系统名称、访问 Token、服务地址和需要挂载的远端目录。
- 已准备与 JuiceFS 服务网络连通的 VPC、vSwitch 和安全组。如果服务配置了来源 IP 白名单，还需要放行该 VPC 的实际出口 IP。
- 已准备云沙箱 API Key、API URL、Domain 和第二代运行时（MicroVM）自定义模板。
- 已获取适用于 `linux/amd64` 的 JuiceFS Enterprise 客户端。

### 第二代运行时镜像要求

如果使用[第二代运行时（MicroVM）](../02.模板/03.通过%20OpenAPI%20构建和管理模板.md)的自定义模板，必须在构建模板前，在源镜像中预装 JuiceFS Enterprise 客户端和 FUSE。第二代运行时直接使用源镜像，不会在模板构建时注入 JuiceFS 客户端。

将获取的客户端保存为 Dockerfile 同目录下的 `juicefs-ee`。以下 Dockerfile 以 Ubuntu 22.04 为例：

```dockerfile
FROM ubuntu:22.04

ARG DEBIAN_FRONTEND=noninteractive
ARG JUICEFS_EE_SHA256

COPY juicefs-ee /usr/bin/juicefs

RUN set -eux; \
    test -n "${JUICEFS_EE_SHA256}"; \
    apt-get update; \
    apt-get install -y --no-install-recommends \
        ca-certificates \
        fuse; \
    echo "${JUICEFS_EE_SHA256}  /usr/bin/juicefs" | sha256sum -c -; \
    chmod 0755 /usr/bin/juicefs; \
    ln -sf /usr/bin/juicefs /usr/bin/juicefs-ee; \
    command -v juicefs; \
    command -v juicefs-ee; \
    command -v fusermount; \
    mkdir -p /mnt/juicefs; \
    rm -rf /var/lib/apt/lists/*

WORKDIR /root

# 不设置 USER、ENTRYPOINT 或 CMD，由 MicroVM 管控链路接管。
```

不要将 JuiceFS Token 或挂载配置写入 Dockerfile 或镜像层。替换客户端文件时，必须重新计算并传入 SHA-256，不要跳过完整性校验。

为兼容第二代运行时的镜像拉取链路，以下命令构建并推送单架构的 Docker schema 2 镜像。将占位符替换为实际值：

```bash
docker buildx build \
  --platform linux/amd64 \
  --build-arg JUICEFS_EE_SHA256="<juicefs-ee-sha256>" \
  --provenance=false \
  --output "type=image,name=<registry>/<namespace>/microsandbox-juicefs-ee:<version>,push=true,oci-mediatypes=false" \
  .
```

构建完成后，验证镜像 manifest 和客户端文件：

```bash
docker buildx imagetools inspect \
  --raw <registry>/<namespace>/microsandbox-juicefs-ee:<version> \
  | jq -e '.mediaType == "application/vnd.docker.distribution.manifest.v2+json"'

docker run --rm --platform linux/amd64 \
  <registry>/<namespace>/microsandbox-juicefs-ee:<version> \
  sh -euxc '
    command -v juicefs
    command -v juicefs-ee
    command -v fusermount
    test -d /mnt/juicefs
  '
```

以上命令全部成功，表示镜像格式和客户端文件符合要求，但不代表 VPC、Token、服务白名单或真实挂载链路已经可用。请使用该镜像重新构建 MicroVM 模板，再运行后续示例。

## 安装 SDK

本文使用 Python E2B SDK 演示：

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install "e2b>=2.31.0"
```

运行示例前设置以下环境变量：

```bash
export E2B_API_KEY="<your-e2b-api-key>"
export E2B_API_URL="https://api.<region>.e2b.fc.aliyuncs.com"
export E2B_DOMAIN="<region>.e2b.fc.aliyuncs.com"
export E2B_TEMPLATE="<microvm-template-id>"

export FCSANDBOX_VPC_ID="vpc-xxxxxxxx"
export FCSANDBOX_SECURITY_GROUP_ID="sg-xxxxxxxx"
export FCSANDBOX_VSWITCH_ID="vsw-xxxxxxxx"

export JUICEFS_BASE_URL="http://<juicefs-service-address>:<port>"
export JUICEFS_VOLUME_NAME="<juicefs-volume-name>"
export JUICEFS_TOKEN="<juicefs-token>"
export JUICEFS_REMOTE_DIR="/"
export JUICEFS_MOUNT_DIR="/mnt/juicefs"
export JUICEFS_ARGS_JSON='["--cache-size=0"]'
```

`JUICEFS_ARGS_JSON` 可选。未设置或设置为空字符串时，示例会按空数组 `[]` 处理。

## 挂载并验证

以下示例通过 metadata 将 JuiceFS 挂载到 `JUICEFS_MOUNT_DIR`，并验证文件读写。将代码保存为 `04_mount_juicefs.py`：

```python
import json
import os

from e2b import Sandbox


def require_env(name: str) -> str:
    value = os.environ.get(name, "").strip()
    if not value:
        raise RuntimeError(f"缺少环境变量: {name}")
    return value


def optional_env(name: str, default: str) -> str:
    return os.environ.get(name, "").strip() or default


def juicefs_args() -> list[str]:
    value = json.loads(os.environ.get("JUICEFS_ARGS_JSON", "").strip() or "[]")
    if not isinstance(value, list) or not all(isinstance(item, str) for item in value):
        raise RuntimeError("JUICEFS_ARGS_JSON 必须是字符串数组")

    managed_options = ("--token", "--subdir", "--conf-dir")
    for item in value:
        if any(item == option or item.startswith(f"{option}=") for option in managed_options):
            raise RuntimeError(f"JUICEFS_ARGS_JSON 不能覆盖平台托管参数: {item}")
    return value


mount_dir = optional_env("JUICEFS_MOUNT_DIR", "/mnt/juicefs")
marker_path = f"{mount_dir}/hello-juicefs.txt"

vpc_config = {
    "vpcId": require_env("FCSANDBOX_VPC_ID"),
    "securityGroupId": require_env("FCSANDBOX_SECURITY_GROUP_ID"),
    "vSwitchIds": [require_env("FCSANDBOX_VSWITCH_ID")],
}

juicefs_config = {
    "mountPoints": [
        {
            "volumeName": require_env("JUICEFS_VOLUME_NAME"),
            "remoteDir": optional_env("JUICEFS_REMOTE_DIR", "/"),
            "mountDir": mount_dir,
            "token": require_env("JUICEFS_TOKEN"),
            "args": juicefs_args(),
        }
    ],
    "envs": {
        "BASE_URL": require_env("JUICEFS_BASE_URL"),
        "GOGC": "50",
    },
}

sandbox = None
marker_written = False

try:
    sandbox = Sandbox.create(
        template=require_env("E2B_TEMPLATE"),
        timeout=300,
        api_key=require_env("E2B_API_KEY"),
        api_url=require_env("E2B_API_URL"),
        domain=require_env("E2B_DOMAIN"),
        metadata={
            "fc.sandbox.network.vpc": json.dumps(vpc_config),
            "fc.sandbox.storage.juicefs": json.dumps(juicefs_config),
        },
    )

    sandbox.files.write(marker_path, "hello juicefs\n")
    marker_written = True
    content = sandbox.files.read(marker_path)
    if content != "hello juicefs\n":
        raise RuntimeError(f"文件内容不一致: {content!r}")
finally:
    try:
        if sandbox is not None and marker_written:
            sandbox.files.remove(marker_path)
    finally:
        if sandbox is not None:
            sandbox.kill()

print("JuiceFS 挂载读写验证成功")
```

运行示例：

```bash
python 04_mount_juicefs.py
```

## 行为说明

- `fc.sandbox.storage.juicefs` 和 `fc.sandbox.network.vpc` 的 metadata 值必须是 JSON 字符串，不能直接传入 Python 字典。
- `mountDir` 是 Sandbox 内的本地挂载目录，`remoteDir` 是 JuiceFS 文件系统中的远端目录。
- metadata 链路使用 `envs.BASE_URL` 指定 JuiceFS 服务地址。字段名区分大小写，不要写成 `baseURL`。
- `args` 是传递给 JuiceFS 客户端的额外挂载参数，可以是空数组。平台会根据运行时信息生成独立的配置目录，不需要在 `args` 中传入 `--conf-dir`。
- Sandbox 暂停后再恢复时会恢复 JuiceFS 挂载，JuiceFS 数据不依赖 Sandbox 生命周期。

## 使用限制

- 创建 Sandbox 时，`fc.sandbox.network.vpc` 必须包含 `vpcId`、`securityGroupId` 和非空的 `vSwitchIds`。模板中的 VPC 配置不能替代该 metadata。
- JuiceFS 服务地址必须能从该 VPC 访问。配置来源 IP 白名单时，应以 Sandbox 经 VPC/NAT 访问服务时的实际出口 IP 为准。
- 挂载目录必须是规范化的绝对 Unix 路径，不能为 `/`，不能包含前后空格或 `..`。
- 建议使用 `/home`、`/mnt`、`/tmp` 或 `/data` 的子目录，例如 `/mnt/juicefs`，避免覆盖模板内已有目录。
- 同一个 Sandbox 中的挂载目录不能重复。
- 不要在日志中打印完整 metadata、JuiceFS Token 或其他凭证。

## 常见问题

### 创建 Sandbox 提示 VPC 配置不完整

确认 `fc.sandbox.network.vpc` 包含 `vpcId`、`securityGroupId` 和非空的 `vSwitchIds`。metadata 中的值必须是 `json.dumps` 生成的 JSON 字符串。

### Sandbox 创建超时或挂载失败

检查 MicroVM 镜像中是否包含 JuiceFS Enterprise 客户端和 FUSE，并检查 `BASE_URL`、VPC 路由、安全组、NAT 出口、服务白名单、Token、文件系统名称和远端目录。保留 request ID 便于排查。

### `JUICEFS_ARGS_JSON` 可以为空吗

可以。本文示例将未设置或空字符串转换为 `[]`，并在 metadata 中始终传入数组。不要传入 JSON `null`，也不要通过该字段覆盖 `--token`、`--subdir` 或 `--conf-dir`。

### JuiceFS 服务地址应该使用哪个字段

使用 `fc.sandbox.storage.juicefs` 中的 `envs.BASE_URL`。这是 metadata 直挂链路的字段；不要在该配置中使用 `baseURL`。
