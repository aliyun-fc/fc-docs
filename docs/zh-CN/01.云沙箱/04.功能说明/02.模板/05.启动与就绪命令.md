# 启动与就绪命令

启动命令（start command）和就绪命令（ready command）是模板构建期的两个命令，用于把 Web 服务等常驻进程固化到模板中：

1. 构建模板时，平台把启动命令写入沙箱内的 `/tmp/start.sh` 并在后台执行，同时每 2 秒执行一次就绪命令，直到就绪命令退出码为 0，判定服务就绪。两条命令并发执行，没有严格的先后依赖。
2. 服务就绪后，平台对仍在运行的沙箱制作模板快照。基于该模板创建的沙箱在创建时服务已在运行，创建即可访问，不会再次执行启动命令。

如果进程不需要固化到模板，例如每次创建沙箱后要运行的任务都不同，可以不使用模板命令，改为在创建沙箱后运行后台命令，参见下文「在沙箱中运行后台命令」。

## 使用限制

- 仅第二代运行时的模板支持启动命令和就绪命令；第一代模板设置任一命令都会返回 400。
- 就绪命令退出码为 0 一次即判定就绪：执行间隔固定 2 秒，成功阈值 1 次、没有失败阈值，失败后会一直重试；等待就绪有 5 分钟硬超时，超时会导致模板构建失败。探测间隔和超时都不可配置。
- 启动命令的退出码不参与就绪判定，提前退出（含非零退出码）不会直接判定失败。如果服务因此没起来，就绪命令会持续失败，最终表现为 5 分钟后超时，失败原因可能落在启动命令或就绪超时上。
- 就绪判定只看退出码，stdout 不回传；最后一次失败尝试的 stderr 会写进构建失败原因，可以在就绪命令里用 `exec 1>&2` 打印诊断信息。

## 执行用户与环境

以下说明适用于 `os_type=linux-amd64` 的沙箱。启动命令和就绪命令由平台在构建期的沙箱内执行，执行身份由模板默认值决定，与镜像声明的 `USER` 无关：

- **执行身份**：模板的默认用户，默认 `user`；在 `steps` 里声明了 `USER`，则为最后一条 `USER` 指定的账号。默认不是 root，也不跟随镜像 `USER`；显式声明 `USER root` 时以 root 执行。不确定时先在命令里跑一次 `id`。
- **sudo 的前提**：需要 root 权限时在命令前加 `sudo`，例如 `sudo -E <command>`；`-E` 用于保留环境变量。免密 sudo 由镜像提供，平台不会在运行期写入：官方基础镜像已包含 `/etc/sudoers.d/user`（`user ALL=(ALL) NOPASSWD:ALL`）；自定义镜像需要自己安装 `sudo` 并添加同样的配置，否则会得到 `sudo: command not found` 或要求输入密码。
- **工作目录**：启动命令物化为 `/tmp/start.sh`（首行 `#!/bin/bash -l`）后执行。命令里请使用绝对路径，不要依赖相对路径；需要固定工作目录时在 `steps` 里声明 `WORKDIR`。
- **UID 分配**：`user` 的 UID/GID 优先取 1000；如果 1000 已被镜像中的其他账号占用（例如 `ubuntu:24.04` 的 `ubuntu`、`node` 镜像的 `node`），平台会顺延使用下一个可用 ID（通常是 1001），沙箱仍会正常启动。请按用户名 `user` 判断身份，不要把 UID 写死。
- **文件属主**：平台会为默认主目录（默认 `/home/user`）准备属主，该目录及其内容归默认用户所有，保证默认可写；镜像中其他路径的属主不变，所以由镜像自带账号或 root 拥有的 `/srv/app` 这类目录，`user` 仍可能写不进去。这类路径需要提前在镜像里调整属主，或在命令中使用 `sudo`。
- **systemd 相关**：`systemctl` 必须以 root 身份调用，未加 `sudo` 会报 `Failed to connect to system scope bus`。镜像的 OCI `ENV` 只进入 envd 及其派生的命令进程（`commands.run`、启动命令、就绪命令），不会进入 systemd 及其拉起的服务；需要在镜像中增加 systemd drop-in 并通过 `EnvironmentFile=` 固化变量，或在启动命令中执行 `sudo -E systemctl import-environment <VAR1> <VAR2>` 后重启服务。
- **镜像入口命令**：第二代沙箱以 systemd 作为 PID 1，镜像的 `ENTRYPOINT`/`CMD` 不会执行。常驻服务需要由 systemd 单元或启动命令拉起。
- **可写路径**：使用默认用户可写的位置，例如 `$HOME`、`/tmp`（默认 `$HOME=/home/user`）。不要假设 `/root`、`/var` 或镜像中其他账号的家目录可写。
- **不需要自己后台化**：平台已经在后台执行启动命令，`python3 -m http.server 8000` 这类前台常驻进程就是推荐写法，不需要额外加 `nohup` 或 `&`。
- **构建期副作用**：构建期对文件系统和 systemd 状态的修改都会进入模板快照，包括 `/tmp`、`$HOME` 下的文件以及 `systemctl disable` 的结果。不要把调试日志、临时文件或密钥留在里面。

常见故障的排查步骤参见[第一代可以运行、第二代无法运行](03.通过%20OpenAPI%20构建和管理模板.md#first-gen-works-second-gen-fails)。

## 使用示例

通过 OpenAPI（POP SDK）创建第二代模板并设置启动命令和就绪命令，构建就绪后用 E2B SDK 创建沙箱。TypeScript、Go、Java 的传参方式参见[通过 OpenAPI 构建和管理模板](03.通过%20OpenAPI%20构建和管理模板.md)的「使用第二代运行时」一节。

Python 完整示例（构建一个预置 HTTP 服务的模板，等待 8000 端口就绪后创建沙箱访问）：

```python
import os
import time

from alibabacloud_fcsandbox20260509 import models
from alibabacloud_fcsandbox20260509.client import Client as FCSandboxClient
from alibabacloud_tea_openapi import models as open_api_models
from e2b import Sandbox

REGION = "cn-hangzhou"
TEAM_ID = "<your-team-id>"  # 参见「通过 OpenAPI 构建和管理模板」的前提条件。

config = open_api_models.Config(
    access_key_id=os.environ["ALIBABA_CLOUD_ACCESS_KEY_ID"],
    access_key_secret=os.environ["ALIBABA_CLOUD_ACCESS_KEY_SECRET"],
    region_id=REGION,
    endpoint=f"fcsandbox.{REGION}.aliyuncs.com",
)
pop_client = FCSandboxClient(config)

# 1. 创建第二代模板并提交构建，把 HTTP 服务固化到模板。
resp = pop_client.create_template(
    models.CreateTemplateRequest(
        body=models.CreateTemplateInput(
            name=f"my-service-{int(time.time())}",
            team_id=TEAM_ID,
            runtime_config=models.CreateTemplateRuntimeConfig(
                cpu=2,
                memory_size=2048,
                disk_size=15360,
                sandbox_config=models.CreateTemplateSandboxConfig(
                    image=f"fc-e2b-registry.{REGION}.cr.aliyuncs.com/runtime/base:v0.0.52",
                    # 启动命令和就绪命令仅第二代运行时支持。
                    generation=2,
                    # 启动命令在构建期以后台进程执行。
                    start_command="python3 -m http.server 8000",
                    # 就绪命令反复执行，退出码为 0 一次即判定就绪。
                    ready_command="curl -sf http://localhost:8000/ > /dev/null",
                ),
            ),
        )
    )
)
template_id = resp.body.template_id

# 2. 轮询构建状态直到就绪。
deadline = time.time() + 900
while True:
    got = pop_client.get_template(template_id, models.GetTemplateRequest(team_id=TEAM_ID))
    state = got.body.status.state
    if state == "ready":
        break
    if state == "error":
        raise SystemExit(f"构建失败: {got.body.status.reason.message}")
    if time.time() > deadline:
        raise SystemExit("构建超时")
    time.sleep(10)

# 3. 模板快照已包含运行中的服务，创建沙箱后即可直接访问。
sandbox = Sandbox.create(
    template=template_id,
    timeout=600,
    # SDK 自动读取 E2B_API_KEY / E2B_API_URL / E2B_DOMAIN 环境变量，
    # 也可以按 region 显式传入 api_url 和 domain。
    api_url=f"https://api.{REGION}.e2b.fc.aliyuncs.com",
    domain=f"{REGION}.e2b.fc.aliyuncs.com",
)
try:
    host = sandbox.get_host(8000)
    print(f"https://{host}")
finally:
    sandbox.kill()
```

不再使用的模板请及时删除释放资源：`pop_client.delete_template(template_id, models.DeleteTemplateRequest(team_id=TEAM_ID))`。

## 在沙箱中运行后台命令

不需要固化到模板的常驻进程，可以在创建沙箱后通过后台命令启动。

Python 示例：

```python
server = sandbox.commands.run(
    "python3 -m http.server 8000",
    background=True,
)

host = sandbox.get_host(8000)
print(f"https://{host}")
```

TypeScript 示例：

```typescript
const server = await sandbox.commands.run("python3 -m http.server 8000", {
  background: true,
});

const host = sandbox.getHost(8000);
console.log(`https://${host}`);
```
