# 用户与工作目录

模板中的用户和工作目录会影响命令执行、文件权限和依赖安装位置。Agent 场景中，建议保持工作目录稳定，避免每次执行命令都依赖隐式路径。

## 查看当前用户和目录

```typescript
const result = await sandbox.commands.run("whoami && pwd");
console.log(result.stdout);
```

Python 示例：

```python
result = sandbox.commands.run("whoami && pwd")
print(result.stdout)
```

## 指定命令工作目录

```typescript
await sandbox.files.makeDir("/tmp/project");
await sandbox.files.write("/tmp/project/main.py", "print('hello')\n");

const result = await sandbox.commands.run("python3 main.py", {
  cwd: "/tmp/project",
});

console.log(result.stdout.trim());
```

Python 示例：

```python
sandbox.files.make_dir("/tmp/project")
sandbox.files.write("/tmp/project/main.py", "print('hello')\n")

result = sandbox.commands.run(
    "python3 main.py",
    cwd="/tmp/project",
)

print(result.stdout.strip())
```

## 默认用户与 UID

模板的默认用户是 `user`，默认工作目录是 `/home/user`（也可以在模板的 `steps` 里指定，见下节「自定义默认用户与工作目录」）。平台在沙箱启动时确保该账号存在：

- UID/GID 优先取 1000。如果镜像中 1000 已被其他账号占用（例如 `ubuntu:24.04` 的 `ubuntu`、`node` 镜像的 `node`），平台会顺延使用 1001、1002 等下一个可用 UID，不会因此拒绝启动。
- 镜像中已有 `user` 账号时，平台直接使用该账号及其 UID，并保留已有账号和家目录的属主。
- `commands.run`、启动命令和就绪命令默认都以 `user` 执行。实际 UID 可以在沙箱内用 `sandbox.commands.run("id")` 查看。
- `commands.run` 的 `cwd`、`user` 参数可以按次覆盖模板默认值；不传时使用模板默认用户和工作目录。启动命令和就绪命令不能按次覆盖，始终使用模板默认值。
- 如果 UID 1000 被镜像中的业务账号占用并拥有应用文件，而应用以 `user` 运行，`user` 可能没有这些文件的写权限。需要在 Dockerfile 中提前调整属主，或在命令中使用 `sudo`。
- 不要把 UID 1000 写死在 `chown`、sudoers、配置文件或路径中。判断身份时使用用户名 `user`，需要可写目录时使用 `$HOME` 或 `/home/user`。
- 镜像的 `/etc/passwd`、`/etc/group` 必须是标准文件且可写，否则平台无法创建或校正默认用户，沙箱启动失败。

## 自定义默认用户与工作目录

第二代模板可以在 `runtimeConfig.sandboxConfig.steps` 里声明 `USER` 和 `WORKDIR`，构建期创建账号并设置目录，沙箱启动后 `commands.run`、启动命令和就绪命令都会以该用户、在该目录执行：

```json
{
  "runtimeConfig": {
    "sandboxConfig": {
      "image": "registry-vpc.cn-shanghai.aliyuncs.com/example/app:v1",
      "steps": [
        {"type": "USER", "args": ["app"]},
        {"type": "WORKDIR", "args": ["/home/app"]}
      ]
    }
  }
}
```

- `USER` 的 `args[0]` 是账号名；账号不存在时构建期创建，并将其家目录作为该用户的主目录。
- `WORKDIR` 的 `args[0]` 是工作目录；目录不存在时构建期创建，属主为该用户。
- 未声明 `USER`/`WORKDIR` 时回落 `user` / `/home/user`。
- 镜像的 OCI `USER`（Dockerfile 里 `USER` 的产物）不参与默认身份判定，**不生效**，迁移镜像时请显式写 `USER` step。
- 只有第二代（micro）支持构建期 `steps`；第一代传入 `steps` 会返回 400。`COPY` 暂不支持。

## 使用建议

- 模板构建时固定常用工具和依赖。
- 任务运行时使用明确的 `cwd`。
- 不要假设所有镜像都有相同默认用户、HOME 目录和权限。
- 不要假设默认用户的 UID 一定是 1000；需要固定 UID 时在镜像中自带 `user` 账号。
