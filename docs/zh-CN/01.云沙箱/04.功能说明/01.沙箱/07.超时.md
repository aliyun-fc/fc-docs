# 超时

可以在创建 Sandbox 时设置超时时间，也可以在 Sandbox 创建后调整超时时间。合理设置超时可以避免 Sandbox 长时间空闲占用资源。

## 创建时配置

Python 示例：

```python
import os

sandbox = Sandbox.create(
    template="code-interpreter-v1",
    timeout=300,
    api_key=os.environ["E2B_API_KEY"],
    api_url=os.environ["E2B_API_URL"],
    domain=os.environ["E2B_DOMAIN"],
)
```

TypeScript 示例：

```typescript
const sandbox = await Sandbox.create("code-interpreter-v1", {
  timeoutMs: 300_000,
  apiKey: process.env.E2B_API_KEY,
  apiUrl: process.env.E2B_API_URL,
  domain: process.env.E2B_DOMAIN,
});
```

## 创建后调整

创建后可以继续调整当前 Sandbox 的超时时间：

```python
sandbox.set_timeout(600)
```

也可以通过静态方法调整指定 Sandbox：

```python
Sandbox.set_timeout(sandbox_id, 600)
```

## 注意事项

- Python SDK 和 TypeScript SDK 的超时参数单位不同。Python 示例中通常使用秒，TypeScript 示例中使用毫秒。
- 超时时间过短可能导致任务提前结束；超时时间过长会增加资源占用和费用风险。
- 任务完成后仍应主动调用 `sandbox.kill()`。

## timeout：单位、默认值和边界

| 调用层或操作 | 默认值或行为 |
| --- | --- |
| E2B 原始 `POST /sandboxes` | OpenAPI 默认 `timeout=15` 秒 |
| 当前官方 Python SDK 创建 | `timeout` 单位为秒，默认 300 秒；TS 对应 `timeoutMs` 毫秒 |
| FC 创建时省略 `timeout` 或传 `0` | 使用 300 秒 |
| FC 创建时传 `1`—`59` 秒 | 提升至 60 秒 |
| FC 创建时传负数 | 返回 400 |
| FC `set_timeout` 传 `0` 或负数 | 返回 400；与创建时 `0` 的行为不同 |
| FC `set_timeout` 传 `1`—`59` 秒 | 提升至 60 秒 |
| FC 超时上限 | 网关上限 604800 秒（7天）；订阅计划可能有更低上限，不表示所有计划均可运行7天 |
| 连接运行中的沙箱 | 仅延长当前到期时间，不缩短已有较长 TTL |
| 连接暂停的沙箱 | 显式恢复后重设 TTL 窗口；需满足 FC 开放条件 |
| 创建后设置超时 | 从本次请求时刻重新计算到期时间；不是在旧到期时间上累加 |

命令执行超时只针对命令，请求等待超时只针对客户端等待；这两者都不能替代沙箱生存时间。FC 上限和计划限制见[使用约束](../../01.%E5%BC%80%E5%A7%8B%E4%BD%BF%E7%94%A8/06.%E4%BD%BF%E7%94%A8%E7%BA%A6%E6%9D%9F.md)。

以下按 E2B 官方 OpenAPI 补充本页涉及的协议字段，核对日期为 2026-09-08。参数表中的必填约束作用于所属对象；可选对象内部仍可有必填字段。字段描述保留官方英文，避免改写协议含义。FC 的支持范围及差异以本页正文和[兼容清单](../../07.%E5%BC%80%E5%8F%91%E5%8F%82%E8%80%83/01.E2B%20SDK%20%E5%85%BC%E5%AE%B9%20API%20%E6%B8%85%E5%8D%95.md)为准，表中的上游默认值、状态码和新增字段不能直接视为 FC 行为。

### `POST /sandboxes/{sandboxID}/refreshes`



[官方协议来源](https://docs.e2b.dev/api-reference/sandboxes/refresh-sandbox)

**Endpoint:** `POST /sandboxes/{sandboxID}/refreshes`

Servers: `https://api.e2b.app`.

Security (upstream OpenAPI): `[{"ApiKeyAuth": []}]`. Scheme details are provided in the linked official contract.

#### 请求参数

| Name | Location | Type | Required | Constraints | Description |
|---|---|---|---|---|---|
| sandboxID | path | string | yes | — | — |

#### 请求体

Required: **no**.

##### application/json

| 字段 | 类型 / 结构 | 必填 | 约束 | 说明 |
|---|---|---|---|---|
| `duration` | integer | no | minimum=0; maximum=3600 | Duration for which the sandbox should be kept alive in seconds |

#### 响应

| 状态码 | 说明 | 内容类型 | 结构 |
|---|---|---|---|
| 204 | Successfully refreshed the sandbox | none declared | — |
| 401 | Authentication error | application/json | Error |
| 404 | Not found | application/json | Error |
| 500 | Server error | application/json | Error |

#### 数据结构

##### SandboxRefreshRequest

| 字段 | 类型 / 结构 | 必填 | 约束 | 说明 |
|---|---|---|---|---|
| `duration` | integer | no | minimum=0; maximum=3600 | Duration for which the sandbox should be kept alive in seconds |

##### Error

| 字段 | 类型 / 结构 | 必填 | 约束 | 说明 |
|---|---|---|---|---|
| `code` | integer | yes | format="int32" | Error code |
| `error_code` | string | no | — | Machine-readable semantic error code. Not a closed set; initial values: sandbox_capacity_unavailable, sandbox_placement_timeout, sandbox_no_compatible_node, sandbox_create_failed, internal_server_error. |
| `message` | string | yes | — | Error |
