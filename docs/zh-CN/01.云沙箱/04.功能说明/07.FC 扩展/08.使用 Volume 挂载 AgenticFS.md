# 使用 Volume 挂载 AgenticFS

AgenticFS Volume 用于把已有的 AgenticFS Access Point 挂载到 Sandbox 内。挂载后，Sandbox 可以通过普通文件路径读写
AgenticFS，数据不随 Sandbox 释放而删除，适合保存 Agent 工作区、模型产物和需要跨 Sandbox 复用的文件。

使用过程分为两个阶段：

1. 使用阿里云 FCSandbox POP SDK 调用 `CreateVolume`，在指定 Team 中创建一个引用 AgenticFS Access Point 的 named Volume。
2. 使用 E2B SDK 创建 Sandbox，通过 `volume_mounts` 把 Volume 名称映射到 Sandbox 内的目录。

`CreateVolume` 只创建云沙箱侧的 Volume 元数据，不会创建或删除 AgenticFS FileSystem、AgenticSpace、Access Point，也不会复制
AgenticFS 中的数据。

## 前提条件

使用前需要准备：

- 已在函数计算云沙箱控制台创建 Team，并获取 Team ID。创建 Volume 的 Team 必须与 E2B API Key 绑定的 Team 相同。
- 目标账号和地域已开通 AgenticFS Volume 能力。
- 已创建 AgenticFS FileSystem、AgenticSpace 和 Access Point，并获取 Access Point 地址。根目录地址格式如下：

  ```text
  ap-<access-point-id>.<file-system-id>-<suffix>.<region>.nas.aliyuncs.com:/
  ```

- 已准备与 Access Point 网络连通的 VPC、vSwitch 和安全组。创建 Sandbox 时必须通过 metadata 传入完整的 VPC 配置；模板中已有
  VPC 配置不能替代该 metadata。
- 已准备一个供 Sandbox 使用的函数执行 RAM Role，并将 Role ARN 写入 `fc.sandbox.auth.role`。该 Role 需要具备 AgenticFS
  挂载和读写权限。
- 调用 POP SDK 的阿里云身份具备 `fcsandbox:CreateVolume` 权限；如果需要运行本文的清理代码，还需要 `fcsandbox:DeleteVolume`
  权限。
- 已准备云沙箱 API Key、API URL、Domain 和可用模板。

Team 的创建和 Team ID 获取方式参见 [Team 与订阅计划](../../01.开始使用/04.Team%20与订阅计划.md)。

## 权限配置

本流程涉及三种凭证，作用不同：

| 凭证                                  | 用途                                 |
|-------------------------------------|------------------------------------|
| 阿里云 AK/SK 或 STS 临时凭证                | 调用 FCSandbox POP SDK 创建和删除 Volume。 |
| 云沙箱 API Key                         | 使用 E2B SDK 创建和操作 Sandbox。          |
| `fc.sandbox.auth.role` 指定的函数执行 Role | Sandbox 挂载并访问 AgenticFS。           |

调用 `CreateVolume` 和 `DeleteVolume` 的 RAM 策略可以按 Team 收敛到以下资源：

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "fcsandbox:CreateVolume",
        "fcsandbox:DeleteVolume"
      ],
      "Resource": "acs:fcsandbox:<region>:<account-id>:teams/<team-id>/volumes/*"
    }
  ]
}
```

Sandbox 执行 Role 需要按实际读写需求授予 NAS Client 权限。AgenticFS 挂载复用 NAS Client 权限：

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "nas:ClientMount",
        "nas:ClientWrite",
        "nas:ClientRootAccess"
      ],
      "Resource": "*"
    }
  ]
}
```

以上 `Resource: "*"` 仅用于说明。生产环境应将权限收敛到实际使用的 AgenticFS 文件系统或访问范围，并确认该 Role
的信任策略允许函数计算服务使用。

## 安装 SDK

Python 版本建议使用 3.10 或更高版本。

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install alibabacloud_fcsandbox20260509==1.2.2 e2b==2.31.0
```

FCSandbox POP SDK 使用阿里云凭证，E2B SDK 使用云沙箱 API Key。运行示例前设置以下环境变量：

```bash
export ALIBABA_CLOUD_ACCESS_KEY_ID="<your-access-key-id>"
export ALIBABA_CLOUD_ACCESS_KEY_SECRET="<your-access-key-secret>"
# 使用 STS 临时凭证时还需要设置：
# export ALIBABA_CLOUD_SECURITY_TOKEN="<your-security-token>"

export FCSANDBOX_REGION_ID="cn-hangzhou"
export FCSANDBOX_ENDPOINT="fcsandbox.cn-hangzhou.aliyuncs.com"
export FCSANDBOX_TEAM_ID="<team-id>"

export E2B_API_KEY="<your-e2b-api-key>"
export E2B_API_URL="https://api.<region>.e2b.fc.aliyuncs.com"
export E2B_DOMAIN="<region>.e2b.fc.aliyuncs.com"
export E2B_TEMPLATE="code-interpreter-v1"

export AGENTICFS_SERVER_ADDR="ap-<access-point-id>.<file-system-id>-<suffix>.<region>.nas.aliyuncs.com:/"
export AGENTICFS_USER_ID="1000"
export AGENTICFS_GROUP_ID="1000"

export E2E_VPC_ID="vpc-xxxxxxxx"
export E2E_SECURITY_GROUP_ID="sg-xxxxxxxx"
export E2E_VSWITCH_ID="vsw-xxxxxxxx"
export E2E_ROLE_ARN="acs:ram::<account-id>:role/<execution-role>"
```

`FCSANDBOX_ENDPOINT` 不包含 `https://`。如果 SDK 已内置目标地域的 Endpoint，可以不设置该变量，由 SDK 根据
`FCSANDBOX_REGION_ID` 解析。

## 创建 AgenticFS Volume

使用 FCSandbox POP SDK 的 `CreateVolume` 创建 AgenticFS Volume：

```python
import os

from alibabacloud_fcsandbox20260509 import models
from alibabacloud_fcsandbox20260509.client import Client as FCSandboxClient
from alibabacloud_tea_openapi import models as open_api_models


def require_env(name: str) -> str:
    value = os.environ.get(name, "").strip()
    if not value:
        raise RuntimeError(f"缺少环境变量: {name}")
    return value


config = open_api_models.Config(
    access_key_id=require_env("ALIBABA_CLOUD_ACCESS_KEY_ID"),
    access_key_secret=require_env("ALIBABA_CLOUD_ACCESS_KEY_SECRET"),
    security_token=os.environ.get("ALIBABA_CLOUD_SECURITY_TOKEN"),
    region_id=require_env("FCSANDBOX_REGION_ID"),
)
if os.environ.get("FCSANDBOX_ENDPOINT"):
    config.endpoint = os.environ["FCSANDBOX_ENDPOINT"]

pop_client = FCSandboxClient(config)
team_id = require_env("FCSANDBOX_TEAM_ID")

response = pop_client.create_volume(
    models.CreateVolumeRequest(
        body=models.CreateVolumeInput(
            team_id=team_id,
            volume_name="agent-workspace",
            agentic_fsvolume_config=models.AgenticFSVolumeConfig(
                server_addr=require_env("AGENTICFS_SERVER_ADDR"),
                user_id=int(require_env("AGENTICFS_USER_ID")),
                group_id=int(require_env("AGENTICFS_GROUP_ID")),
            ),
        )
    )
)

if response.body is None or response.body.volume is None:
    raise RuntimeError("CreateVolume 未返回 Volume")

volume = response.body.volume
print(f"request_id={response.body.request_id}")
print(f"volume_id={volume.volume_id}")
print(f"volume_name={volume.volume_name}")
print(f"storage_class={volume.storage_class}")
print(f"status={volume.status}")
```

Python SDK 中 `agentic_fsvolume_config` 的拼写由生成模型定义；它对应 OpenAPI 请求中的 AgenticFS Volume 配置。不要改成
`agentic_fs_volume_config`。

`CreateVolumeInput` 的关键参数如下：

| Python 参数                 | 是否必填 | 说明                                                          |
|---------------------------|------|-------------------------------------------------------------|
| `team_id`                 | 是    | Volume 所属 Team ID，必须与后续 E2B API Key 所属 Team 一致。             |
| `volume_name`             | 是    | named Volume 名称，在同一个 Team 内必须唯一。                            |
| `agentic_fsvolume_config` | 是    | AgenticFS 配置。请求不能同时设置 OSS 等其他 Volume 配置。                    |
| `server_addr`             | 是    | AgenticFS Access Point 地址，最长 128 个字符。必须包含以 `:/` 开始的规范化绝对路径。 |
| `user_id`                 | 否    | 挂载使用的 Linux UID，取值范围为 `-1`～`65534`。                         |
| `group_id`                | 否    | 挂载使用的 Linux GID，取值范围为 `-1`～`65534`。                         |

`storage_class` 由 `agentic_fsvolume_config` 自动推导为 `AGENTIC_FS`，请求中不需要设置。POP `CreateVolume` 使用顶层的类型化配置，不要再传
E2B 兼容 REST 接口中的 `fcExtensionConfig`。

如果需要把 Access Point 下的子目录作为 Volume，可以把 `server_addr` 设置为：

```text
ap-<access-point-id>.<file-system-id>-<suffix>.<region>.nas.aliyuncs.com:/project-a
```

远端路径必须是规范化路径，不能包含空白字符、控制字符、重复分隔符、`.`、`..` 或多余的结尾 `/`。

## 创建 Sandbox 并挂载 Volume

创建 Sandbox 时，将本地挂载目录作为 `volume_mounts` 的 key，将 POP `CreateVolume` 返回的 `volume_name` 作为 value。同时通过
metadata 传入完整 VPC 配置和函数执行 Role：

```python
import json

from e2b import Sandbox

vpc_config = {
    "vpcId": require_env("E2E_VPC_ID"),
    "securityGroupId": require_env("E2E_SECURITY_GROUP_ID"),
    "vSwitchIds": [require_env("E2E_VSWITCH_ID")],
}

mount_dir = "/mnt/agenticfs"
sandbox = Sandbox.create(
    template=require_env("E2B_TEMPLATE"),
    timeout=300,
    api_key=require_env("E2B_API_KEY"),
    api_url=require_env("E2B_API_URL"),
    domain=require_env("E2B_DOMAIN"),
    volume_mounts={
        mount_dir: volume.volume_name,
    },
    metadata={
        "fc.sandbox.network.vpc": json.dumps(vpc_config),
        "fc.sandbox.auth.role": require_env("E2E_ROLE_ARN"),
    },
)
```

`volume_mounts` 只引用 Volume 名称，不使用 Volume ID 或 AgenticFS Access Point 地址。Sandbox 服务会在当前 Team 中解析该名称，并把
AgenticFS 挂载到指定路径。

## 验证挂载和清理资源

创建成功后，应实际执行一次写入、读取和删除，验证 AgenticFS 数据面可用。最后先释放 Sandbox，再删除云沙箱侧的 Volume 元数据：

```python
marker_path = f"{mount_dir}/hello-agenticfs.txt"

try:
    info = sandbox.get_info()
    print(f"volume_mounts={info.volume_mounts}")

    sandbox.files.write(marker_path, "hello agenticfs\n")
    content = sandbox.files.read(marker_path)
    if content != "hello agenticfs\n":
        raise RuntimeError(f"文件内容不一致: {content!r}")

    sandbox.files.remove(marker_path)
    print("AgenticFS 挂载读写验证成功")
finally:
    sandbox.kill()

delete_response = pop_client.delete_volume(
    volume.volume_id,
    models.DeleteVolumeRequest(team_id=team_id),
)
print(f"delete_request_id={delete_response.body.request_id}")
```

删除 Volume 只删除云沙箱控制面的 named Volume 元数据，不会删除 AgenticFS Access Point 或其中的数据。如果后续 Sandbox 仍需使用该
Volume，请不要执行 `delete_volume`。

## 使用限制

- `server_addr` 必须使用 AgenticFS Access Point 地址，不能使用普通 NAS 挂载地址或带协议前缀的 URL。
- `server_addr` 和 Sandbox 挂载目录当前最大长度均为 128 个字符。
- 同一个 Sandbox 挂载多个 AgenticFS Volume 时，各 Volume 的 `user_id` 和 `group_id` 设置必须完全一致，包括“未设置”这一状态。
- AgenticFS 与 metadata 中的原生 NAS 挂载同时使用时，两者的 UID/GID 也必须一致；AgenticFS 与 NAS 挂载点合计最多 5 个。
- 同一个 Sandbox 中的挂载目录不能重复。建议使用 `/mnt/agenticfs` 或其子目录，避免覆盖模板内已有目录。
- Volume 创建成功只表示控制面元数据已创建。最终验收应包含 Sandbox 创建、真实文件写入、读取和删除。
- Sandbox 暂停后再恢复时会恢复 Volume 挂载；AgenticFS 数据由外部文件系统持久化，不依赖 Sandbox 生命周期。

## 常见问题

| 现象                                         | 可能原因与处理方式                                                                                          |
|--------------------------------------------|----------------------------------------------------------------------------------------------------|
| POP SDK 返回 `Forbidden`                     | 调用 AK/STS 身份缺少 `fcsandbox:CreateVolume`，或没有目标 Team 的 Volume 资源权限。                                  |
| 返回 `TeamNotFound`                          | `team_id` 不存在、地域不匹配，或不属于当前账号可访问范围。                                                                 |
| 返回 `CreateVolumeNotSupported` 或 `NotFound` | 当前账号、地域或 Team 未开放对应的 Volume/AgenticFS 能力。                                                          |
| 返回 `InvalidParameter`                      | 检查 Access Point 地址、UID/GID 范围，并确认请求只设置了一个 Volume 配置。                                               |
| 返回 `VolumeConflict`                        | 同一 Team 中已存在同名 Volume。更换 `volume_name`，或先确认并清理旧 Volume。                                            |
| 创建 Sandbox 提示 VPC 配置不完整                    | `fc.sandbox.network.vpc` 必须同时包含 `vpcId`、`securityGroupId` 和非空的 `vSwitchIds`。模板 VPC 不能替代该 metadata。 |
| 创建 Sandbox 提示 `executionRoleArn`           | `fc.sandbox.auth.role` 缺失或为空，或调用方不能使用该 Role。                                                       |
| Sandbox 创建时挂载失败                            | 检查 Access Point 状态、VPC/vSwitch/安全组连通性、执行 Role 权限以及 AgenticFS 所在地域。保留错误中的 request ID 便于排查。          |
| Volume 已创建但文件读写失败                          | 先检查 `sandbox.get_info().volume_mounts`，再确认目录权限、UID/GID、Role 权限和 AgenticFS Access Point 的实际状态。      |
