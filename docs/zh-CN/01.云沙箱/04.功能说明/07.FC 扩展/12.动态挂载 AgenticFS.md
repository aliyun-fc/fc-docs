# 动态挂载 AgenticFS

动态挂载 AgenticFS 用于在创建 Sandbox 时，将已有 AgenticFS AgenticSpace Access Point 或其子目录挂载到 Sandbox 内的本地目录。挂载完成后，Sandbox 可以像访问本地文件系统一样读取或写入挂载目录。

本方式直接通过 Sandbox metadata 提交 AgenticFS 挂载配置，不需要预先创建云沙箱 Volume。如需复用已保存的挂载配置，请先[创建 AgenticFS Volume](./08.创建%20AgenticFS%20Volume.md)，再通过 `volume_mounts` [挂载 AgenticFS Volume](../12.卷/02.挂载%20AgenticFS%20Volume.md)。如需向运行中的 Sandbox 追加挂载，请参见[追加挂载沙箱存储](./09.追加挂载沙箱存储.md)。

创建 Sandbox 时需要传入以下 metadata：

- `fc.sandbox.storage.agenticfs`：AgenticFS 挂载配置，值为 JSON 字符串。
- `fc.sandbox.network.vpc`：用于访问 AgenticFS Access Point 的完整 VPC 配置，值为 JSON 字符串。
- `fc.sandbox.auth.role`：用于访问 AgenticFS 的 RAM Role ARN。

## 前提条件

AgenticFS 的产品说明参见[什么是 AgenticFS](https://help.aliyun.com/zh/nas/product-overview/agenticfs-overview)。相关资源在 [NAS 控制台](https://nasnext.console.aliyun.com/)创建和管理。

使用前需要准备：

- 已创建 AgenticFS、AgenticSpace 和启用 RAM 认证的 Access Point，并确认 Access Point 处于 `active` 状态。
- 已获取 Access Point 地址，例如 `ap-<access-point-id>.<file-system-id>-<suffix>.<region>.nas.aliyuncs.com:/`。
- 已准备与 Access Point 网络连通的 VPC、vSwitch 和安全组。
- 已准备函数执行 RAM Role。该 Role 具备 AgenticFS 挂载和读写权限，且信任策略允许函数计算服务扮演。
- 已准备云沙箱 API Key、API URL、Domain 和可用模板。

### 第二代运行时镜像要求

如果使用[第二代运行时（MicroVM）](../02.模板/03.通过%20OpenAPI%20构建和管理模板.md)的自定义模板，必须在构建模板前，在源镜像中预装 AgenticFS 客户端。客户端安装、镜像构建和验证方法参见[挂载 AgenticFS Volume](../12.卷/02.挂载%20AgenticFS%20Volume.md)中的第二代运行时镜像要求。

## 配置权限

请将以下权限策略授予函数执行 RAM Role：

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "nas:ClientMount",
        "nas:ClientWrite",
        "nas:ClientRootAccess"
      ],
      "Resource": "*"
    }
  ]
}
```

该 Role 的信任策略还必须允许函数计算服务扮演。相关配置参见[权限策略及示例](https://help.aliyun.com/zh/functioncompute/policies-and-sample-policies)。

## 挂载配置

`fc.sandbox.storage.agenticfs` 的值必须是 JSON 字符串，结构如下：

```json
{
  "userID": 1000,
  "groupID": 1000,
  "mountPoints": [
    {
      "serverAddr": "ap-<access-point-id>.<file-system-id>-<suffix>.<region>.nas.aliyuncs.com:/project-a",
      "mountDir": "/mnt/agenticfs"
    }
  ]
}
```

字段说明：

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| `userID` | 否 | 挂载使用的用户 ID，取值范围为 `-1`～`65534`。同一个配置中的所有挂载点共用该值。 |
| `groupID` | 否 | 挂载使用的用户组 ID，取值范围为 `-1`～`65534`。同一个配置中的所有挂载点共用该值。 |
| `mountPoints` | 是 | AgenticFS 挂载点列表，至少包含一个挂载点。 |
| `mountPoints[].serverAddr` | 是 | AgenticFS Access Point 地址。可以在 `:/` 后指定 Access Point 下的远端子目录。 |
| `mountPoints[].mountDir` | 是 | Sandbox 内的挂载目录，必须是规范化的绝对 Unix 路径，例如 `/mnt/agenticfs`。 |

字段名区分大小写。必须使用 `userID`、`groupID`、`serverAddr` 和 `mountDir`。平台会为 AgenticFS 挂载启用 TLS，不要在配置中传入 `enableTLS`；配置使用严格 JSON 解析，未声明的字段会导致创建 Sandbox 失败。

## 本地挂载目录

`mountDir` 表示 Sandbox 运行环境中的本地文件系统挂载点，不是 AgenticFS 的远端目录。

- 建议使用 `/home`、`/mnt`、`/tmp` 或 `/data` 的子目录，例如 `/mnt/agenticfs` 或 `/data/files`，避免覆盖模板内已有目录。
- 不能使用 `/`，也不能包含前后空格、`.`、`..` 或重复的路径分隔符。
- 同一个 Sandbox 中的挂载目录不能重复，也不能与其他存储类型使用相同的挂载目录。

## 创建带 AgenticFS 挂载的 Sandbox

创建 Sandbox 的基本方法参见[创建沙箱](../01.沙箱/02.创建沙箱.md)。以下 Python 示例在创建 Sandbox 时动态挂载 AgenticFS，并验证文件写入、读取和删除。将代码保存为 `12_sandbox_agenticfs.py`：

```python
import json
import os

from e2b import Sandbox


def require_env(name: str) -> str:
    value = os.environ.get(name, "").strip()
    if not value:
        raise RuntimeError(f"缺少环境变量: {name}")
    return value


mount_dir = "/mnt/agenticfs"
marker_path = f"{mount_dir}/hello-agenticfs.txt"
agenticfs_config = {
    "userID": int(require_env("AGENTICFS_USER_ID")),
    "groupID": int(require_env("AGENTICFS_GROUP_ID")),
    "mountPoints": [
        {
            "serverAddr": require_env("AGENTICFS_SERVER_ADDR"),
            "mountDir": mount_dir,
        }
    ],
}
vpc_config = {
    "vpcId": require_env("FCSANDBOX_VPC_ID"),
    "securityGroupId": require_env("FCSANDBOX_SECURITY_GROUP_ID"),
    "vSwitchIds": [require_env("FCSANDBOX_VSWITCH_ID")],
}

sandbox = None
marker_written = False
try:
    sandbox = Sandbox.create(
        template=require_env("E2B_TEMPLATE"),
        timeout=300,
        api_key=require_env("E2B_API_KEY"),
        api_url=require_env("E2B_API_URL"),
        domain=require_env("E2B_DOMAIN"),
        metadata={
            "fc.sandbox.storage.agenticfs": json.dumps(agenticfs_config),
            "fc.sandbox.network.vpc": json.dumps(vpc_config),
            "fc.sandbox.auth.role": require_env("FCSANDBOX_ROLE_ARN"),
        },
    )

    sandbox.files.write(marker_path, "hello agenticfs\n")
    marker_written = True
    content = sandbox.files.read(marker_path)
    if content != "hello agenticfs\n":
        raise RuntimeError(f"文件内容不一致: {content!r}")
finally:
    try:
        if sandbox is not None and marker_written:
            sandbox.files.remove(marker_path)
    finally:
        if sandbox is not None:
            sandbox.kill()

print("AgenticFS 动态挂载读写验证成功")
```

运行前设置环境变量：

```bash
export E2B_API_KEY="<your-e2b-api-key>"
export E2B_API_URL="https://api.<region>.e2b.fc.aliyuncs.com"
export E2B_DOMAIN="<region>.e2b.fc.aliyuncs.com"
export E2B_TEMPLATE="<template-id>"

export AGENTICFS_SERVER_ADDR="ap-<access-point-id>.<file-system-id>-<suffix>.<region>.nas.aliyuncs.com:/"
export AGENTICFS_USER_ID="1000"
export AGENTICFS_GROUP_ID="1000"

export FCSANDBOX_VPC_ID="vpc-xxxxxxxx"
export FCSANDBOX_SECURITY_GROUP_ID="sg-xxxxxxxx"
export FCSANDBOX_VSWITCH_ID="vsw-xxxxxxxx"
export FCSANDBOX_ROLE_ARN="acs:ram::<account-id>:role/<execution-role>"

python 12_sandbox_agenticfs.py
```

## 挂载 Access Point 下的子目录

在 `serverAddr` 的 `:/` 后指定远端目录，可以只挂载 Access Point 下的子目录。例如：

```text
ap-<access-point-id>.<file-system-id>-<suffix>.<region>.nas.aliyuncs.com:/project-a
```

若远端子目录不存在，系统会在首次挂载 Sandbox 时自动创建。远端路径必须使用规范化的绝对路径，不能包含空白字符、控制字符、重复分隔符、`.` 或 `..`，也不能以 `/` 结尾。

## 使用限制

- `fc.sandbox.storage.agenticfs` 和 `fc.sandbox.network.vpc` 的值必须是 JSON 字符串，不能直接传入 Python 字典。
- metadata 键必须使用全小写的 `fc.sandbox.storage.agenticfs`。`fc.sandbox.storage.agenticFs` 和 `fc.sandbox.storage.agentic_fs` 不会被识别为 AgenticFS 挂载配置。
- `serverAddr` 必须使用 AgenticFS Access Point 地址，不能使用普通 NAS 挂载地址或带协议前缀的 URL，最大长度为 128 个字符。
- `mountDir` 最大长度为 128 个字符，必须是规范化的绝对 Unix 路径，且不能为 `/`。
- 创建 Sandbox 时必须通过 `fc.sandbox.network.vpc` 提供完整 VPC 配置，并通过 `fc.sandbox.auth.role` 提供执行 Role。模板中的 VPC 配置不能替代该 metadata。
- 同一个 Sandbox 中存在多个 AgenticFS 挂载点时，它们共用同一组 `userID` 和 `groupID`。

## 常见问题

### 创建 Sandbox 提示 VPC 配置不完整

确认 `fc.sandbox.network.vpc` 包含 `vpcId`、`securityGroupId` 和非空的 `vSwitchIds`，并检查 VPC 与 Access Point 的网络连通性。

### 创建 Sandbox 提示需要 Function Role

确认 `fc.sandbox.auth.role` 不为空，Role 具备 AgenticFS 挂载和读写权限，并且信任策略允许函数计算服务扮演。

### metadata 返回未知字段错误

AgenticFS metadata 使用严格 JSON 解析。检查字段大小写，并删除 `enableTLS`、`readOnly` 等未声明字段。

### Sandbox 创建时挂载失败

确认 Access Point 处于 `active` 状态，并检查 Access Point 地址、远端子目录、VPC 连通性、执行 Role 权限和自定义镜像中的 AgenticFS 客户端。保留 request ID 便于排查。
