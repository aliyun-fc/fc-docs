# 创建 JuiceFS Volume

JuiceFS Volume 保存已有 JuiceFS 企业版文件系统的挂载配置。创建完成后，可以在创建 Sandbox 时按 Volume 名称挂载。

`CreateVolume` 只创建云沙箱侧的 Volume 元数据，不会创建、删除或复制 JuiceFS 文件系统及其中的数据。

## 前提条件

使用前需要准备：

- Volume 目前仍处于邀测阶段，需要提交阿里云工单申请开通。
- 已在函数计算云沙箱控制台创建 Team，并获取 Team ID。
- 已在 [JuiceFS 企业版控制台](https://juicefs.com/console)创建文件系统，并获取文件系统名称、访问 Token 和服务地址。操作方法参见 [JuiceFS 企业版快速上手](https://juicefs.com/docs/zh/cloud/getting_started/)。
- 调用 POP SDK 的阿里云身份具备 `fcsandbox:CreateVolume` 权限；查询 Volume 需要 `fcsandbox:ListVolumes` 和 `fcsandbox:GetVolume` 权限；删除 Volume 还需要 `fcsandbox:DeleteVolume` 权限。

Team 的创建和 Team ID 获取方式参见[创建 Team](../../01.开始使用/02.创建%20Team.md)。

## 权限配置

调用 Volume API 的 RAM 身份需要以下权限，请替换占位符：

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "fcsandbox:CreateVolume",
        "fcsandbox:ListVolumes",
        "fcsandbox:GetVolume",
        "fcsandbox:DeleteVolume"
      ],
      "Resource": "*"
    }
  ]
}
```

生产环境支持按 Team 精确授权 Volume 资源：

```text
acs:fcsandbox:<region>:<account-id>:teams/<team-id>/volumes/*
```

## 安装 SDK

云沙箱 OpenAPI 当前支持 Java、Python、Go 和 TypeScript SDK。支持范围、安装方式和版本以[阿里云 SDK & API 说明](https://help.aliyun.com/zh/functioncompute/alibaba-cloud-sdk-api-description)为准。本文使用 Python 演示。

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install "alibabacloud_fcsandbox20260509==1.5.0"
```

运行示例前设置以下环境变量：

```bash
export ALIBABA_CLOUD_ACCESS_KEY_ID="<your-access-key-id>"
export ALIBABA_CLOUD_ACCESS_KEY_SECRET="<your-access-key-secret>"
# 使用 STS 临时凭证时还需要设置：
# export ALIBABA_CLOUD_SECURITY_TOKEN="<your-security-token>"

export FCSANDBOX_REGION_ID="<region>"
export FCSANDBOX_ENDPOINT="fcsandbox.<region>.aliyuncs.com"
export FCSANDBOX_TEAM_ID="<team-id>"
export FCSANDBOX_VOLUME_NAME="juicefs-workspace"

export JUICEFS_VOLUME_NAME="<juicefs-file-system-name>"
export JUICEFS_BASE_URL="https://<juicefs-service-address>"
export JUICEFS_TOKEN="<juicefs-token>"
export JUICEFS_REMOTE_DIR="/"
```

`FCSANDBOX_ENDPOINT` 不包含 `https://`。如果 SDK 已内置目标地域的 Endpoint，可以不设置该变量，由 SDK 根据 `FCSANDBOX_REGION_ID` 解析。

## 创建 JuiceFS Volume

请求参数、返回参数和错误码以 OpenAPI 门户的 [CreateVolume - 创建 Volume](https://api.aliyun.com/api/FCSandbox/2026-05-09/CreateVolume) 为准。

`juiceFSVolumeConfig` 字段说明：

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| `volumeName` | 是 | JuiceFS 文件系统名称，不是要创建的云沙箱 Volume 名称。 |
| `baseURL` | 是 | JuiceFS 企业版客户端访问的服务地址。 |
| `remoteDir` | 否 | JuiceFS 文件系统中要挂载的远端目录。本文示例显式设置为 `/`。 |
| `token` | 是 | JuiceFS 文件系统的访问 Token。Volume 查询响应不会回显该字段。 |
| `args` | 否 | 传递给 JuiceFS 客户端的额外挂载参数，类型为字符串数组。平台根据 `token` 和 `remoteDir` 生成客户端的 `--token` 和 `--subdir` 参数，不要通过该字段重复传入这两个参数。 |

`--subdir` 是 JuiceFS 客户端用于挂载远端子目录的命令行参数，对应表中的 `remoteDir`，不是 Sandbox 内的本地挂载目录。用户只需要设置 `remoteDir`，平台会在挂载时完成转换。

以下示例创建 JuiceFS Volume 并输出创建结果。当前 Python SDK 尚未提供 `JuiceFSVolumeConfig` 专用模型，因此示例使用 SDK 的通用 OpenAPI 调用方法提交相同的 `CreateVolume` 请求。将代码保存为 `13_create_juicefs_volume.py`：

```python
import os

from alibabacloud_fcsandbox20260509.client import Client as FCSandboxClient
from alibabacloud_tea_openapi import models as open_api_models
from alibabacloud_tea_openapi import utils_models as open_api_util_models
from darabonba.runtime import RuntimeOptions


def require_env(name: str) -> str:
    value = os.environ.get(name, "").strip()
    if not value:
        raise RuntimeError(f"缺少环境变量: {name}")
    return value


config = open_api_models.Config(
    access_key_id=require_env("ALIBABA_CLOUD_ACCESS_KEY_ID"),
    access_key_secret=require_env("ALIBABA_CLOUD_ACCESS_KEY_SECRET"),
    security_token=os.environ.get("ALIBABA_CLOUD_SECURITY_TOKEN"),
    region_id=require_env("FCSANDBOX_REGION_ID"),
)
if os.environ.get("FCSANDBOX_ENDPOINT"):
    config.endpoint = os.environ["FCSANDBOX_ENDPOINT"]

pop_client = FCSandboxClient(config)
body = {
    "teamID": require_env("FCSANDBOX_TEAM_ID"),
    "volumeName": require_env("FCSANDBOX_VOLUME_NAME"),
    "juiceFSVolumeConfig": {
        "volumeName": require_env("JUICEFS_VOLUME_NAME"),
        "baseURL": require_env("JUICEFS_BASE_URL"),
        "remoteDir": require_env("JUICEFS_REMOTE_DIR"),
        "token": require_env("JUICEFS_TOKEN"),
        "args": [],
    },
}

response = pop_client.call_api(
    open_api_util_models.Params(
        action="CreateVolume",
        version="2026-05-09",
        protocol="HTTPS",
        pathname="/pop/2026-05-09/volumes",
        method="POST",
        auth_type="AK",
        style="ROA",
        req_body_type="json",
        body_type="json",
    ),
    open_api_util_models.OpenApiRequest(body=body),
    RuntimeOptions(
        autoretry=False,
        connect_timeout=10_000,
        read_timeout=60_000,
    ),
)

response_body = response.get("body") or {}
volume = response_body.get("volume") or {}
if not volume.get("volumeID"):
    raise RuntimeError("CreateVolume 未返回 Volume")

print(f"request_id={response_body.get('requestId', '')}")
print(f"volume_id={volume['volumeID']}")
print(f"volume_name={volume.get('volumeName', '')}")
print(f"storage_class={volume.get('storageClass', '')}")
print(f"status={volume.get('status', '')}")
```

运行示例：

```bash
python 13_create_juicefs_volume.py
```

创建成功仅表示 Volume 元数据创建成功。参见[挂载 JuiceFS Volume](../12.卷/04.挂载%20JuiceFS%20Volume.md)将该 Volume 挂载到 Sandbox，并通过实际读写确认挂载可用。

## 挂载远端子目录

`remoteDir` 用于限制该 Volume 可访问的 JuiceFS 目录范围。例如，将 `JUICEFS_REMOTE_DIR` 设置为 `/datasets/project-a` 后，Sandbox 中的挂载目录对应此远端子目录，而不是文件系统根目录。

如果远端子目录不存在，挂载时会在 JuiceFS 文件系统中自动创建：

```bash
export JUICEFS_REMOTE_DIR="/datasets/project-a"
python 13_create_juicefs_volume.py
```

请使用以 `/` 开头的远端绝对路径，并确保 Token 具有创建和访问目标目录所需的权限。

## 管理 Volume

通过 [ListVolumes](https://api.aliyun.com/api/FCSandbox/2026-05-09/ListVolumes) 查询 Volume 列表，通过 [GetVolume](https://api.aliyun.com/api/FCSandbox/2026-05-09/GetVolume) 查看详情，通过 [DeleteVolume](https://api.aliyun.com/api/FCSandbox/2026-05-09/DeleteVolume) 删除不再使用的 Volume。

删除 Volume 只删除云沙箱侧的挂载配置，不会删除 JuiceFS 文件系统或其中的数据。

## 使用限制

- 当前仅支持 JuiceFS 企业版。
- `remoteDir` 最大为 128 字节，`token` 最大为 256 字节。
- JuiceFS Volume 使用客户已有的文件系统，不支持 StorageProfile，也不会创建或删除外部存储资源。
- 同一 Team 中的 Volume 名称不能重复。
- 不要在日志中打印请求体、JuiceFS Token 或其他凭证。

## 常见问题

### `baseURL` 与 metadata 挂载中的 `BASE_URL` 是同一个字段吗

两者表示相同的 JuiceFS 服务地址，但属于不同的请求结构。创建 JuiceFS Volume 时使用 `juiceFSVolumeConfig.baseURL`；通过 metadata 直接挂载时使用 `fc.sandbox.storage.juicefs` 中的 `envs.BASE_URL`。

### 创建成功是否代表 JuiceFS 已经可以挂载

不是。`CreateVolume` 只校验并保存挂载配置，不探测 JuiceFS 服务的网络连通性，也不会执行真实挂载。必须继续创建 Sandbox，并完成文件读写验证。
