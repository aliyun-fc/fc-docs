# 动态挂载 JuiceFS

创建 Sandbox 时，可以通过 `fc.sandbox.storage.juicefs` metadata 将已有 JuiceFS 文件系统挂载到指定目录。挂载后，Sandbox 可以通过文件路径访问 JuiceFS，数据不随 Sandbox 释放而删除。

当前仅支持在创建 Sandbox 时，通过 metadata 配置 JuiceFS 挂载。

## 前提条件

- 已在 [JuiceFS 企业版控制台](https://juicefs.com/console)创建文件系统，并获取文件系统名称、访问 Token 和服务地址。操作方法参见 [JuiceFS 企业版快速上手](https://juicefs.com/docs/zh/cloud/getting_started/)。
- 已准备与 JuiceFS 服务网络连通的 VPC、vSwitch 和安全组。
- 已准备云沙箱 API Key、API URL、Domain 和第二代运行时（MicroVM）自定义模板。

### 第二代运行时镜像要求

JuiceFS 动态挂载必须使用[第二代运行时（MicroVM）](../02.模板/03.通过%20OpenAPI%20构建和管理模板.md)。构建自定义模板前，必须在源镜像中预装 JuiceFS 企业版客户端和 FUSE。第二代运行时直接使用源镜像，不会在模板构建时注入 JuiceFS 客户端。

当前仅支持 JuiceFS 企业版。JuiceFS 官方在 Docker Hub 的 [`juicedata/mount`](https://hub.docker.com/r/juicedata/mount/tags) 仓库提供企业版 Mount 镜像，镜像标签以 `ee-` 开头。镜像中的 `/usr/bin/juicefs` 是客户端启动器，固定版本的客户端可执行文件位于 `/usr/local/juicefs/mount/jfsmount`。

以下示例使用 `juicedata/mount:ee-5.3.7-58af72b`。其中，`5.3.7` 是客户端版本，`58af72b` 是对应的构建 commit。版本信息可通过 [JuiceFS 命令参考](https://juicefs.com/docs/zh/cloud/reference/command_reference/)核对。镜像和容器的使用方法参见[在 Docker 中使用 JuiceFS](https://juicefs.com/docs/zh/cloud/use_juicefs_in_docker/)。

先确认镜像可以拉取，并检查其中的企业版客户端：

```bash
docker pull --platform linux/amd64 \
  juicedata/mount:ee-5.3.7-58af72b

docker run --rm --platform linux/amd64 \
  --entrypoint /usr/bin/juicefs \
  juicedata/mount:ee-5.3.7-58af72b \
  version
```

输出的客户端版本应为 `5.3.7`，构建 commit 应为 `58af72b`。不要使用 `latest` 或 `ee-nightly` 等浮动标签，以免重新构建模板后客户端版本发生变化。如果构建环境不能访问 Docker Hub，请先将该镜像同步到可访问的私有镜像仓库，再替换以下 Dockerfile 中 `juicedata/mount` 的镜像地址。

以下 Dockerfile 默认使用 Ubuntu 22.04。构建已有 Sandbox 基础镜像时，通过 `BASE_IMAGE` 构建参数传入该镜像地址：

```dockerfile
ARG BASE_IMAGE=ubuntu:22.04

FROM juicedata/mount:ee-5.3.7-58af72b AS juicefs-ee

FROM ${BASE_IMAGE}

ARG DEBIAN_FRONTEND=noninteractive

RUN set -eux; \
    apt-get update; \
    apt-get install -y --no-install-recommends \
        ca-certificates \
        fuse \
        librados2; \
    rm -rf /var/lib/apt/lists/*

COPY --from=juicefs-ee /usr/local/juicefs/mount/jfsmount /usr/bin/juicefs

RUN set -eux; \
    chmod 0755 /usr/bin/juicefs; \
    command -v juicefs; \
    command -v fusermount; \
    mkdir -p /mnt/juicefs

WORKDIR /root

# 不设置自定义 USER、ENTRYPOINT 或 CMD，由 Sandbox 管控链路接管。
```

不要将 JuiceFS Token 或挂载配置写入 Dockerfile 或镜像层。

构建并推送 `linux/amd64` 镜像。将占位符替换为实际值：

```bash
docker buildx build \
  --platform linux/amd64 \
  --build-arg BASE_IMAGE="<your-sandbox-base-image>" \
  --push \
  -t "<registry>/<namespace>/microsandbox-juicefs-ee:<version>" \
  .
```

构建完成后，检查镜像中的客户端、RADOS 运行库和 FUSE 2：

```bash
docker run --rm --platform linux/amd64 \
  --entrypoint /bin/sh \
  <registry>/<namespace>/microsandbox-juicefs-ee:<version> \
  -euxc '
    command -v juicefs
    command -v fusermount
    ldconfig -p | grep "librados\.so\.2"
    juicefs version
  '
```

该检查只验证镜像内容，不代表 VPC、Token 或真实挂载链路已经可用。请使用该镜像重新构建 MicroVM 模板，再运行后续示例。

## 挂载配置

`fc.sandbox.storage.juicefs` 的值是 JSON 字符串，结构如下：

```json
{
  "mountPoints": [
    {
      "volumeName": "<juicefs-file-system-name>",
      "remoteDir": "/",
      "mountDir": "/mnt/juicefs",
      "token": "<juicefs-token>",
      "args": []
    }
  ],
  "envs": {
    "BASE_URL": "https://<juicefs-service-address>"
  }
}
```

字段说明：

| 字段 | 类型 | 是否必填 | 说明 |
| --- | --- | --- | --- |
| `mountPoints` | 对象数组 | 是 | JuiceFS 挂载点列表，最多包含 5 个挂载点。 |
| `volumeName` | 字符串 | 是 | JuiceFS 文件系统名称，不是云沙箱 Volume 名称或 ID。 |
| `remoteDir` | 字符串 | 否 | JuiceFS 文件系统中要挂载的远端目录，例如 `/datasets/project-a`。如果目录不存在，挂载时会自动创建。建议显式设置。 |
| `mountDir` | 字符串 | 是 | Sandbox 内的本地挂载目录，必须是绝对路径，例如 `/mnt/juicefs`。 |
| `token` | 字符串 | 是 | JuiceFS 文件系统的访问 Token。 |
| `args` | 字符串数组 | 否 | 传递给 JuiceFS 客户端的额外挂载参数，可以为空数组。平台根据 `token` 和 `remoteDir` 管理 `--token` 和 `--subdir`，不能通过该字段覆盖这两个参数。 |
| `envs` | 对象 | 是 | 仅传递给 JuiceFS 挂载进程的环境变量，不会设置到 Sandbox 用户进程中。 |
| `envs.BASE_URL` | 字符串 | 是 | JuiceFS 企业版客户端访问的服务地址。字段名区分大小写。 |
| `envs.GOGC` | 字符串 | 否 | JuiceFS 挂载进程的 Go 垃圾回收调优参数。例如，`"50"` 可降低内存目标，但可能增加垃圾回收频率和 CPU 开销；通常无需设置。 |

`--conf-dir` 不是平台禁止的参数。如需自行指定，可在 `args` 中使用 `/tmp` 的规范化绝对子目录，例如 `["--conf-dir", "/tmp/juicefs-config"]`；未指定时，平台会为本次挂载生成独立的配置目录。

本文 Python 示例在未设置 `JUICEFS_REMOTE_DIR` 时显式使用 `/`。这是示例代码的默认值，不代表对服务端 API 缺省行为的说明。

## 安装 SDK

本文使用 Python E2B SDK 演示：

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install "e2b>=2.31.0"
```

运行示例前设置以下环境变量：

```bash
export E2B_API_KEY="<your-e2b-api-key>"
export E2B_API_URL="https://api.<region>.e2b.fc.aliyuncs.com"
export E2B_DOMAIN="<region>.e2b.fc.aliyuncs.com"
export E2B_TEMPLATE="<microvm-template-id>"

export FCSANDBOX_VPC_ID="vpc-xxxxxxxx"
export FCSANDBOX_SECURITY_GROUP_ID="sg-xxxxxxxx"
export FCSANDBOX_VSWITCH_ID="vsw-xxxxxxxx"

export JUICEFS_BASE_URL="http://<juicefs-service-address>:<port>"
export JUICEFS_VOLUME_NAME="<juicefs-volume-name>"
export JUICEFS_TOKEN="<juicefs-token>"
export JUICEFS_REMOTE_DIR="/"
export JUICEFS_MOUNT_DIR="/mnt/juicefs"
```

`JUICEFS_ARGS_JSON` 可选。未设置或设置为空字符串时，示例会按空数组 `[]` 处理。

## 创建带 JuiceFS 挂载的 Sandbox

以下示例通过 metadata 创建带 JuiceFS 挂载的 Sandbox，并验证文件读写。将代码保存为 `12_sandbox_juicefs.py`：

```python
import json
import os

from e2b import Sandbox


def require_env(name: str) -> str:
    value = os.environ.get(name, "").strip()
    if not value:
        raise RuntimeError(f"缺少环境变量: {name}")
    return value


def optional_env(name: str, default: str) -> str:
    return os.environ.get(name, "").strip() or default


def juicefs_args() -> list[str]:
    value = json.loads(os.environ.get("JUICEFS_ARGS_JSON", "").strip() or "[]")
    if not isinstance(value, list) or not all(isinstance(item, str) for item in value):
        raise RuntimeError("JUICEFS_ARGS_JSON 必须是字符串数组")

    managed_options = ("--token", "--subdir")
    for item in value:
        if any(item == option or item.startswith(f"{option}=") for option in managed_options):
            raise RuntimeError(f"JUICEFS_ARGS_JSON 不能覆盖平台托管参数: {item}")
    return value


mount_dir = optional_env("JUICEFS_MOUNT_DIR", "/mnt/juicefs")
marker_path = f"{mount_dir}/hello-juicefs.txt"

vpc_config = {
    "vpcId": require_env("FCSANDBOX_VPC_ID"),
    "securityGroupId": require_env("FCSANDBOX_SECURITY_GROUP_ID"),
    "vSwitchIds": [require_env("FCSANDBOX_VSWITCH_ID")],
}

juicefs_config = {
    "mountPoints": [
        {
            "volumeName": require_env("JUICEFS_VOLUME_NAME"),
            "remoteDir": optional_env("JUICEFS_REMOTE_DIR", "/"),
            "mountDir": mount_dir,
            "token": require_env("JUICEFS_TOKEN"),
            "args": juicefs_args(),
        }
    ],
    "envs": {
        "BASE_URL": require_env("JUICEFS_BASE_URL"),
    },
}

sandbox = None
marker_written = False

try:
    sandbox = Sandbox.create(
        template=require_env("E2B_TEMPLATE"),
        timeout=300,
        api_key=require_env("E2B_API_KEY"),
        api_url=require_env("E2B_API_URL"),
        domain=require_env("E2B_DOMAIN"),
        metadata={
            "fc.sandbox.network.vpc": json.dumps(vpc_config),
            "fc.sandbox.storage.juicefs": json.dumps(juicefs_config),
        },
    )

    sandbox.files.write(marker_path, "hello juicefs\n")
    marker_written = True
    content = sandbox.files.read(marker_path)
    if content != "hello juicefs\n":
        raise RuntimeError(f"文件内容不一致: {content!r}")
finally:
    try:
        if sandbox is not None and marker_written:
            sandbox.files.remove(marker_path)
    finally:
        if sandbox is not None:
            sandbox.kill()

print("JuiceFS 挂载读写验证成功")
```

运行示例：

```bash
python 12_sandbox_juicefs.py
```

## 挂载远端子目录

`remoteDir` 用于限制该挂载点可访问的 JuiceFS 目录范围。例如，将 `JUICEFS_REMOTE_DIR` 设置为 `/datasets/project-a` 后，Sandbox 中的 `JUICEFS_MOUNT_DIR` 对应此远端子目录，而不是文件系统根目录。

如果远端子目录不存在，挂载时会在 JuiceFS 文件系统中自动创建。执行以下命令挂载该子目录：

```bash
export JUICEFS_REMOTE_DIR="/datasets/project-a"
python 12_sandbox_juicefs.py
```

请使用以 `/` 开头的远端绝对路径，并确保 Token 具有创建和访问目标目录所需的权限。

## 行为说明

- `fc.sandbox.storage.juicefs` 和 `fc.sandbox.network.vpc` 的 metadata 值必须是 JSON 字符串，不能直接传入 Python 字典。
- `mountDir` 是 Sandbox 内的本地挂载目录，`remoteDir` 是 JuiceFS 文件系统中的远端目录。两者属于不同的路径空间。
- metadata 链路使用 `envs.BASE_URL` 指定 JuiceFS 服务地址。字段名区分大小写，不要写成 `baseURL`。
- `args` 是传递给 JuiceFS 客户端的额外挂载参数，可以是空数组。不要通过 `args` 覆盖平台托管的 `--token` 或 `--subdir`。`--conf-dir` 可以省略，也可以按“挂载配置”中的约束显式指定。
- Sandbox 暂停后再恢复时会恢复 JuiceFS 挂载，JuiceFS 数据不依赖 Sandbox 生命周期。

## 使用限制

- 创建 Sandbox 时，`fc.sandbox.network.vpc` 必须包含 `vpcId`、`securityGroupId` 和非空的 `vSwitchIds`。模板中的 VPC 配置不能替代该 metadata。
- JuiceFS 服务地址必须能从该 VPC 访问。
- 挂载目录必须是规范化的绝对 Unix 路径，不能为 `/`，不能包含前后空格或 `..`。
- 建议使用 `/home`、`/mnt`、`/tmp` 或 `/data` 的子目录，例如 `/mnt/juicefs`，避免覆盖模板内已有目录。
- 同一个 Sandbox 中的挂载目录不能重复。
- 不要在日志中打印完整 metadata、JuiceFS Token 或其他凭证。

## 常见问题

### 创建 Sandbox 提示 VPC 配置不完整

确认 `fc.sandbox.network.vpc` 包含 `vpcId`、`securityGroupId` 和非空的 `vSwitchIds`。metadata 中的值必须是 `json.dumps` 生成的 JSON 字符串。

### Sandbox 创建超时或挂载失败

检查 MicroVM 镜像中是否包含 JuiceFS 企业版客户端、RADOS 运行库和 FUSE，并检查 `BASE_URL`、VPC 路由、安全组、Token、文件系统名称和远端目录。保留 request ID 便于排查。

### `JUICEFS_ARGS_JSON` 可以为空吗

可以。本文示例将未设置或空字符串转换为 `[]`，并在 metadata 中始终传入数组。不要传入 JSON `null`，也不要通过该字段覆盖 `--token` 或 `--subdir`。

如需显式指定配置目录，可将 `JUICEFS_ARGS_JSON` 设置为 `["--conf-dir", "/tmp/juicefs-config"]`。该路径必须是 `/tmp` 下的规范化绝对子目录；未指定时，平台会生成独立的配置目录。

### JuiceFS 服务地址应该使用哪个字段

使用 `fc.sandbox.storage.juicefs` 中的 `envs.BASE_URL`。这是 metadata 直挂链路的字段；不要在该配置中使用 `baseURL`。
