# 自带阿里云 STS 注入

您可以自行提供 STS 或普通 AK/SK，在沙箱内使用占位 AK 调用业务 SDK，无需将真实凭证放入沙箱。支持多账号，无需配置 Workload Identity 或 RAM Role。

凭证由您获取并轮转；需要平台自动获取和刷新 STS 时，使用[托管阿里云 STS 注入](./03.托管阿里云%20STS%20注入.md)。

## 最小权限授权

> **重要：自带凭证重签不会自动收窄真实凭证的权限。** 真实 AK/SK 或 STS 不进入沙箱，但沙箱内代码仍可通过网关使用这些凭证已获授的权限。STS 会过期，也不能替代最小权限授权。

- 优先使用任务级 STS 临时凭证。在签发时，通过 RAM Role 权限和 Session Policy 将操作、资源范围限定到当前任务所需；仅需读取时，不授予写入或删除权限。使用普通 AK/SK 时，同样需要限制其所属身份的权限，不要使用主账号或高权限身份的凭证。
- 为每组凭证显式配置 `domains`，仅允许实际使用的服务域名；域名限制不能区分同一服务下的不同资源，仍需在凭证权限中限定具体资源。
- 不要直接授予沙箱访问共享数据库等敏感资源的权限，也不要将生产系统共用的高权限凭证配置为重签凭证。确需使用业务数据时，通过可信业务服务仅开放当前任务所需的数据或操作。

## 配置沙箱

在 `network.rules` 的固定配置键 `fc.sandbox.network.resign-credentials` 下配置凭证映射。每条映射的 `placeholder` 为占位 AK，`value` 为包含以下字段的 JSON 字符串：

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| `accessKeyId` | 是 | 真实 AccessKey ID |
| `accessKeySecret` | 是 | 真实 AccessKey Secret |
| `securityToken` | 否 | 使用 STS 时填写；普通 AK/SK 省略 |
| `domains` | 否 | 这组凭证允许重签的域名；省略或 `null` 默认 `["*.aliyuncs.com"]`，`[]` 禁用这组凭证，非空数组替换默认范围 |

`domains` 与托管 STS 的域名匹配语义一致：支持精确域名、`*.suffix` 子域名和 `!exact.host` 精确排除。排除优先，顺序无关；`*.suffix` 不包含根域。不支持裸 `*`、`!*.suffix`；只有排除项时不会自动补上默认允许范围。每组凭证独立配置，不能借用其他账号的域名权限。

例如 `["*.aliyuncs.com", "!mounted.oss-cn-hangzhou.aliyuncs.com"]` 允许使用这组凭证访问阿里云域名，但排除指定 bucket。域名排除只禁止使用这组凭证重签，不禁止网络访问；访问仍须通过 `allowOut` / `denyOut`。

以下代码在**沙箱外**运行，从环境变量读取账号 A、B 的凭证。账号 A 仅允许向示例 ECS endpoint 重签，账号 B 允许阿里云域名并排除指定 bucket，请替换为实际业务目标。示例通过 `*.aliyuncs.com` 放行网络；固定配置键无需加入 `allowOut`。

**Node.js**

```typescript
import { Sandbox } from "e2b";

function readCredential(prefix: string, domains: string[]) {
  const accessKeyId = process.env[`${prefix}_ACCESS_KEY_ID`];
  const accessKeySecret = process.env[`${prefix}_ACCESS_KEY_SECRET`];
  if (!accessKeyId || !accessKeySecret) {
    throw new Error(`${prefix}: AccessKey ID and Secret are required`);
  }
  return JSON.stringify({
    accessKeyId,
    accessKeySecret,
    securityToken: process.env[`${prefix}_SECURITY_TOKEN`],
    domains,
  });
}

const entries = [
  {
    placeholder: "sandbox-ak-account-a",
    value: readCredential("ACCOUNT_A", ["ecs.cn-hangzhou.aliyuncs.com"]),
  },
  {
    placeholder: "sandbox-ak-account-b",
    value: readCredential("ACCOUNT_B", ["*.aliyuncs.com", "!mounted.oss-cn-hangzhou.aliyuncs.com"]),
  },
];

const network = {
  allowInternetAccess: true,
  allowOut: ["*.aliyuncs.com"],
  denyOut: ["0.0.0.0/0"],
  rules: {
    "fc.sandbox.network.resign-credentials": [{
      transform: {
        headers: {
          "fc.sandbox.network.header-value-replacements": JSON.stringify(entries),
        },
      },
    }],
  },
};

const sandbox = await Sandbox.create({ network });
```

**Python**

```python
import json
import os
from e2b import Sandbox


def read_credential(prefix, domains):
    credential = {
        "accessKeyId": os.environ[f"{prefix}_ACCESS_KEY_ID"],
        "accessKeySecret": os.environ[f"{prefix}_ACCESS_KEY_SECRET"],
        "domains": domains,
    }
    token = os.environ.get(f"{prefix}_SECURITY_TOKEN")
    if token:
        credential["securityToken"] = token
    return json.dumps(credential, separators=(",", ":"))


entries = [
    {
        "placeholder": "sandbox-ak-account-a",
        "value": read_credential("ACCOUNT_A", ["ecs.cn-hangzhou.aliyuncs.com"]),
    },
    {
        "placeholder": "sandbox-ak-account-b",
        "value": read_credential("ACCOUNT_B", ["*.aliyuncs.com", "!mounted.oss-cn-hangzhou.aliyuncs.com"]),
    },
]

network = {
    "allow_internet_access": True,
    "allow_out": ["*.aliyuncs.com"],
    "deny_out": ["0.0.0.0/0"],
    "rules": {
        "fc.sandbox.network.resign-credentials": [{
            "transform": {
                "headers": {
                    "fc.sandbox.network.header-value-replacements":
                        json.dumps(entries, separators=(",", ":"))
                }
            }
        }]
    },
}

sandbox = Sandbox.create(network=network)
```

## 在沙箱内选择账号

在业务 SDK 的凭证参数中传入以下占位值，再正常调用 SDK：

| 访问身份 | AccessKey ID | AccessKey Secret |
| --- | --- | --- |
| 账号 A | `sandbox-ak-account-a` | `placeholder-secret` |
| 账号 B | `sandbox-ak-account-b` | `placeholder-secret` |

业务 SDK 的 AccessKey ID 必须与 `placeholder` 完全一致，以选择对应账号；AccessKey Secret 使用示例中的占位值。同一账号可访问多个已放行且命中该组 `domains` 的目标，服务端权限由真实凭证决定。占位 AK 不用于隔离沙箱内不同代码的权限。

## HTTPS 与重签检查

网络允许访问后，平台仅在 TLS 握手的 SNI 域名命中普通 Header 规则、托管 STS 域名或任意一组自带凭证的有效域名时解密 HTTPS；每组先处理自身排除项，再合并匹配结果。都未命中时原始 TLS 透传；没有 SNI 也不会仅因配置自带凭证而解密。

解密后选中占位 AK 对应的凭证时，请求域名和入口 SNI 必须同时命中该组 `domains`，否则返回 403，不回退托管 STS。HTTP 请求检查请求域名；OSS PostObject 提取到表单中的占位 AK 后执行相同检查。确认命中后重签失败也不会切换身份；未命中任何占位 AK 时继续原有托管 STS 或普通请求处理。

例如，只配置默认自带凭证时，`my.bad.com` 不触发 HTTPS 解密，也不会获得真实 STS。即使另有普通 Header 规则使该域名被解密，也不能使用不允许该域名的自带凭证重签。

## 支持范围

支持 ACS3（V3）、ROA V1、FC 2.0、RPC V1 和 OSS V1/V4，适用于阿里云服务、FC HTTP Trigger 及采用相同签名协议的服务。

- RPC：鉴权参数须放在 URL Query 中；支持 `application/x-www-form-urlencoded` 业务表单。
- OSS：支持 Header 鉴权、预签名 URL 和 PostObject 上传；PostObject 的鉴权表单字段须放在文件字段之前，不支持自定义 CNAME。

## 更新配置

沙箱运行期间可通过 `updateNetwork` 更新凭证、`domains` 或凭证映射，具体操作见[更新网络配置](../04.更新网络配置.md)。配置需整体提交；每个请求使用同一份域名范围和 AK/SK/token，配置更新生效后，已有解密连接的后续请求也按新配置检查。
