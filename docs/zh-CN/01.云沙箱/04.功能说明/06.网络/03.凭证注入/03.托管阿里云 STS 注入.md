# 托管阿里云 STS 注入

平台通过 Workload Identity 获取并自动刷新 STS。沙箱内使用占位凭证调用阿里云 SDK，无需自行管理 STS，也无需将真实凭证放入沙箱。

如需自行提供凭证或使用多个账号，请参见[自带阿里云 STS 注入](./08.自带阿里云%20STS%20注入.md)。

## 使用前提

在阿里云 **Agent Identity** 里先准备：

1. 创建一个 Workload Identity；
2. 为它关联一个用于访问阿里云资源的 RAM Role；
3. 为该 Role 配置业务所需的最小权限。

多个沙箱访问同一个 OSS Bucket 时，可共用一个 Role，再在创建每个沙箱时用 Policy 将权限收窄到各自的专属路径，无需为每个沙箱单独创建身份。

## 最小权限授权

> **重要：STS 的临时性和自动刷新不会自动收窄权限。** 真实凭证不进入沙箱，但沙箱内代码仍可通过网关，以关联 Role 的有效权限访问已放行的服务。请按任务需要授权，避免不可信代码滥用权限，造成数据泄露、篡改或删除。

- 为沙箱配置业务专用 Role，仅授予任务需要的操作；支持资源级授权时，将权限限定到具体资源，例如指定 OSS Bucket 下的任务专属路径。不要为方便接入而绑定 `AdministratorAccess` 等超出任务需要的策略。
- 创建沙箱时，使用 `fc.sandbox.identity.role.policy` 进一步限定当前任务的操作和资源范围；仅需读取数据时，不授予写入或删除权限。不配置 Session Policy 时，STS 权限不会因此自动缩小，仍需确保 Role 本身权限足够小。Session Policy 的权限收窄规则参见 [AssumeRole 的 Policy 参数](https://help.aliyun.com/zh/ram/developer-reference/api-sts-2015-04-01-assumerole)。
- 使用 `fc.sandbox.identity.role.domains` 将重签范围限定到实际使用的服务域名。域名限制不能替代资源权限控制，同一服务域名下的其他资源仍需通过权限策略隔离。
- 不要直接授予沙箱访问共享数据库等敏感资源的权限，也不要复用生产系统的高权限 Role。确需使用业务数据时，通过可信业务服务仅开放当前任务所需的数据或操作。

## 配置沙箱

创建沙箱时，在 `metadata` 里填一个身份名即可，其余用默认值：

**Node.js**

```typescript
import { Sandbox } from "e2b";

const sandbox = await Sandbox.create("code-interpreter-v1", {
  metadata: {
    "fc.sandbox.identity.name": "my-identity",
  },
});
```

**Python**

```python
from e2b import Sandbox

sandbox = Sandbox.create(
    template="code-interpreter-v1",
    metadata={"fc.sandbox.identity.name": "my-identity"},
)
```

默认会对发往 `*.aliyuncs.com`、可识别的阿里云签名请求做重签。

## 验证凭证注入

阿里云请求需要先由 SDK 生成签名，因此使用标准 SDK 和正常 Endpoint 进行验证。初始化时传入占位凭证，让 SDK 生成完整的签名请求，真正的签名由网关重做。

以下示例在沙箱内用 FC SDK 调用 `ListFunctions`。身份关联的 Role 需要有 `fc:ListFunctions` 权限；SDK 依赖可预装在模板中。

**Node.js**

```typescript
import assert from "node:assert/strict";
import FC from "@alicloud/fc20230330";
import OpenApi from "@alicloud/openapi-core";
import Darabonba from "@darabonba/typescript";

const config = new OpenApi.$OpenApiUtil.Config({
  accessKeyId: "fake-access-key-id",
  accessKeySecret: "fake-access-key-secret",
  securityToken: "fake-sts-token",
  endpoint: "<account-id>.cn-hangzhou-internal.fc.aliyuncs.com",
});
const client = new FC.default(config);
const result = await client.listFunctionsWithOptions(
  new FC.ListFunctionsRequest({ limit: 1 }),
  {},
  new Darabonba.RuntimeOptions({
    connectTimeout: 30_000,
    readTimeout: 30_000,
  }),
);
assert.equal(result.statusCode, 200);
```

**Python**

```python
from alibabacloud_fc20230330.client import Client as FCClient
from alibabacloud_fc20230330 import models as fc_models
from alibabacloud_tea_openapi.models import Config
from alibabacloud_tea_util.models import RuntimeOptions

config = Config(
    access_key_id="fake-access-key-id",
    access_key_secret="fake-access-key-secret",
    security_token="fake-sts-token",
    endpoint="<account-id>.cn-hangzhou-internal.fc.aliyuncs.com",
)
client = FCClient(config)
response = client.list_functions_with_options(
    fc_models.ListFunctionsRequest(limit=1),
    {},
    RuntimeOptions(connect_timeout=30_000, read_timeout=30_000),
)
assert response.status_code == 200
```

上面的 Endpoint 落在默认重签范围 `*.aliyuncs.com` 内，因此无需额外配置域名。将 `<account-id>` 和地域替换为实际值即可。

## 可选字段

需要更精细控制时，可添加以下字段。`metadata` 的值必须是字符串，因此对象或数组需要序列化为 JSON 字符串。

**Node.js**

```typescript
import { Sandbox } from "e2b";

const rolePolicy = {
  Version: "1",
  Statement: [{
    Effect: "Allow",
    Action: ["oss:GetObject", "oss:PutObject"],
    Resource: "acs:oss:*:*:agent-data/sandboxes/task-123/*",
  }],
};

const sandbox = await Sandbox.create("code-interpreter-v1", {
  metadata: {
    "fc.sandbox.identity.name": "my-identity",
    "fc.sandbox.identity.role.policy": JSON.stringify(rolePolicy),
    "fc.sandbox.identity.role.domains": JSON.stringify([
      "agent-data.oss-cn-hangzhou.aliyuncs.com",
    ]),
  },
});
```

**Python**

```python
import json

from e2b import Sandbox

role_policy = {
    "Version": "1",
    "Statement": [{
        "Effect": "Allow",
        "Action": ["oss:GetObject", "oss:PutObject"],
        "Resource": "acs:oss:*:*:agent-data/sandboxes/task-123/*",
    }],
}

sandbox = Sandbox.create(
    template="code-interpreter-v1",
    metadata={
        "fc.sandbox.identity.name": "my-identity",
        "fc.sandbox.identity.role.policy": json.dumps(role_policy),
        "fc.sandbox.identity.role.domains": json.dumps([
            "agent-data.oss-cn-hangzhou.aliyuncs.com"
        ]),
        },
)
```

| 字段 | 作用 |
| --- | --- |
| `fc.sandbox.identity.role.policy` | Session Policy，只能进一步收窄权限，不能扩权。有效权限 = Role 权限 ∩ 这个 Policy。 |
| `fc.sandbox.identity.role.domains` | 允许用该身份重签的目标域名列表。 |

重签域名的取值规则：

- 不配置：默认 `*.aliyuncs.com`；
- 配置非空数组：只认列表里的域名，不再包含默认范围；
- 配置空数组 `[]`：关闭重签；
- 支持精确域名和 `*.suffix` 通配（`*.example.com` 不匹配 `example.com` 本身）；
- 以 `!` 前缀的精确域名表示排除（黑名单）：命中的域名一律不重签，优先级高于其他匹配，可从通配范围里排除个别域名（如同时配置 `*.aliyuncs.com` 与 `!oss-cn-hangzhou.aliyuncs.com`）；`!` 仅支持精确域名，不支持 `!*.suffix`；
- 只填域名，不带协议、端口、路径；
- 创建后不能修改。

这些身份字段只在创建沙箱时配置，之后查询接口不返回，也不能通过 `updateNetwork` 修改。请在您自己的后端保存所用配置。

## 更新配置

`allowOut`、`denyOut` 等普通网络配置可以在沙箱运行期间更新，具体操作见[更新网络配置](../04.更新网络配置.md)。Workload Identity、Role Policy 和重签域名不能通过 `updateNetwork` 修改；需要更换时，请创建新沙箱。
