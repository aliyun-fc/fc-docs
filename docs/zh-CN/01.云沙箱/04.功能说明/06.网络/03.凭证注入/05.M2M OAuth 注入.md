# M2M OAuth 注入

M2M（Machine to Machine）OAuth 适用于没有终端用户参与、后台以应用自身身份访问 OAuth 服务的场景。Token 由平台自动获取并刷新，沙箱内正常发起请求，出网时由网关注入真实 Token。建议先阅读[凭证注入概述](./01.凭证注入总览.md)了解整体框架。

## 适用场景

M2M OAuth 适用于没有终端用户参与、后台用应用身份访问下游服务的场景，例如：

- 用企业内部应用身份访问钉钉开放平台；
- 用 Microsoft Entra ID 应用身份访问 Microsoft Graph；
- 用 Auth0 M2M 应用访问企业 API；
- 用 OAuth 2.0 `client_credentials` 流程访问内部服务。

它不涉及用户登录、授权页面、回调。与 API Key 的区别在于：M2M Token 有有效期，由平台自动刷新。用法与 API Key 基本一致，沙箱内正常发起请求，网关注入真实 Token，区别仅在于引用表达式不同，且可能需要配置 scopes 或 audience。

如果您自行完成 `client_credentials` 流程换取 Token，也可以用[自带凭证注入](./02.自带凭证注入.md)直接注入，但需要自行管理 Token 过期与刷新。

## 使用前提

在 Agent Identity 里先准备好：

1. 创建 Workload Identity，并关联一个可用的 RAM Role；
2. 给这个 Role 授予 `agentidentitydata:GetResourceOAuth2Token` 权限；
3. 创建 OAuth 凭证提供商，配好目标服务的 Token Endpoint、Client ID、Client Secret；
4. 允许该 Workload Identity 使用这个凭证提供商；
5. 确认目标服务的域名、Header 名称，以及是否需要 `scopes` 或 `audience`。

访问用户私有数据（个人文档、邮箱）时不能用 M2M，需使用[用户委托 OAuth 注入](./06.用户委托%20OAuth%20注入.md)。

## 配置沙箱

以钉钉为例，把 Agent Identity 里名为 `dingtalk-provider` 的 Token 注入到发往 `api.dingtalk.com` 的请求：

**Node.js**

```typescript
import { Sandbox } from "e2b";

const sandbox = await Sandbox.create("code-interpreter-v1", {
  metadata: {
    "fc.sandbox.identity.name": "my-agent",
  },
  network: {
    allowOut: ["api.dingtalk.com"],
    denyOut: ["0.0.0.0/0"],
    rules: {
      "api.dingtalk.com": [{
        transform: {
          headers: {
            "x-acs-dingtalk-access-token":
              "${fc.sandbox.identity.oauth.m2m:dingtalk-provider}",
          },
        },
      }],
    },
  },
});
```

**Python**

```python
from e2b import Sandbox

sandbox = Sandbox.create(
    template="code-interpreter-v1",
    metadata={"fc.sandbox.identity.name": "my-agent"},
    network={
        "allow_out": ["api.dingtalk.com"],
        "deny_out": ["0.0.0.0/0"],
        "rules": {
            "api.dingtalk.com": [{
                "transform": {
                    "headers": {
                        "x-acs-dingtalk-access-token":
                            "${fc.sandbox.identity.oauth.m2m:dingtalk-provider}"
                    }
                }
            }]
        },
    },
)
```

引用表达式格式为 `${fc.sandbox.identity.oauth.m2m:<提供商名>}`，它明确选择 M2M 流程，不会自动切到用户委托。钉钉企业内部应用通常无需额外传 scopes。

## 验证凭证注入

在沙箱内直接请求目标服务，无需携带认证 Header：

```bash
curl -i https://api.dingtalk.com/v1.0/contact/departments/1
```

请求出站时，网关会注入 `x-acs-dingtalk-access-token: <真实 Token>`。如果 SDK 强制要求传入 Token，可使用占位值，网关会覆盖对应 Header。

## 配置 scopes 或 audience

有些 Provider 要求 Token 请求带 `scopes` 或 `audience`。这类参数通过一个保留控制项 `@fc.sandbox.identity` 提交，它不是真实域名，也不会作为 Header 发出，只用来携带取 Token 时的参数。

Microsoft Graph（需要 scopes）：

**Node.js**

```typescript
const network = {
  allowOut: ["graph.microsoft.com"],
  denyOut: ["0.0.0.0/0"],
  rules: {
    "@fc.sandbox.identity": [{
      transform: { headers: {
        "fc.sandbox.identity.oauth.m2m.options": JSON.stringify({
          "microsoft-graph": { scopes: ["https://graph.microsoft.com/.default"] },
        }),
      } },
    }],
    "graph.microsoft.com": [{
      transform: { headers: {
        Authorization: "Bearer ${fc.sandbox.identity.oauth.m2m:microsoft-graph}",
      } },
    }],
  },
};
```

**Python**

```python
import json

network = {
    "allow_out": ["graph.microsoft.com"],
    "deny_out": ["0.0.0.0/0"],
    "rules": {
        "@fc.sandbox.identity": [{
            "transform": {"headers": {
                "fc.sandbox.identity.oauth.m2m.options": json.dumps({
                    "microsoft-graph": {
                        "scopes": ["https://graph.microsoft.com/.default"]
                    }
                })
            }}
        }],
        "graph.microsoft.com": [{
            "transform": {"headers": {
                "Authorization":
                    "Bearer ${fc.sandbox.identity.oauth.m2m:microsoft-graph}"
            }}
        }]
    },
}
```

Auth0（需要 audience）：把上面的 options 值换成：

**Node.js**

```typescript
const m2mOptions = JSON.stringify({
  "company-auth0": { customParameters: { audience: "https://api.example.com" } },
});
```

**Python**

```python
import json

m2m_options = json.dumps({
    "company-auth0": {
        "customParameters": {"audience": "https://api.example.com"}
    }
})
```

options 的 key 是 Provider 名称，要和引用表达式里的名字逐字一致（区分大小写）。

## 更新配置

沙箱运行期间可通过 `updateNetwork` 修改 Provider、注入规则或 scopes/audience，通用操作见[更新网络配置](../04.更新网络配置.md)。

M2M options 按字段处理：省略保留、提交则替换整个 M2M Provider 表、`{}` 清空。因此要保留其他 Provider 时需一起提交。
