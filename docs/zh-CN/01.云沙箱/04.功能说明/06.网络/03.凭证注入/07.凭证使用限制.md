# 凭证使用限制

本文统一说明凭证注入的网络放行、HTTPS 证书信任、连接数、配置限制和安全要求。使用各凭证注入方式前，请先了解以下内容。

## 网络放行

`network.rules` 只负责改写 Header，不会放开网络访问。一个域名要既在 `allowOut` 里通过网络策略，又命中 `rules`，请求才既能发出，又携带凭证。

访问阿里云服务时，`metadata` 中的重签域名同样不会自动放开网络，仍需通过 `allowOut` 等网络策略允许访问。

## HTTPS 证书信任

平台需要解密 HTTPS 才能改写 Header，因此会在节点出口代理上做 TLS inspection，用平台 CA 为目标域名动态签发证书。如果沙箱客户端不信任平台 CA，HTTPS 会报证书错误。

- 官方模板和受支持的 Debian/Ubuntu 自定义模板已配好平台 CA，curl、Python requests、Node.js 可直接使用。
- Java、Firefox/NSS、只读 OpenSSL CApath 的应用、非 Debian/Ubuntu 镜像以及使用私有 trust bundle 或证书 pinning 的客户端需要自行配置信任。
- 官方镜像版本需不低于 `v0.0.44`；自定义镜像需在 2026-08-15 平台发布之后构建，否则可能没有平台 CA。
- 目标服务使用自签证书或私有 CA 时，当前不支持上传自定义上游 CA，也不会跳过校验。
- 当前不支持 ECH、QUIC/HTTP3、显式 CONNECT proxy、上游 mTLS、WebSocket/HTTP Upgrade 和非 80/443 端口。

Java 客户端可将 `/usr/local/share/ca-certificates/e2b-ca.crt` 导入 JVM `cacerts`。

## 连接数限制

配置 `network.rules` 后，经平台出口代理的 HTTP/HTTPS 共用一个活跃 TCP 连接计数，每个沙箱最多同时 2000 条连接。达到上限后新连接被拒绝或重置，旧连接关闭后可再建。

该限制按 TCP 连接数计算，不按请求数或 RPS 计算。使用 keep-alive 或 HTTP/2 复用可减少占用。2000 是当前固定上限，不能调整。

## 配置限制

| 项目 | 限制 |
| --- | --- |
| 目标域名 | 最多 10 个；仅精确 DNS 域名，不匹配子域，不支持 wildcard、IP、CIDR、URL、端口、路径 |
| 每个域名 | 必须恰好 1 条 rule |
| 普通 Header | 每条最多 20 个；name 1..64 bytes；value 最多 2048 bytes |
| 整体 rules | 序列化后最多 64 KiB |
| replacement | 每域名最多 16 个；每沙箱最多 64 个 |
| placeholder | 8..128 bytes；只允许字母、数字、`_`、`.`、`-`；不能等于真实 value、不能重复、不能互为子串 |

以下 Header 不支持配置或不执行替换：`Host`、`Content-Length`、`Transfer-Encoding`、`Connection`、`Upgrade`、代理认证 Header、`x-envoy-*`、`x-forwarded-*` 等路由或帧控制 Header。受限集合可能随版本调整。

## 请求处理范围

当前只改写出站 HTTP/HTTPS 请求的 Header，不能修改 Body、URL 或响应。

## 托管凭证

- Agent Identity 托管的 API Key 和 OAuth Token 只注入到目标服务，不进入沙箱。查询沙箱信息只返回引用表达式和非敏感 options，不返回真实凭证。
- 目标服务会收到真实凭证，请确认目标可信，并为凭证配置最小权限。
- M2M OAuth Token 由平台按有效期自动刷新，目标服务返回的 401/403 会原样透传，平台不会因此立即刷新或自动重放请求。
- 用户委托 OAuth 的用户 JWT、UserId 和真实 Token 不进入沙箱，也不通过查询接口返回。不同用户的凭证相互隔离，不要把 JWT 写入业务日志或沙箱代码。

## 阿里云请求重签

- 重签域名只决定哪些请求可以重签，不会放开网络访问；目标域名仍需通过 `allowOut` 等网络策略放行。
- 支持 ACS3、RPC、ROA、FC 2.0、OSS V1 和 OSS V4 签名协议。使用标准阿里云 SDK 时通常无需自行处理签名。
- 不要在不支持的协议中携带真实 AK，这类请求不会由平台保护。

## 安全建议

- 只在可信控制端读取和提交真实凭证，不要写入代码仓库；使用 Secret 管理、CI Secret 或短期业务凭据。
- 优先使用 HTTPS。HTTP 离开节点代理后是明文，凭证可能在链路上暴露。
- 使用短期、最小权限、按租户或会话隔离、可撤销的凭据。
- 只为真实目标配置精确域名，确认目标不会回显或记录认证 Header。
- 保护创建、更新、查询接口的权限，不要打印完整 `network.rules`；占位符本身不应包含真实凭据。
- 立即撤销凭据时，更新网络配置清空对应规则，并在凭据系统中撤销或轮换。强撤销场景不能只靠删除规则，需覆盖已有长连接和控制面不确定状态。
