# 四层网络直连

四层网络直连允许专有网络 VPC 内的客户端通过私网 `IP:Port` 访问 Sandbox 中运行的 TCP 服务。该功能适合 VNC、SSH、数据库、缓存和自定义二进制协议等需要 TCP 长连接的场景。

使用四层网络直连时，先在创建 Sandbox 时配置入口 VPC，再为 Sandbox 内的业务端口申请 endpoint。申请成功后，客户端使用返回的 `host` 和 `port` 建立 TCP 连接。

HTTP/HTTPS、Web UI 和普通 API 场景可以继续使用 `sandbox.getHost(port)` 提供的七层访问地址。两种接入方式的差异如下：

| 接入方式 | 访问地址 | 协议 | 适用场景 |
| --- | --- | --- | --- |
| 四层网络直连 | 私网 `IP:Port` | TCP | VNC、SSH、数据库、缓存和自定义 TCP 服务 |
| 七层访问地址 | HTTPS 域名 | HTTP、HTTPS、WebSocket | Web UI、服务预览和 HTTP API |

## 使用限制

| 限制项 | 说明 |
| --- | --- |
| 开通范围 | 当前按账号和地域邀测。使用前请提交阿里云工单申请开通。 |
| 网络范围 | endpoint 仅提供 VPC 私网地址。客户端需要位于入口 VPC，或位于已与入口 VPC 连通的网络。 |
| 协议 | 仅支持 TCP。 |
| Sandbox 状态 | Sandbox 处于 `running` 状态时可以申请 endpoint。 |
| 内部端口 | 取值范围为 `1`～`65535`。`49983` 是系统保留端口。 |
| 外部端口 | 由平台动态分配，可能与内部端口不同。 |
| 单个 Sandbox 四层端口映射规则数 | 默认最多 4 条，即 `AllocPortForward` 创建的映射规则数量。实际上限以账号配置为准，如需调整，请联系我们。 |
| endpoint 生命周期 | endpoint 与 Sandbox 生命周期关联，Sandbox 被删除或到期后自动回收。 |
| 端口映射释放 | 当前不支持单独删除某个端口映射。 |
| 访问鉴权 | 四层流量不经过七层访问令牌校验，业务服务需要自行实现身份认证和访问控制。 |

## 前提条件

使用四层网络直连前，请完成以下准备工作：

- 账号和目标地域已开通四层网络直连。
- 已在目标地域创建 VPC、vSwitch 和安全组，三者属于同一账号和地域。
- vSwitch 具有充足的可用 IP 地址。建议配置两个或更多 vSwitch，以提高可用性。
- 业务客户端位于入口 VPC，或已通过云企业网、VPN、专线等方式与入口 VPC 连通。
- 已获取目标地域的云沙箱 API Key 和 API 地址。API Key 的获取方式，请参见[创建 API Key](../../01.开始使用/03.创建%20API%20Key.md)。
- Sandbox 中的 TCP 服务监听 `0.0.0.0:<internalPort>`。

## 工作原理

四层网络直连的创建和访问过程如下：

1. 创建 Sandbox 时，通过 metadata 指定入口 VPC、vSwitch 和安全组。
2. Sandbox 进入 `running` 状态后，为业务内部端口申请 endpoint。
3. 平台返回 endpoint 的 `host` 和 `port`，并将该地址收到的 TCP 流量转发到 Sandbox 的 `internalPort`。
4. 客户端从可访问入口 VPC 的网络连接该 endpoint。

入口 VPC 用于承载客户端到 Sandbox 的入站流量。Sandbox 主动访问 VPC 资源时使用出口 VPC。两项配置相互独立：

- 入口 VPC 使用 `fc.sandbox.network.portforwardvpc`。
- 出口 VPC 使用 `fc.sandbox.network.vpc`，配置方法请参见[VPC 网络配置](../07.FC%20扩展/02.VPC%20网络配置.md)。

如果入站和出站流量使用同一个 VPC，仍需分别设置两个 metadata 字段。

## 使用 HTTP API

以下请求均发送到目标地域的云沙箱 API 地址：

```text
https://api.<region>.e2b.fc.aliyuncs.com
```

### 1. 创建 Sandbox 并配置入口 VPC

入口 VPC 使用以下 metadata 字段：

```text
fc.sandbox.network.portforwardvpc
```

字段值必须是序列化后的 JSON 字符串，字符串中的对象结构如下：

```json
{
  "vpcId": "vpc-xxxxxxxx",
  "vSwitchIds": ["vsw-xxxxxxxx"],
  "securityGroupId": "sg-xxxxxxxx"
}
```

字段说明：

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| `vpcId` | 是 | 四层 endpoint 所在的入口 VPC。 |
| `vSwitchIds` | 是 | endpoint 使用的 vSwitch ID 列表。 |
| `securityGroupId` | 是 | 控制 endpoint 入方向访问范围的安全组。 |

创建 Sandbox：

```http
POST /sandboxes
X-API-KEY: <your-api-key>
Content-Type: application/json
```

```json
{
  "templateID": "base",
  "timeout": 3600,
  "metadata": {
    "fc.sandbox.network.portforwardvpc": "{\"vpcId\":\"vpc-xxxxxxxx\",\"vSwitchIds\":[\"vsw-xxxxxxxx\"],\"securityGroupId\":\"sg-xxxxxxxx\"}"
  }
}
```

创建成功表示入口网络配置已生效，业务端口仍需在 Sandbox 进入 `running` 状态后单独申请。

### 2. 在 Sandbox 中启动 TCP 服务

业务服务需要监听所有网卡和计划使用的内部端口。例如，VNC 服务使用 `5900` 端口时，应监听：

```text
0.0.0.0:5900
```

如果服务仅监听 `127.0.0.1`，四层 endpoint 无法访问该服务。

### 3. 申请 endpoint

为运行中的 Sandbox 申请 `5900` 端口的四层 endpoint：

```http
POST /sandboxes/{sandboxID}/fc-l4-ip
X-API-KEY: <your-api-key>
Content-Type: application/json
```

```json
{
  "internalPort": 5900,
  "protocol": "tcp"
}
```

请求参数：

| 参数 | 是否必填 | 说明 |
| --- | --- | --- |
| `internalPort` | 是 | Sandbox 内业务服务监听的端口，范围为 `1`～`65535`，且不能为 `49983`。 |
| `protocol` | 否 | 当前仅支持 `tcp`。省略或传空字符串时默认为 `tcp`。 |

响应示例：

```json
{
  "host": "172.16.0.10",
  "port": 30000,
  "internalPort": 5900,
  "protocol": "tcp"
}
```

其中：

- `host` 是入口 VPC 内的私网 IP 地址。
- `port` 是平台分配的外部端口。
- `internalPort` 是 Sandbox 内的业务端口。
- `protocol` 是 endpoint 使用的传输协议。

每次申请都会返回当前有效的 endpoint。客户端应使用响应中的 `host` 和 `port`，不要使用 `internalPort` 替代响应中的 `port`。

### 4. 配置安全组并连接服务

在入口安全组中添加入方向规则，允许业务客户端的 IP 地址或 CIDR 访问 endpoint 响应中的 `port`。建议只开放业务所需的来源范围和端口。

以下示例测试 endpoint 的 TCP 连通性：

```bash
nc -vz 172.16.0.10 30000
```

实际业务客户端使用相同的 `host` 和 `port` 建立连接。例如，VNC 客户端连接 `172.16.0.10:30000` 后，流量会转发到 Sandbox 的 `5900` 端口。

## 安全建议

- 为 SSH、VNC、数据库、自定义管理接口等服务配置应用层认证。
- 使用安全组将访问来源限制为可信客户端 IP 或业务网段。
- 为数据库账号、SSH 密钥和应用 Token 设置最小权限与合理的有效期。
- 将凭证保存在安全的凭证管理服务中，避免写入代码、模板、metadata 和日志。
- 使用业务日志或审计日志记录连接行为和认证结果。

四层流量不经过 `trafficAccessToken` 或 `envdAccessToken` 校验。`secure: true` 和 `network.allowPublicTraffic` 配置只作用于对应的七层链路，不能替代四层业务服务自身的认证。

## 生命周期说明

- **Pause**：Sandbox 进入暂停状态后，新的 endpoint 申请会返回状态冲突。
- **Resume**：等待 Sandbox 恢复为 `running`，再次调用 endpoint API 获取当前地址，并重新建立 TCP 连接。
- **Kill 或到期**：endpoint 随 Sandbox 生命周期自动回收。
- **重复申请**：同一内部端口可以重复申请。每次调用均以最新响应作为当前 endpoint。

## 常见问题

| 现象 | 可能原因 | 处理方式 |
| --- | --- | --- |
| 创建 Sandbox 时返回 `invalid port forward vpc config` | VPC、vSwitch 或安全组配置不完整，资源不属于同一账号或地域 | 检查三个资源 ID、地域和账号归属。 |
| 申请 endpoint 时返回 `l4 direct is not enabled for this account` | 当前账号或地域未开通四层网络直连 | 提交阿里云工单申请开通。 |
| 返回 `l4 endpoint is not ready` | 入口 VPC 未配置，或 endpoint 网络资源仍在创建 | 确认创建请求包含入口 VPC 配置；资源创建中时，等待后进行有限次数重试。 |
| 返回 `port limit exceeded` | 当前 Sandbox 已达到四层端口映射规则数量上限 | 复用现有映射规则。如需调整，请联系我们。 |
| 返回 `internalPort 49983 is reserved for envd` | 使用了系统保留端口 | 将业务服务改用其他端口。 |
| 返回 `conflict` | Sandbox 当前未处于 `running` 状态 | 等待 Sandbox 完成创建或恢复后重试。 |
| endpoint 从客户端不可达 | 客户端与入口 VPC 网络不通、安全组未放行外部端口，或服务未监听所有网卡 | 检查网络连通性、安全组入方向规则和服务监听地址。 |
| endpoint 可连接但认证失败 | 业务服务的账号、密钥或访问策略未通过 | 检查业务服务自身的认证配置。 |
