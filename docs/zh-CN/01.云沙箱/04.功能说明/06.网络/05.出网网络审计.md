# 出网网络审计

出网网络审计记录沙箱尝试访问的网络目标，以及出网策略的放行或拒绝结果。日志投递到您的日志服务（SLS）。

[出网流量控制](./02.出网流量控制.md)负责限制沙箱可以访问哪些目标，网络审计帮助您了解这些限制在运行时的执行情况。

## 使用前提

1. 为沙箱所用模板配置同地域的 SLS Project 和 Logstore，参见[模板文档](../02.模板/03.通过%20OpenAPI%20构建和管理模板.md)中的“日志配置”。
2. 为沙箱配置 `allowOut`、`denyOut` 或 `allowInternetAccess: false` 等出网访问控制。当前审计随出网访问控制生效；未配置访问控制，或只有凭证注入规则时，不会因此开启本项审计。

## 日志字段

### 公共字段

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| `logType` | 日志类型，固定为 `networkAudit`。 | `networkAudit` |
| `sandboxID` | 产生该记录的沙箱 ID，用于关联业务任务。 | `sbx-example` |
| `__time__` | SLS 保留的日志时间，使用审计事件发生时间，精度为秒；不是单独的日志正文键。 | 在 SLS 时间列查看 |
| `__topic__` | SLS 保留的日志主题。 | `fc-network-policy-audit` |

### 网络访问和 DNS 查询字段

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| `protocol` | 观测到的协议，取值为 `http`、`https`、`tcp`、`udp`、`icmp`、`other` 或 `dns`。 | `https` |
| `destination` | HTTP Host、TLS SNI、DNS 查询域名，或目标 IP。无法取得 HTTP Host/TLS SNI 时使用目标 IP；普通 TCP/UDP 等记录使用目标 IP。 | `api.example.com` |
| `destinationIP` | 网络访问在策略判定处观测到的目标 IP。DNS 查询记录不包含此字段。 | `203.0.113.10` |
| `destinationPort` | HTTP、HTTPS、TCP、UDP 网络访问的目标端口。DNS、ICMP 和其他协议记录不包含此字段。 | `443` |
| `action` | 策略结果：`allow` 表示放行，`deny` 表示拒绝。 | `allow` |
| `dnsQueryType` | 仅 DNS 记录包含，表示查询类型。 | `A`、`AAAA` |
| `dnsTransport` | 仅 DNS 记录包含，表示查询使用的传输协议。 | `udp`、`tcp` |

### 审计限流通知字段

审计记录产生过快时，可能收到 `eventType: auditThrottled` 通知。该通知表示部分审计记录因限流未被保留。它包含公共字段和下列字段，不包含 `action`、`protocol`、`destination` 等访问结果字段。分析访问趋势或排查安全事件时，应同时查看此类通知，避免把不完整的记录当成全量访问记录。

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| `eventType` | 事件类型，固定为 `auditThrottled`。 | `auditThrottled` |
| `reason` | 限流原因，固定为 `rateLimit`。 | `rateLimit` |
| `suppressedRecords` | 本次通知覆盖的限流期间未保留的审计记录数，不是丢弃的网络报文数。 | `51` |
| `rateLimit` | 单个审计采集进程针对该实例的明细接纳上限，单位为条/秒；不是该沙箱全部审计记录合计的上限，以日志实际值为准。 | `250` |
| `windowStart` | 本次限流期间首条未保留记录的时间，UTC。 | `2026-10-15T08:00:00.001Z` |
| `windowEnd` | 本次限流期间末条未保留记录的时间，UTC。 | `2026-10-15T08:00:05.123Z` |

## 日志示例

以下 JSON 展示 SLS 日志正文的主要字段，省略函数公共上下文和 SLS 保留字段。域名、IP 和沙箱 ID 均为示例值。

### HTTPS 访问被放行

```json
{
  "logType": "networkAudit",
  "sandboxID": "sbx-example",
  "protocol": "https",
  "destination": "api.example.com",
  "destinationIP": "203.0.113.10",
  "destinationPort": "443",
  "action": "allow"
}
```

这条记录表示沙箱对该目标的访问被网络策略允许。若任务仍然失败，应继续检查 TLS、服务鉴权和应用响应。

### HTTP 访问被拒绝

```json
{
  "logType": "networkAudit",
  "sandboxID": "sbx-example",
  "protocol": "http",
  "destination": "blocked.example.com",
  "destinationIP": "198.51.100.20",
  "destinationPort": "80",
  "action": "deny"
}
```

这条记录表示沙箱访问 `blocked.example.com` 的 HTTP 请求被网络策略拒绝。

### TCP 访问被拒绝

```json
{
  "logType": "networkAudit",
  "sandboxID": "sbx-example",
  "protocol": "tcp",
  "destination": "198.51.100.20",
  "destinationIP": "198.51.100.20",
  "destinationPort": "5432",
  "action": "deny"
}
```

这条记录表示沙箱访问该 IP 的 5432 端口时被网络策略拒绝。可以结合任务预期，判断是否遗漏了数据库访问配置，或出现了不应发生的外联尝试。

## 常见问题

### 模板已开启日志，如何在创建沙箱时关闭审计日志？

创建沙箱时，在 `metadata` 的 `fc.sandbox.observability.logging` 中将 `enableInstanceMetrics` 设为 `false`：

```json
{
  "metadata": {
    "fc.sandbox.observability.logging": "{\"project\":\"your-project\",\"logstore\":\"your-logstore\",\"enableInstanceMetrics\":false}"
  }
}
```

该 metadata 值是 **JSON 字符串**，`project` 和 `logstore` 均需填写，可使用模板已配置的值。此设置对本次创建的沙箱生效，也会关闭实例级别指标日志。

### 为什么只配置 IP/CIDR 时，HTTP/HTTPS 日志里看不到域名？

IP/CIDR 规则根据目标 IP 判定放行或拒绝。未启用凭证注入等需要应用层代理的功能时，流量在四层处理，不解析 HTTP Host 或 TLS SNI。因此，即使访问 HTTP/HTTPS，日志也会记录为 `tcp`，`destination` 为目标 IP。

例如，仅配置 `denyOut: ["0.0.0.0/0"]` 后访问 `https://api.example.com`，TCP 连接在建立阶段就被拒绝，日志记录为 `tcp` / `deny`，无法取得 Host/SNI。

配置域名访问规则后，HTTP 80 和 TLS 443 流量会进行域名检查，取得的有效 Host/SNI 会显示在 `destination` 中。

### 为什么非 80/443 端口的流量看不到 Host/SNI？

当前仅对 TCP 80 端口的 HTTP 和 TCP 443 端口的 TLS 流量解析 Host/SNI。其他端口即使承载 HTTP/HTTPS，例如 `http://api.example.com:8080` 或 `https://api.example.com:8443`，也按 TCP 流量记录，`destination` 为目标 IP，不显示域名。UDP 流量（如 UDP 443）也不会解析 HTTP Host 或 TLS SNI。

### 为什么访问 443 端口有时记录为 `tcp` 或 `udp`？

`https` 表示从 TLS SNI 等握手信息识别出的访问，不表示 TLS 握手或 HTTP 请求已经成功；仅使用 443 端口的流量也可能记录为 `tcp` 或 `udp`。

### 什么情况下 `destinationIP` 与代理最终连接的 IP 不同？

`destinationIP` 记录沙箱尝试连接的目标 IP。当 HTTP Host 或 TLS SNI 命中域名白名单时，代理会自行解析该域名，并连接解析得到的 IP，防止客户端伪造 Host/SNI 绕过白名单。此时，`destinationIP` 可能与代理最终连接的 IP 不同。

例如，沙箱尝试连接 `203.0.113.10`，TLS SNI 为白名单域名 `api.example.com`；代理解析该域名后连接到 `203.0.113.20`。日志中的 `destinationIP` 仍为 `203.0.113.10`，表示沙箱原本尝试访问的地址。
