# 配置 RAM 用户权限

企业通常由一个阿里云账号统一持有云资源，再通过 RAM 用户、RAM 用户组或 RAM Role 分配管理权限。本文根据常见使用场景，介绍如何将云沙箱权限限制到指定资源组、Team 或资源类型。用户习惯所说的“主账号”和“子账号”，在本文中分别称为“阿里云账号”和“RAM 用户”。

## 先确认使用哪种凭证

| 使用方式 | 使用的凭证 | 是否需要配置 FCSandbox RAM 权限 |
| --- | --- | --- |
| 登录控制台管理 Team、API Key 等资源 | 阿里云账号或 RAM 用户 | 是 |
| 调用 FCSandbox OpenAPI | 阿里云 AK 或 STS 临时凭证 | 是 |
| 通过 E2B SDK、E2B CLI 或兼容 HTTP API 创建和访问 Sandbox | 云沙箱 API Key | 否 |

每个云沙箱 API Key 绑定一个 Team。RAM 权限策略控制控制台和 OpenAPI 的访问范围，不会进一步限制已经签发的 API Key。因此，只通过 E2B SDK 使用 Sandbox 的业务应用通常不需要 FCSandbox RAM 权限。

本文不介绍 Sandbox 访问 OSS、AgenticFS 等其他云服务所需的函数执行 RAM Role。相关配置参见[使用 Volume 挂载 OSS](../04.功能说明/07.FC%20扩展/07.使用%20Volume%20挂载%20OSS.md)和[使用 Volume 挂载 AgenticFS](../04.功能说明/07.FC%20扩展/08.使用%20Volume%20挂载%20AgenticFS.md)。

## 规划资源和人员权限

多团队共用一个阿里云账号时，建议按“业务团队 × 环境”划分资源组，按项目划分 Team。例如：

```text
阿里云账号
├── 资源组：团队 A 测试
│   ├── Team：数据分析测试
│   └── Team：机器学习测试
├── 资源组：团队 A 生产
│   ├── Team：数据分析生产
│   └── Team：机器学习生产
├── 资源组：团队 B 测试
└── 资源组：团队 B 生产
```

推荐按以下方式分配权限：

| 身份 | 推荐权限范围 |
| --- | --- |
| 云沙箱平台管理员 | 账号下全部云沙箱资源 |
| 业务团队管理员 | 本团队的测试和生产资源组 |
| 项目开发人员 | 指定测试 Team |
| 生产运维人员 | 指定生产 Team |
| 自动化程序 | 指定 Team 下实际需要管理的资源类型 |
| 业务应用 | 仅持有对应 Team 的云沙箱 API Key |

资源组适合作为团队和环境的权限边界，Team 适合作为项目边界。测试和生产环境应使用不同资源组，避免开发人员因拥有测试资源权限而误操作生产资源。Team 及其资源关系参见[创建 Team](02.创建%20Team.md)。

## 配置 RAM 权限

1. 使用阿里云账号或具备 RAM 管理权限的 RAM 用户登录 [RAM 控制台](https://ram.console.aliyun.com/)。
2. 创建自定义权限策略，并选择**脚本编辑**。具体操作参见[创建 RAM 自定义权限策略](https://help.aliyun.com/zh/ram/create-a-custom-policy)。
3. 根据下面的场景修改策略中的地域、账号 ID、资源组 ID 和 Team ID。
4. 将策略授权给目标 RAM 用户、RAM 用户组或 RAM Role。具体操作参见[管理权限策略授权](https://help.aliyun.com/zh/ram/manage-policy-references)。
5. 使用目标 RAM 身份验证授权结果，确认所需操作可以执行，非授权范围仍被拒绝。

### 场景一：管理账号下全部云沙箱资源

适用于统一管理所有 Team 和资源的平台管理员。以下策略仅授予指定账号和地域下的 FCSandbox 权限，不包含函数计算或其他云服务权限：

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "fcsandbox:*",
      "Resource": "acs:fcsandbox:<region>:<account-id>:*"
    }
  ]
}
```

### 场景二：管理业务团队的资源组

适用于管理一个业务团队的测试和生产环境，但不能访问其他团队的管理员。以下示例将权限限制到两个资源组：

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "fcsandbox:*",
      "Resource": "acs:fcsandbox:<region>:<account-id>:*",
      "Condition": {
        "StringEquals": {
          "acs:ResourceGroupId": [
            "<test-resource-group-id>",
            "<production-resource-group-id>"
          ]
        }
      }
    }
  ]
}
```

RAM 用户登录控制台后，需要切换到已授权的资源组。调用列表接口时，也应传入对应的 `resourceGroupID`。

### 场景三：只管理指定 Team

适用于项目开发人员或生产运维人员。以下策略允许管理指定 Team 及其子资源，但不能创建其他 Team：

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "fcsandbox:*",
      "Resource": [
        "acs:fcsandbox:<region>:<account-id>:teams/<team-id>",
        "acs:fcsandbox:<region>:<account-id>:teams/<team-id>/*"
      ]
    }
  ]
}
```

Team 本身和 Team 子资源使用不同的 ARN，因此需要同时配置两条 Resource。该策略不包含账号级 Team 列表权限。若用户需要通过控制台选择 Team，可以增加资源组范围的 `fcsandbox:ListTeams` 权限，但该用户将能看到同一资源组内的 Team 列表。需要严格限制 Team 可见范围时，建议为该项目使用独立资源组。

### 场景四：自动化程序只管理指定 Team 的 Volume

适用于只负责创建、查询和清理 Volume 的自动化程序。建议使用 RAM Role 和 STS 临时凭证：

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "fcsandbox:CreateVolume",
        "fcsandbox:ListVolumes",
        "fcsandbox:GetVolume",
        "fcsandbox:UpdateVolume",
        "fcsandbox:DeleteVolume"
      ],
      "Resource": "acs:fcsandbox:<region>:<account-id>:teams/<team-id>/volumes/*"
    }
  ]
}
```

调用 Volume 接口时需要传入对应的 Team ID。若不传 Team ID，列表接口会按账号下的 Volume 集合鉴权，上述 Team 级策略不会匹配。

### 场景五：业务应用只创建和访问 Sandbox

由管理员为业务应用创建独立 Team 和 API Key，应用通过该 API Key 使用 E2B SDK。应用不需要阿里云 AK，也不需要配置 FCSandbox RAM 权限。

建议不同项目和环境使用不同 Team 与 API Key，不要让测试和生产应用共用一个 API Key。创建方法参见[创建 API Key](03.创建%20API%20Key.md)。

## 验证授权结果

完成配置后，分别验证允许和拒绝的操作：

| 身份 | 应允许 | 应拒绝 |
| --- | --- | --- |
| 平台管理员 | 管理账号下全部 Team 和资源 | 其他账号的资源 |
| 业务团队管理员 | 管理已授权资源组内的 Team 和资源 | 其他业务团队的资源组 |
| 项目开发人员 | 管理指定测试 Team | 其他项目及生产 Team |
| 生产运维人员 | 管理指定生产 Team | 测试 Team 和其他生产 Team |
| Volume 自动化程序 | 管理指定 Team 的 Volume | API Key、其他 Team 的 Volume 等非授权资源 |
| 业务应用 | 使用 API Key 创建和访问 Sandbox | 通过 OpenAPI 管理 Team、API Key 或 Volume |

## 常见误区

- **所有项目共用一个 Team**：项目成员难以隔离 API Key、Template、Sandbox 和 Volume。建议每个项目和环境使用独立 Team。
- **测试和生产共用一个资源组**：按资源组授权时，开发人员可能同时获得生产资源权限。建议测试和生产分别使用资源组。
- **使用 AdministratorAccess 简化授权**：该策略包含超出云沙箱范围的权限。只管理云沙箱时，应使用 `fcsandbox` 自定义策略。
- **混淆 RAM 权限和云沙箱 API Key**：RAM 权限用于控制台和 OpenAPI；API Key 用于 E2B SDK、CLI 和兼容 HTTP API。
- **只授权 Team 或只授权 Team 子资源**：`teams/<team-id>` 不包含 `teams/<team-id>/*`，管理整个 Team 时需要同时配置。
- **忽略列表权限范围**：列表接口可能使用集合 ARN。增加集合权限前，应确认用户是否可以看到该范围内的全部资源。

## 附录：Resource ARN 规则

### ARN 基本格式

```text
acs:fcsandbox:<region>:<account-id>:<resource-path>
```

| 占位符 | 说明 |
| --- | --- |
| `<region>` | 云沙箱资源所在地域，例如 `cn-beijing` |
| `<account-id>` | 资源所属阿里云账号 ID |
| `<team-id>` | Team ID |
| `<template-id>` | Template ID |
| `<volume-id>` | Volume ID |

### 常用匹配规则

| Resource 表达式 | 匹配范围 |
| --- | --- |
| `acs:fcsandbox:<region>:<account-id>:*` | 指定账号和地域下的全部云沙箱资源 |
| `acs:fcsandbox:*:<account-id>:*` | 指定账号在全部地域的云沙箱资源 |
| `acs:fcsandbox:<region>:<account-id>:teams/*` | 账号下的 Team，不包含 Team 子资源 |
| `acs:fcsandbox:<region>:<account-id>:teams/<team-id>` | 指定 Team，不包含其子资源 |
| `acs:fcsandbox:<region>:<account-id>:teams/<team-id>/*` | 指定 Team 的全部子资源，不包含 Team 本身 |
| `acs:fcsandbox:<region>:<account-id>:teams/*/templates/*` | 所有 Team 下的 Template，以及使用这些 Template ARN 鉴权的 Sandbox |
| `acs:fcsandbox:<region>:<account-id>:teams/<team-id>/templates/*` | 指定 Team 下的 Template，以及使用这些 Template ARN 鉴权的 Sandbox |
| `acs:fcsandbox:<region>:<account-id>:teams/<team-id>/templates/<template-id>` | 指定 Template，以及使用该 Template ARN 鉴权的 Sandbox |
| `acs:fcsandbox:<region>:<account-id>:teams/*/apikeys/*` | 所有 Team 下的 API Key |
| `acs:fcsandbox:<region>:<account-id>:teams/<team-id>/apikeys/*` | 指定 Team 下的 API Key |
| `acs:fcsandbox:<region>:<account-id>:teams/*/volumes/*` | 所有 Team 下的 Volume |
| `acs:fcsandbox:<region>:<account-id>:teams/<team-id>/volumes/*` | 指定 Team 下的全部 Volume |
| `acs:fcsandbox:<region>:<account-id>:teams/<team-id>/volumes/<volume-id>` | 指定 Volume |
| `acs:fcsandbox:<region>:<account-id>:teams/*/quotas/*` | 所有 Team 的配额 |
| `acs:fcsandbox:<region>:<account-id>:teams/<team-id>/quotas/*` | 指定 Team 的配额 |

Sandbox 没有独立的 Resource ARN。Sandbox 操作使用其所属 Template 的 ARN 鉴权。Resource 决定允许访问的 Template 和关联 Sandbox 范围，Action 决定允许执行 Template 或 Sandbox 的哪些操作。

API Key 和配额只支持 Team 粒度授权，不能分别限制到某一个 API Key 或某一条配额记录。列表接口根据请求范围可能使用账号级集合或 Team 级集合 ARN；仅具有 Team 级权限时，调用支持 Team ID 的列表接口需要显式传入 Team ID。
